Tahap 2: struktur (sitemap dan user flow)

Buka versi interaktif

Sitemap Kopi Kita memakai 4 tab navigasi bawah: Beranda, Menu, Pesanan, Akun. Masuk (OTP/passkey) baru diminta saat checkout pertama, sehingga orang bisa menjelajah menu tanpa akun.

User flow "pesan ulang sebelum berangkat" menggambar jalur utama dan cabang: belum masuk, stok habis, gagal bayar. Setiap kotak di flow adalah satu layar yang nanti kamu temukan di folder wireframe.

Poin penting

  • Sitemap = struktur; user flow = urutan langkah untuk satu tugas.
  • Gambar cabang error sejak awal, bukan setelah UI jadi.
  • Satu kotak flow = satu layar di tahap berikutnya.

Cek pemahaman

Kenapa cabang "gagal bayar" digambar di user flow?

Jawaban: Supaya layar dan pesan error dirancang sejak awal

State error adalah bagian dari desain, bukan tambahan.

Kerjakan latihannya di aplikasi

Sebelumnya: Tahap 1: riset (persona, empathy map, journey map)

Berikutnya: Tahap 3-5: lo-fi, mid-fi, hi-fi dan semua state
