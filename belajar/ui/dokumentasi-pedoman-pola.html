Dokumentasi pedoman pola

Buka versi interaktif

Komponen tanpa dokumentasi akan dipakai dengan cara yang berbeda-beda oleh setiap orang. Halaman dokumentasi yang baik berisi: deskripsi singkat, kapan dipakai dan kapan tidak, anatomi (bagian-bagian bernomor), varian dan state, contoh Do dan Don't, panduan konten (panjang label, gaya kalimat), aksesibilitas, dan kode.

Contoh Do dan Don't adalah bagian yang paling sering dibaca, karena langsung menunjukkan kesalahan umum. Taruh berdampingan: kiri hijau "Lakukan", kanan merah "Jangan", masing-masing dengan alasan satu kalimat.

Dokumentasi bisa dibuat di Figma (halaman khusus di library), Zeroheight, Supernova, atau Storybook untuk kode. Yang penting: satu tempat yang diketahui semua orang, dan diperbarui setiap kali komponen berubah, lengkap dengan changelog.

Halaman dokumentasi tombol di pratinjau baru punya contoh Do.

HTML
<section class="dok">
  <h2>Tombol primary</h2>
  <p>Untuk satu aksi utama di setiap layar.</p>
  <div class="contoh">
    <figure class="do"><div class="demo"><button class="p">Simpan</button><button class="s">Batal</button></div><figcaption><b>Lakukan:</b> satu primary, aksi lain secondary.</figcaption></figure>
  </div>
</section>
CSS
body { font-family: system-ui, sans-serif; margin: 0; padding: 16px; color: #1F2933; }
.contoh { display: grid; grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); gap: 16px; }
figure { margin: 0; border-radius: 12px; overflow: hidden; border-top: 4px solid; background: #F5F7FA; }
.do { border-color: #1E7B45; }
.dont { border-color: #B42318; }
.demo { padding: 24px; display: flex; gap: 8px; }
figcaption { padding: 12px 16px; font-size: 14px; background: #fff; }
.p, .s { font: inherit; padding: 8px 16px; border-radius: 8px; border: 1px solid #1D5FA8; }
.p { background: #1D5FA8; color: #fff; }
.s { background: #fff; color: #1D5FA8; }

Tantangan

  1. Tambahkan contoh <figure class="dont"> di dalam .contoh: dua tombol primary berdampingan, dengan keterangan "Jangan: dua primary di satu layar."

Soal latihan

  1. Tulis kerangka dokumentasi komponen Toast (notifikasi singkat).

    Petunjuk

    Deskripsi, kapan dipakai, anatomi, varian, Do/Don't, konten, aksesibilitas.

    Lihat jawaban
    CONTOH
    Toast
Deskripsi : pesan singkat tentang hasil aksi, hilang sendiri.
Kapan     : konfirmasi ringan (Tersimpan, Disalin).
Jangan    : untuk error penting atau yang butuh keputusan (pakai dialog/banner).
Anatomi   : 1 ikon, 2 pesan, 3 aksi opsional (Urungkan).
Varian    : neutral, success, error.
Do        : maksimal 1 baris, kata kerja lampau ("Kelas disimpan").
Don't     : dua toast bertumpuk.
Aksesibilitas: role="status", tampil minimal 4 detik, bisa ditutup.

Poin penting

  • Isi dokumentasi: kapan dipakai, anatomi, varian, Do/Don't, konten, aksesibilitas, kode.
  • Do dan Don't berdampingan dengan alasan.
  • Satu tempat, diperbarui bersama changelog.
