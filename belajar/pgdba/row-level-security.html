Row-Level Security

Buka versi interaktif

Row-Level Security (RLS) membatasi baris mana yang boleh dilihat atau diubah oleh setiap pengguna, langsung di database. Cocok untuk aplikasi multi-tenant: data toko A tidak boleh terlihat oleh toko B walaupun ada bug di query aplikasi.

Aktifkan dengan ALTER TABLE ... ENABLE ROW LEVEL SECURITY, lalu buat POLICY berisi kondisi USING (baris yang boleh dibaca) dan WITH CHECK (baris yang boleh ditulis). Supabase memakai RLS sebagai fondasi keamanannya.

Pemilik tabel dan superuser melewati RLS kecuali memakai FORCE ROW LEVEL SECURITY. Uji kebijakan dengan beberapa role sebelum rilis.

SQL
CREATE TABLE pesanan_toko (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  toko text NOT NULL,
  total numeric(12,2)
);
INSERT INTO pesanan_toko (toko, total) VALUES
  ('toko_a', 150000), ('toko_b', 90000), ('toko_a', 45000);

ALTER TABLE pesanan_toko ENABLE ROW LEVEL SECURITY;
CREATE POLICY milik_sendiri ON pesanan_toko
  USING (toko = current_setting('app.toko'));

GRANT SELECT ON pesanan_toko TO baca_saja;
SET ROLE dewi;
SET app.toko = 'toko_a';
SELECT * FROM pesanan_toko;
KELUARAN
 id |  toko  |   total
----+--------+-----------
  1 | toko_a | 150000.00
  3 | toko_a |  45000.00
(2 rows)

Poin penting

  • RLS = filter baris otomatis per pengguna.
  • USING untuk baca, WITH CHECK untuk tulis.
  • Pemilik tabel melewati RLS kecuali FORCE.
