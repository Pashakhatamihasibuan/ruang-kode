Replikasi dan high availability

Buka versi interaktif

Streaming replication mengirim WAL dari server primary ke satu atau lebih standby secara terus-menerus. Standby bisa melayani query baca (hot standby) dan siap dipromosikan jika primary mati. Mode asinkron cepat tetapi bisa kehilangan beberapa transaksi terakhir; mode sinkron menunggu standby mengonfirmasi.

Logical replication mereplikasi perubahan per tabel lewat publication dan subscription. Cocok untuk upgrade versi utama dengan downtime minimal atau mengirim sebagian tabel ke sistem lain.

High availability butuh otomatisasi failover: Patroni (dengan etcd atau Consul) adalah standar industri, sering dipadukan dengan HAProxy atau PgBouncer. Di Kubernetes, operator seperti CloudNativePG mengurus semuanya.

SQL
-- di primary: pantau standby
SELECT client_addr, state, sync_state,
       pg_wal_lsn_diff(pg_current_wal_lsn(), replay_lsn) AS tertinggal_byte
FROM pg_stat_replication;

-- logical replication satu tabel
CREATE PUBLICATION pub_produk FOR TABLE produk;
-- di server tujuan:
CREATE SUBSCRIPTION sub_produk
  CONNECTION 'host=db1 dbname=tokodb user=replikator'
  PUBLICATION pub_produk;
KELUARAN
 client_addr |   state   | sync_state | tertinggal_byte
-------------+-----------+------------+-----------------
 10.0.1.12   | streaming | async      |             328
 10.0.1.13   | streaming | async      |               0

CREATE PUBLICATION
CREATE SUBSCRIPTION

Poin penting

  • Streaming replication: WAL ke standby.
  • Logical replication: per tabel, lintas versi.
  • Patroni untuk failover otomatis.
