Tipe data dan constraint

Buka versi interaktif

Pilih tipe yang tepat: integer atau bigint untuk angka bulat, numeric(12,2) untuk uang (jangan float, karena tidak presisi), text untuk teks (sama cepatnya dengan varchar), timestamptz untuk waktu (selalu simpan zona waktu), boolean, uuid, jsonb, dan array seperti text[].

Constraint menjaga data tetap benar di level database: NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY (dengan ON DELETE CASCADE atau RESTRICT), CHECK (misalnya harga harus positif), dan EXCLUDE (misalnya jadwal ruangan tidak boleh tumpang tindih).

Aturan bisnis di aplikasi bisa dilewati oleh skrip atau integrasi lain; constraint di database tidak bisa. Itu sebabnya DBA menyukai constraint.

SQL
CREATE TABLE produk (
  id     bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nama   text NOT NULL,
  harga  numeric(12,2) NOT NULL CHECK (harga > 0),
  tag    text[] DEFAULT '{}'
);

CREATE TABLE pesanan (
  id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  produk_id  bigint NOT NULL REFERENCES produk(id) ON DELETE RESTRICT,
  jumlah     integer NOT NULL CHECK (jumlah BETWEEN 1 AND 100)
);

Soal latihan

  1. Tambahkan constraint agar email pelanggan wajib mengandung tanda @.

    Petunjuk

    ALTER TABLE ... ADD CONSTRAINT ... CHECK (email LIKE ...).

    Lihat jawaban
    SQL
    ALTER TABLE penjualan.pelanggan
  ADD CONSTRAINT email_valid CHECK (email LIKE '%@%');

Poin penting

  • Uang pakai numeric, waktu pakai timestamptz.
  • Constraint menjaga data di level paling bawah.
  • CHECK, FOREIGN KEY, UNIQUE, EXCLUDE.
