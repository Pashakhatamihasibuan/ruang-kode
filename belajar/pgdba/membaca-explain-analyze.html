Membaca EXPLAIN ANALYZE

Buka versi interaktif

Query planner memilih cara tercepat menjalankan query berdasarkan statistik tabel (diperbarui oleh ANALYZE). EXPLAIN menampilkan rencana perkiraan; EXPLAIN (ANALYZE, BUFFERS) benar-benar menjalankan query dan menampilkan waktu nyata serta jumlah halaman yang dibaca.

Baca dari bagian paling dalam (paling menjorok) ke atas. Perhatikan: Seq Scan pada tabel besar dengan filter yang selektif (tanda butuh indeks), selisih besar antara rows perkiraan dan actual rows (statistik usang), serta Sort Method: external merge Disk (work_mem kurang).

Jenis join: Nested Loop (bagus untuk sedikit baris), Hash Join (tabel sedang sampai besar, butuh memori), dan Merge Join (kedua sisi sudah terurut). Situs explain.dalibo.com membantu memvisualkan rencana yang panjang.

SQL
EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM pesanan WHERE pelanggan_id = 4821;
KELUARAN
 Seq Scan on pesanan  (cost=0.00..31872.80 rows=12 width=48) (actual time=0.042..187.531 rows=9 loops=1)
   Filter: (pelanggan_id = 4821)
   Rows Removed by Filter: 1203335
   Buffers: shared hit=1920 read=13952
 Planning Time: 0.118 ms
 Execution Time: 187.566 ms

Poin penting

  • Baca rencana dari dalam ke luar.
  • Seq Scan + banyak "Rows Removed by Filter" = kandidat indeks.
  • Perkiraan vs aktual jauh berbeda = jalankan ANALYZE.

Cek pemahaman

Rencana di atas membuang 1,2 juta baris untuk mendapat 9. Solusinya?

Jawaban: Indeks pada pelanggan_id

Filter sangat selektif.

Kerjakan latihannya di aplikasi

Sebelumnya: VACUUM, autovacuum, dan bloat

Berikutnya: Jenis indeks dan kapan memakainya
