PostgreSQL DBA · Modul 1 · Konsep & kode

Arsitektur proses dan penyimpanan

Buka versi interaktif

PostgreSQL memakai model satu proses per koneksi. Proses induk postmaster menerima koneksi lalu membuat proses backend untuk setiap klien. Karena itu ribuan koneksi langsung memboroskan memori; solusinya connection pooler seperti PgBouncer.

Proses latar belakang penting: checkpointer (menulis halaman kotor ke disk secara berkala), background writer, WAL writer, autovacuum launcher, dan walsender untuk replikasi. Memori bersama utama adalah shared_buffers, cache halaman data berukuran 8 kB.

Setiap perubahan ditulis dulu ke WAL (Write-Ahead Log) sebelum ke file data. Jika server mati mendadak, PostgreSQL memutar ulang WAL sejak checkpoint terakhir. WAL juga menjadi dasar replikasi dan point-in-time recovery. Data tersimpan di direktori PGDATA: base/ untuk tabel, pg_wal/ untuk WAL.

SQL
-- proses yang sedang berjalan
SELECT pid, backend_type, state
FROM pg_stat_activity
ORDER BY backend_type;

SHOW data_directory;
SHOW shared_buffers;

Poin penting

  • Satu proses backend per koneksi, pakai pooler untuk banyak koneksi.
  • WAL ditulis sebelum file data: kunci pemulihan dan replikasi.
  • shared_buffers adalah cache halaman data.
