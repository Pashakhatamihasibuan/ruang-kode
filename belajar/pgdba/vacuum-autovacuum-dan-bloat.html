VACUUM, autovacuum, dan bloat

Buka versi interaktif

Versi baris yang sudah mati (dead tuple) akibat MVCC tetap menempati ruang. VACUUM menandai ruang itu agar bisa dipakai ulang dan memperbarui visibility map. Jika tidak di-vacuum, tabel dan indeks membengkak (bloat) dan query melambat.

Autovacuum berjalan otomatis berdasarkan jumlah baris mati. Untuk tabel besar yang sering di-update, turunkan autovacuum_vacuum_scale_factor per tabel. VACUUM FULL mengembalikan ruang ke sistem operasi tetapi mengunci tabel sepenuhnya; di produksi pakai extension pg_repack.

VACUUM juga mencegah transaction ID wraparound: ID transaksi 32-bit akan berputar setelah sekitar 2 miliar transaksi. Pantau umur datfrozenxid; jika terlalu tua, PostgreSQL akan berhenti menerima tulisan demi keamanan data.

SQL
SELECT relname, n_live_tup, n_dead_tup,
       round(100.0 * n_dead_tup / nullif(n_live_tup + n_dead_tup, 0), 1) AS persen_mati,
       last_autovacuum
FROM pg_stat_user_tables
ORDER BY n_dead_tup DESC
LIMIT 3;

ALTER TABLE pesanan SET (autovacuum_vacuum_scale_factor = 0.02);
VACUUM (VERBOSE, ANALYZE) pesanan;

Soal latihan

  1. Tampilkan 5 tabel dengan dead tuple terbanyak beserta waktu autovacuum terakhir.

    Petunjuk

    View pg_stat_user_tables, urutkan n_dead_tup menurun.

    Lihat jawaban
    SQL
    SELECT relname, n_dead_tup, last_autovacuum
FROM pg_stat_user_tables
ORDER BY n_dead_tup DESC
LIMIT 5;

Poin penting

  • Dead tuple dibersihkan oleh VACUUM.
  • Setel autovacuum per tabel untuk tabel besar.
  • Pantau wraparound lewat umur datfrozenxid.

Cek pemahaman

Risiko VACUUM FULL di jam sibuk?

Jawaban: Tabel terkunci penuh selama proses

Gunakan pg_repack sebagai gantinya.

Kerjakan latihannya di aplikasi

Sebelumnya: MVCC, lock, dan deadlock
