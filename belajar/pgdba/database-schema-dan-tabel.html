Database, schema, dan tabel

Buka versi interaktif

Hierarki objek PostgreSQL: cluster (satu server) berisi beberapa database, setiap database berisi schema, dan schema berisi tabel, view, fungsi, dan sequence. Query tidak bisa langsung JOIN antar database, tetapi bisa antar schema.

Schema bawaan bernama public. Pakai schema untuk memisahkan domain (penjualan, gudang) atau penyewa (multi-tenant). search_path menentukan schema mana yang dicari jika nama tabel ditulis tanpa awalan.

Untuk kunci utama, gunakan GENERATED ALWAYS AS IDENTITY (standar SQL) daripada SERIAL lama.

SQL
CREATE SCHEMA penjualan;

CREATE TABLE penjualan.pelanggan (
  id        bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nama      text NOT NULL,
  email     text UNIQUE,
  kota      text DEFAULT 'Medan',
  dibuat    timestamptz NOT NULL DEFAULT now()
);

INSERT INTO penjualan.pelanggan (nama, email)
VALUES ('Rina', 'rina@contoh.id'), ('Budi', 'budi@contoh.id')
RETURNING id, nama, kota;

Soal latihan

  1. Buat schema gudang dan tabel gudang.stok dengan kolom id (identity), produk (teks wajib), jumlah (bilangan bulat default 0).

    Petunjuk

    CREATE SCHEMA lalu CREATE TABLE dengan awalan schema.

    Lihat jawaban
    SQL
    CREATE SCHEMA gudang;
CREATE TABLE gudang.stok (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  produk text NOT NULL,
  jumlah integer NOT NULL DEFAULT 0
);

Poin penting

  • Cluster → database → schema → tabel.
  • Schema memisahkan domain atau penyewa.
  • IDENTITY lebih disarankan daripada SERIAL.
