Jenis indeks dan kapan memakainya

Buka versi interaktif

B-tree (bawaan) untuk =, <, >, BETWEEN, ORDER BY, dan LIKE dengan awalan tetap. GIN untuk JSONB, array, dan pencarian teks penuh. GiST untuk data geometri dan rentang. BRIN sangat kecil, untuk tabel raksasa yang datanya berurutan secara alami (log berdasarkan waktu). Hash hanya untuk =.

Indeks khusus: komposit (urutan kolom penting: kolom kesetaraan di depan), partial (WHERE status = 'aktif'), expression (lower(email)), dan covering (INCLUDE) agar terjadi Index Only Scan.

Indeks tidak gratis: memperlambat INSERT dan UPDATE serta memakan disk. Di produksi, buat dengan CREATE INDEX CONCURRENTLY agar tabel tidak terkunci, dan hapus indeks yang tidak pernah dipakai (lihat pg_stat_user_indexes.idx_scan = 0).

SQL
CREATE INDEX CONCURRENTLY pesanan_pelanggan_idx
  ON pesanan (pelanggan_id, dibuat DESC);

EXPLAIN (ANALYZE)
SELECT * FROM pesanan WHERE pelanggan_id = 4821
ORDER BY dibuat DESC LIMIT 5;

Soal latihan

  1. Buat partial index untuk pesanan berstatus menunggu berdasarkan kolom dibuat.

    Petunjuk

    CREATE INDEX ... WHERE status = ...

    Lihat jawaban
    SQL
    CREATE INDEX CONCURRENTLY pesanan_menunggu_idx
  ON pesanan (dibuat)
  WHERE status = 'menunggu';

Poin penting

  • B-tree untuk sebagian besar kasus.
  • Urutan kolom indeks komposit penting.
  • CREATE INDEX CONCURRENTLY di produksi.
