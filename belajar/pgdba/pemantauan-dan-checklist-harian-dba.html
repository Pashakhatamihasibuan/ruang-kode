Pemantauan dan checklist harian DBA

Buka versi interaktif

Pantau metrik ini: jumlah koneksi dibanding max_connections, cache hit ratio (idealnya di atas 99% untuk OLTP), query lambat, transaksi yang idle in transaction terlalu lama (menahan VACUUM), lag replikasi, ukuran database, dan umur wraparound.

Aktifkan log_min_duration_statement (misalnya 500 ms) untuk mencatat query lambat dan analisis dengan pgBadger. Untuk dasbor, pakai postgres_exporter + Prometheus + Grafana, atau layanan seperti pganalyze.

Atur peringatan sebelum masalah terjadi: disk di atas 80%, lag replikasi di atas 1 menit, koneksi di atas 80% batas, dan backup terakhir lebih dari 24 jam.

SQL
SELECT round(100.0 * sum(blks_hit) / nullif(sum(blks_hit + blks_read), 0), 2) AS cache_hit_persen
FROM pg_stat_database;

SELECT pid, now() - xact_start AS lama, state
FROM pg_stat_activity
WHERE state = 'idle in transaction'
  AND now() - xact_start > interval '5 minutes';

SELECT pg_size_pretty(pg_database_size('tokodb')) AS ukuran;

Soal latihan

  1. Tampilkan 5 tabel terbesar beserta ukurannya (termasuk indeks) dalam format mudah dibaca.

    Petunjuk

    pg_total_relation_size dan pg_size_pretty dari pg_stat_user_tables.

    Lihat jawaban
    SQL
    SELECT relname, pg_size_pretty(pg_total_relation_size(relid)) AS ukuran
FROM pg_stat_user_tables
ORDER BY pg_total_relation_size(relid) DESC
LIMIT 5;

Poin penting

  • Cache hit ratio di atas 99% untuk OLTP.
  • Idle in transaction menahan VACUUM.
  • Prometheus + Grafana atau pgBadger.
