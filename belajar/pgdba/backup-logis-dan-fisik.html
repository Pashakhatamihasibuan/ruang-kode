Backup logis dan fisik

Buka versi interaktif

Backup logis dengan pg_dump menghasilkan perintah SQL atau format arsip untuk satu database. Fleksibel (bisa memulihkan satu tabel, pindah versi PostgreSQL), tetapi lambat untuk database ratusan GB. pg_dumpall menyertakan role dan tablespace.

Backup fisik dengan pg_basebackup menyalin seluruh direktori data. Cepat dipulihkan dan, jika digabung dengan arsip WAL, memungkinkan Point-in-Time Recovery (PITR): memulihkan ke detik tertentu, misalnya tepat sebelum seseorang tidak sengaja menjalankan DELETE tanpa WHERE.

Di produksi, pakai alat seperti pgBackRest atau Barman untuk backup terjadwal, kompresi, enkripsi, dan penyimpanan di object storage. Ingat aturan 3-2-1 dan yang paling penting: uji restore secara rutin.

TERMINAL
# backup logis format custom (terkompresi, bisa restore sebagian)
pg_dump -h localhost -U postgres -Fc -f tokodb_2026-11-05.dump tokodb

# restore hanya tabel produk ke database uji
pg_restore -U postgres -d tokodb_uji -t produk tokodb_2026-11-05.dump

# backup fisik + WAL untuk PITR
pg_basebackup -h db1 -U replikator -D /backup/base -Ft -z -X stream -P

Soal latihan

  1. Tulis perintah pg_dump yang hanya mencadangkan schema penjualan dari database tokodb dalam format custom.

    Petunjuk

    Opsi -n untuk schema, -Fc untuk format custom.

    Lihat jawaban
    SQL
    pg_dump -U postgres -Fc -n penjualan -f penjualan.dump tokodb

Poin penting

  • pg_dump untuk fleksibilitas, pg_basebackup untuk kecepatan dan PITR.
  • pgBackRest atau Barman untuk produksi.
  • Backup yang tidak pernah diuji restore belum terbukti.
