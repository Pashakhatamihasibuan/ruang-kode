Transaksi dan tingkat isolasi

Buka versi interaktif

Transaksi mengelompokkan beberapa perintah menjadi satu kesatuan: semua berhasil (COMMIT) atau semua dibatalkan (ROLLBACK). Contoh klasik: transfer saldo harus mengurangi rekening A dan menambah rekening B.

ACID: Atomicity (semua atau tidak sama sekali), Consistency (constraint tetap terpenuhi), Isolation (transaksi bersamaan tidak saling mengacaukan), Durability (yang sudah COMMIT tidak hilang walau server mati).

Tingkat isolasi PostgreSQL: Read Committed (bawaan, setiap perintah melihat data yang sudah di-commit saat itu), Repeatable Read (melihat snapshot yang sama sepanjang transaksi), dan Serializable (seolah transaksi berjalan bergantian; aplikasi harus siap mengulang jika muncul error serialisasi).

CREATE TABLE rekening (no text PRIMARY KEY, saldo numeric(14,2) CHECK (saldo >= 0));
INSERT INTO rekening VALUES ('A', 500000), ('B', 100000);

BEGIN;
UPDATE rekening SET saldo = saldo - 700000 WHERE no = 'A';
-- gagal: saldo menjadi negatif
ROLLBACK;

BEGIN;
UPDATE rekening SET saldo = saldo - 200000 WHERE no = 'A';
UPDATE rekening SET saldo = saldo + 200000 WHERE no = 'B';
COMMIT;
SELECT * FROM rekening;

Soal latihan

  1. Tulis transaksi yang memindahkan stok 5 unit dari gudang Medan ke gudang Binjai di tabel stok(gudang, jumlah).

    Petunjuk

    Dua UPDATE di dalam BEGIN ... COMMIT.

    Lihat jawaban
    SQL
    BEGIN;
UPDATE stok SET jumlah = jumlah - 5 WHERE gudang = 'Medan';
UPDATE stok SET jumlah = jumlah + 5 WHERE gudang = 'Binjai';
COMMIT;

Poin penting

  • BEGIN, COMMIT, ROLLBACK.
  • ACID menjamin data tetap benar.
  • Read Committed bawaan; Serializable paling ketat.
