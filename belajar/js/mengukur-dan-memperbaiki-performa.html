Mengukur dan memperbaiki performa

Buka versi interaktif

Panel Performance merekam apa yang dilakukan browser: klik Record, lakukan aksi yang lambat, lalu Stop. Perhatikan Main thread dalam bentuk flame chart: blok lebar adalah fungsi yang lama. Long task (lebih dari 50 ms, ditandai segitiga merah) membuat halaman terasa macet dan memperburuk metrik INP (Interaction to Next Paint). Ungu = layout/recalculate style, hijau = paint.

Masalah performa JS yang sering ditemukan: perulangan berat di main thread, layout thrashing (membaca ukuran elemen lalu menulis style bergantian di dalam loop sehingga memaksa layout berulang), render ulang berlebihan, dan bundle JS terlalu besar. Perbaikannya: pecah pekerjaan (scheduler.yield() atau setTimeout), pindahkan ke Web Worker, kelompokkan baca lalu tulis DOM, debounce event, memoization, dan code splitting.

Untuk mengukur di kode, gunakan performance.now() (resolusi tinggi), performance.mark/measure (tampil di panel Performance), dan Lighthouse untuk audit menyeluruh. Prinsipnya: ukur dulu, optimasi bagian yang terbukti lambat, lalu ukur lagi. Contoh di bawah membandingkan pencarian di array dan Set; angka pasti berbeda di setiap komputer, jadi yang dicetak hanya kesimpulannya.

JAVASCRIPT
const N = 200_000;
const idArr = Array.from({ length: N }, (_, i) => `user-${i}`);
const idSet = new Set(idArr);
const dicari = Array.from({ length: 2000 }, (_, i) => `user-${N - 1 - i * 7}`);

function ukur(label, fn) {
  performance.mark(`${label}-mulai`);
  const t0 = performance.now();
  const hasil = fn();
  const ms = performance.now() - t0;
  performance.measure(label, `${label}-mulai`);   // muncul di panel Performance (browser)
  return { label, hasil, ms };
}
const a = ukur('array.includes', () => dicari.filter(id => idArr.includes(id)).length);
const s = ukur('set.has', () => dicari.filter(id => idSet.has(id)).length);
console.log(a.label, 'menemukan', a.hasil, '|', s.label, 'menemukan', s.hasil);
console.log('Set lebih cepat minimal 10x:', a.ms / s.ms > 10);

// memoization untuk fungsi murni yang mahal
function memo(fn) {
  const cache = new Map();
  return n => (cache.has(n) ? cache.get(n) : (cache.set(n, fn(n)), cache.get(n)));
}
let dihitung = 0;
const ongkirMahal = memo(kota => { dihitung++; return kota.length * 1000; });
['Bandung', 'Medan', 'Bandung', 'Bandung'].forEach(ongkirMahal);
console.log('fungsi mahal dihitung', dihitung, 'kali untuk 4 panggilan');
console.log(performance.getEntriesByType('measure').map(m => m.name));

Poin penting

  • Panel Performance: cari long task dan blok lebar di flame chart.
  • Long task > 50 ms memperburuk INP.
  • Hindari layout thrashing; pakai Worker untuk komputasi berat.
  • performance.now, mark, measure, dan Lighthouse.
  • Ukur dulu, optimasi, ukur lagi.
