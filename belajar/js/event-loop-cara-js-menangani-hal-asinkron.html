Event loop: cara JS menangani hal asinkron

Buka versi interaktif

JS menjalankan kode di satu thread dengan satu call stack. Pekerjaan yang lama (timer, jaringan, membaca file) diserahkan ke lingkungan (Web API di browser, libuv di Node). Saat selesai, callback-nya dimasukkan ke antrean dan dijalankan oleh event loop ketika call stack kosong. Karena itu JS bisa non-blocking walau single-threaded.

Ada dua antrean utama: microtask queue (callback Promise then/catch/finally, await, queueMicrotask, MutationObserver) dan macrotask/task queue (setTimeout, setInterval, event I/O, event klik). Aturannya: jalankan kode sinkron sampai habis, lalu kosongkan semua microtask, lalu ambil satu macrotask, kosongkan microtask lagi, (browser bisa render), dan ulangi.

Konsekuensi praktis: setTimeout(fn, 0) tidak langsung jalan, melainkan setelah kode sinkron dan semua microtask. Kode sinkron yang berat (loop jutaan iterasi) memblokir event loop sehingga halaman macet dan tidak bisa diklik; pecah pekerjaannya atau pindahkan ke Web Worker. Di Node, process.nextTick berjalan bahkan sebelum microtask Promise (contoh ini dijalankan sebagai skrip CommonJS; di modul ES urutan nextTick bisa berbeda karena modul dievaluasi secara asinkron).

Poin penting

  • Single-threaded + event loop = non-blocking.
  • Urutan: sinkron, semua microtask, satu macrotask, ulangi.
  • Promise (microtask) mendahului setTimeout 0 (macrotask).
  • Kode sinkron berat memblokir UI.
