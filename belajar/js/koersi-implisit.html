Koersi implisit

Buka versi interaktif

Koersi terjadi saat operator menerima tipe yang tidak sesuai. Aturan intinya: operator + dengan salah satu operand string melakukan penggabungan string; operator aritmetika lain (- * / %) mengubah operand menjadi number; konteks kondisi (if, &&, ||, !) mengubah ke boolean; == melakukan koersi sebelum membandingkan.

Object dikonversi ke primitif lewat ToPrimitive: memanggil [Symbol.toPrimitive] jika ada, lalu valueOf() atau toString() tergantung hint. Itu sebabnya [] + {} menghasilkan "[object Object]" dan [1,2] + [3] menghasilkan "1,23".

Bug koersi yang sering terjadi di produksi: menjumlahkan nilai input form ("10" + 5 = "105"), membandingkan string angka ("10" < "9" bernilai true karena dibandingkan per karakter), dan memakai || untuk default padahal 0 adalah nilai sah. TypeScript dan ESLint (eqeqeq) membantu mencegahnya.

Soal latihan

  1. Urutkan ["100", "25", "3"] secara numerik. Tunjukkan dulu hasil sort() tanpa pembanding, lalu hasil yang benar.

    Petunjuk

    sort() bawaan membandingkan sebagai string; pakai (a, b) => a - b.

    Lihat jawaban
    JAVASCRIPT
    const data = ['100', '25', '3'];
console.log([...data].sort());
console.log([...data].sort((a, b) => a - b));
console.log(data.map(Number).sort((a, b) => a - b));
    KELUARAN
    [ '100', '25', '3' ]
[ '3', '25', '100' ]
[ 3, 25, 100 ]

Poin penting

  • + dengan string = gabung; operator lain = number.
  • Object diubah ke primitif lewat Symbol.toPrimitive/valueOf/toString.
  • Bandingkan string angka setelah dikonversi ke number.
  • Pakai ?? untuk default jika 0 atau "" valid.

Cek pemahaman

Hasil '5' + 5 + 5?

Jawaban: '555'

Dari kiri: "5"+5 = "55", lalu "55"+5.

Hasil '10' &lt; '9'?

Jawaban: true

Dua string dibandingkan per karakter: "1" &lt; "9".
