Siklus hidup memori dan garbage collection

Buka versi interaktif

Setiap nilai melewati siklus hidup memori: alokasi (saat membuat variabel, object, array, fungsi), pemakaian (membaca dan menulis), dan pelepasan saat tidak dibutuhkan. Di JS, alokasi dan pelepasan otomatis; pelepasan dilakukan oleh garbage collector (GC).

Secara konsep, nilai primitif kecil dan frame fungsi berada di stack, sedangkan object, array, dan closure berada di heap. GC modern memakai algoritma mark-and-sweep: mulai dari roots (variabel global, call stack aktif), tandai semua yang bisa dijangkau lewat referensi, lalu bersihkan sisanya. Karena itu object yang saling merujuk (siklus) tetap dibersihkan jika tidak terjangkau dari root, masalah yang dulu ada pada algoritma reference counting.

V8 memakai generational GC: object baru ditaruh di young generation yang sering dibersihkan cepat (minor GC/scavenge), sedangkan yang bertahan dipindah ke old generation yang dibersihkan lebih jarang (major GC). Kita tidak bisa memaksa GC di kode biasa; tugas kita adalah tidak menyimpan referensi yang tidak perlu. Contoh di bawah memakai FinalizationRegistry untuk mengamati kapan object dibersihkan (Node dijalankan dengan izin memicu GC hanya untuk demonstrasi).

JAVASCRIPT
import v8 from 'node:v8';
import vm from 'node:vm';
v8.setFlagsFromString('--expose-gc');
const gc = vm.runInNewContext('gc');           // hanya untuk demo; jangan di produksi

const registry = new FinalizationRegistry(label => console.log(`GC membersihkan: ${label}`));
const tunggu = () => new Promise(r => setTimeout(r, 20));

let laporan = { data: new Array(100_000).fill('x') };
registry.register(laporan, 'laporan besar');
const cadangan = laporan;                      // referensi kedua
laporan = null;
gc(); await tunggu();
console.log('masih ada referensi lain -> belum dibersihkan');

let a = { nama: 'A' }, b = { nama: 'B' };
a.teman = b; b.teman = a;                      // referensi melingkar
registry.register(a, 'siklus A-B');
a = b = null;
gc(); await tunggu();

const ref = new WeakRef(cadangan);
console.log('WeakRef masih hidup:', ref.deref() !== undefined);
console.log('heap terpakai (MB) kira-kira:', Math.round(process.memoryUsage().heapUsed / 1e6) > 0);
KELUARAN
masih ada referensi lain -> belum dibersihkan
GC membersihkan: siklus A-B
WeakRef masih hidup: true
heap terpakai (MB) kira-kira: true

Poin penting

  • Siklus: alokasi, pakai, lepas.
  • GC mark-and-sweep: yang tidak terjangkau dari root dibersihkan.
  • Referensi melingkar tetap bisa dibersihkan.
  • Generational GC: young dan old generation.
  • Tugas kita: jangan menahan referensi yang tidak perlu.

Cek pemahaman

Mark-and-sweep berbasis keterjangkauan.

Apakah dua object yang saling merujuk tetapi tidak terjangkau akan dibersihkan?
