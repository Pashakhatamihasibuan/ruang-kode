WeakMap dan WeakSet

Buka versi interaktif

WeakMap dan WeakSet hanya menerima object (atau symbol non-registered) sebagai key/nilai dan memegangnya secara lemah (weak reference): jika tidak ada referensi lain ke object itu, garbage collector boleh menghapusnya, dan entri di WeakMap ikut hilang. Ini mencegah memory leak.

Konsekuensinya, WeakMap/WeakSet tidak bisa diiterasi dan tidak punya size; isinya bergantung pada kapan GC berjalan. Metode yang tersedia hanya get/set/has/delete (WeakMap) dan add/has/delete (WeakSet).

Pemakaian nyata: menyimpan data privat atau metadata untuk object milik pihak lain (misalnya elemen DOM) tanpa memodifikasinya, cache/memoization per object yang otomatis bersih, dan menandai object yang sudah diproses (WeakSet) agar tidak diproses dua kali.

JAVASCRIPT
const cache = new WeakMap();
function hitungBerat(obj) {
  if (cache.has(obj)) return cache.get(obj) + ' (dari cache)';
  const hasil = obj.items.reduce((a, b) => a + b, 0);
  cache.set(obj, hasil);
  return hasil;
}
let laporan = { items: [3, 4, 5] };
console.log(hitungBerat(laporan));
console.log(hitungBerat(laporan));
laporan = null;   // tidak ada referensi lagi: entri boleh dibersihkan GC

const sudahDikirim = new WeakSet();
function kirimEmail(user) {
  if (sudahDikirim.has(user)) return `lewati ${user.email}`;
  sudahDikirim.add(user);
  return `kirim ke ${user.email}`;
}
const u = { email: 'rina@contoh.id' };
console.log(kirimEmail(u), '|', kirimEmail(u));

try { new WeakMap().set('teks', 1); } catch (e) { console.log(e.name + ':', e.message); }

Poin penting

  • Weak = tidak menghalangi garbage collection.
  • Key/nilai harus object.
  • Tidak bisa diiterasi, tidak ada size.
  • Cocok untuk cache per object dan metadata DOM.
