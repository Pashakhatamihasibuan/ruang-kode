TypeScript · Modul 5 · Konsep & kode

Validasi data dari API dengan type predicate

Buka versi interaktif

Data dari fetch atau JSON.parse tidak punya jaminan bentuk. Menulis as Produk hanya menenangkan compiler, bukan memeriksa data. Kalau server mengirim bentuk lain, error baru muncul jauh di bagian lain program.

Type predicate adalah fungsi yang mengembalikan x is Produk. Di dalamnya kamu memeriksa data sungguhan; di luar, TypeScript memakai hasilnya untuk mempersempit tipe. Gabungkan dengan filter untuk menyaring data yang valid saja.

Untuk skema besar, pustaka seperti Zod atau Valibot menulis pemeriksaan sekaligus tipe dari satu definisi.

TYPESCRIPT
type Produk = { nama: string; harga: number };

function isProduk(x: unknown): x is Produk {
  return typeof x === "object" && x !== null
    && typeof (x as Produk).nama === "string"
    && typeof (x as Produk).harga === "number";
}

const dariServer: unknown = JSON.parse(
  '[{"nama":"Kopi","harga":85000},{"nama":"Teh","harga":"25rb"},null]'
);
const daftar = Array.isArray(dariServer) ? dariServer.filter(isProduk) : [];
console.log(daftar.length, "produk valid");
for (const p of daftar) console.log(p.nama, p.harga * 2);
KELUARAN
1 produk valid
Kopi 170000

Poin penting

  • as Tipe tidak memeriksa data.
  • Type predicate: fungsi yang mengembalikan x is Tipe.
  • filter(isTipe) menyaring dan mempersempit tipe.
  • Skema besar: Zod atau Valibot.

Cek pemahaman

Apa beda as Produk dan type predicate isProduk?

Jawaban: as tidak memeriksa apa pun; isProduk memeriksa data saat program berjalan

Assertion hanya berlaku saat kompilasi.

Kenapa {"nama":"Teh","harga":"25rb"} tidak lolos?

Jawaban: harga bertipe string, bukan number

Pemeriksaan typeof harga === number gagal.

Kerjakan latihannya di aplikasi

Sebelumnya: as, as const, ! & satisfies

Berikutnya: Kelas & modifier akses
