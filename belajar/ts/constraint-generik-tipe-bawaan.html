Constraint generik & tipe bawaan

Buka versi interaktif

Generik tanpa batasan menerima tipe apa saja, sehingga TypeScript tidak tahu properti apa yang tersedia. Constraint dengan extends membatasinya: <T extends { harga: number }> berarti T boleh tipe apa pun asal punya properti harga.

keyof bisa dipakai sebagai constraint juga. <T, K extends keyof T> memastikan nama properti yang dikirim benar-benar ada pada objek, dan tipe hasilnya T[K] ikut tepat.

Parameter generik juga boleh punya tipe bawaan seperti <T = string>, dipakai saat pemanggil tidak menyebut tipenya dan TypeScript tidak bisa menebaknya.

TYPESCRIPT
function termahal<T extends { harga: number }>(daftar: T[]): T {
  return daftar.reduce((a, b) => (b.harga > a.harga ? b : a));
}

function ambil<T, K extends keyof T>(obj: T, kunci: K): T[K] {
  return obj[kunci];
}

type Respons<T = string> = { ok: boolean; data: T };

const produk = [
  { nama: "Kopi Gayo", harga: 85_000, stok: 40 },
  { nama: "Madu Hutan", harga: 120_000, stok: 15 },
];
const teratas = termahal(produk);
console.log(teratas.nama);          // tipe teratas: { nama, harga, stok }
console.log(ambil(teratas, "stok")); // ambil(teratas, "warna") ditolak compiler
const r: Respons = { ok: true, data: "tersimpan" };
console.log(r.data.toUpperCase());
KELUARAN

TERSIMPAN

Poin penting

  • T extends {...} membatasi tipe yang diterima.
  • K extends keyof T menjamin nama properti valid.
  • T[K] memberi tipe hasil yang tepat.
  • Tipe bawaan: <T = string>.

Cek pemahaman

Apa arti <code>&lt;T extends { harga: number }&gt;</code>?

Jawaban: T boleh tipe apa saja yang punya properti harga bertipe number

extends di generik berarti batasan.

Kenapa ambil(teratas, "warna") ditolak?

Jawaban: "warna" bukan keyof tipe teratas

K dibatasi pada nama properti yang ada.
