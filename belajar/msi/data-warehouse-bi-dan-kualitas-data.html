Data warehouse, BI, dan kualitas data

Buka versi interaktif

Database transaksi dirancang untuk mencatat dengan cepat, bukan untuk analisis berat. Data warehouse mengumpulkan data dari banyak sistem (kasir, ERP, CRM, iklan) ke satu tempat yang dirancang untuk analisis, biasanya lewat proses ETL (extract, transform, load).

Business Intelligence (BI) adalah alat dan proses untuk mengubah data itu menjadi laporan dan dashboard: Power BI, Tableau, Looker Studio, atau Metabase. Dashboard yang baik dimulai dari pertanyaan bisnis dan KPI, bukan dari grafik yang terlihat keren.

Semua itu sia-sia bila datanya buruk: garbage in, garbage out. Dimensi kualitas data: akurat, lengkap, konsisten, tepat waktu, dan unik (tidak ganda). Tetapkan pemilik data (data owner) untuk setiap tabel penting agar jelas siapa yang bertanggung jawab memperbaikinya.

Soal latihan

  1. Sebutkan enam dimensi kualitas data dengan contoh masalahnya.

    Petunjuk

    Akurasi, kelengkapan, konsistensi, ketepatan waktu, validitas, keunikan.

    Lihat jawaban
    CONTOH
    Akurasi      : harga tercatat 1.800 padahal 18.000
Kelengkapan  : 20% pelanggan tanpa kota
Konsistensi  : "Jkt", "Jakarta", "DKI" untuk kota yang sama
Tepat waktu  : data penjualan baru masuk 3 hari kemudian
Validitas    : tanggal lahir 31/02/2001
Keunikan     : satu transaksi tercatat dua kali

  2. Kenapa laporan BI tidak diambil langsung dari database transaksi (OLTP)?

    Petunjuk

    Beban dan struktur data.

    Lihat jawaban
    CONTOH
    Query analitik berat memperlambat transaksi pelanggan, data OLTP tersebar di
banyak tabel dan sistem, dan riwayat tidak disimpan. Warehouse menyatukan,
membersihkan, dan menyimpan riwayat khusus untuk analisis.

Poin penting

  • Data warehouse: menyatukan data dari banyak sistem untuk analisis (via ETL).
  • BI mengubah data menjadi dashboard berbasis KPI.
  • Kualitas data: akurat, lengkap, konsisten, tepat waktu, unik.
  • Setiap data penting butuh pemilik yang bertanggung jawab.
