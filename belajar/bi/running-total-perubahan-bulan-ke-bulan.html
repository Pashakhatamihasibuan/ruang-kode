Running total & perubahan bulan ke bulan

Buka versi interaktif

Dua pertanyaan yang hampir selalu muncul di laporan: "berapa omzet kumulatif sampai bulan ini?" dan "naik atau turun berapa persen dibanding bulan lalu?". Keduanya dijawab dengan window function tanpa subquery.

SUM(...) OVER (ORDER BY bulan) menjumlahkan dari baris pertama sampai baris saat ini, sehingga menghasilkan running total. LAG(...) OVER (ORDER BY bulan) mengambil nilai baris sebelumnya, lalu persentase perubahan dihitung dari keduanya.

Bungkus pembaginya dengan NULLIF agar bulan pertama atau bulan dengan omzet 0 tidak memicu pembagian dengan nol. Query di bawah dijalankan pada database skema bintang yang sama dengan pelajaran BI lainnya.

SQL
WITH bulanan AS (
  SELECT t.bulan, SUM(f.jumlah * f.harga) AS omzet
  FROM fakta_penjualan f
  JOIN dim_tanggal t ON t.tanggal_id = f.tanggal_id
  GROUP BY t.bulan
)
SELECT bulan, omzet,
       SUM(omzet) OVER (ORDER BY bulan) AS kumulatif,
       ROUND(100.0 * (omzet - LAG(omzet) OVER (ORDER BY bulan))
             / NULLIF(LAG(omzet) OVER (ORDER BY bulan), 0), 1) AS ubah_persen
FROM bulanan
ORDER BY bulan;

Poin penting

  • SUM() OVER (ORDER BY ...) menghasilkan running total.
  • LAG() mengambil nilai periode sebelumnya.
  • NULLIF mencegah pembagian dengan nol.
  • CTE memisahkan agregasi dan perhitungan window.

Cek pemahaman

Fungsi untuk mengambil omzet bulan sebelumnya?

Jawaban: LAG(omzet) OVER (ORDER BY bulan)

LAG melihat ke baris sebelumnya, LEAD ke baris berikutnya.

Kenapa ubah_persen bulan pertama bernilai NULL?

Jawaban: Tidak ada bulan sebelumnya, jadi LAG menghasilkan NULL
