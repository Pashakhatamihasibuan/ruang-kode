Guard clause untuk menangani kesalahan

Buka versi interaktif

Guard clause (klausa penjaga) adalah pemeriksaan di awal algoritma yang langsung menolak data yang tidak sah, sebelum logika utama dijalankan. Daripada membungkus seluruh logika di dalam IF yang dalam, kita tangani kasus buruk dulu, lalu keluar.

Contoh: nilai ujian harus 0 sampai 100. Tanpa penjaga, input 120 akan dianggap "Lulus", padahal datanya salah. Dengan penjaga, input di luar rentang langsung dijawab dengan pesan error yang jelas.

Di dalam fungsi, guard clause biasanya memakai RETURN lebih awal, sehingga logika utama tidak perlu menjorok ke dalam. Lihat pseudocode di bagian contoh: setiap penjaga berdiri sendiri, dan logika utama tetap rata kiri.

Kasus yang perlu dijaga: angka di luar rentang, teks kosong, pembagian dengan nol, stok tidak cukup, dan data yang belum diisi. Jalankan visual dengan 120, -5, 80, dan 60.

CONTOH
FUNCTION StatusNilai(nilai : INTEGER) RETURNS STRING
    // penjaga: tolak data tidak sah lebih dulu
    IF nilai < 0 OR nilai > 100 THEN
        RETURN "Error: nilai harus 0 sampai 100"
    ENDIF
    // logika utama
    IF nilai >= 75 THEN
        RETURN "Lulus"
    ENDIF
    RETURN "Remedial"
ENDFUNCTION

FUNCTION BagiAman(a : REAL, b : REAL) RETURNS REAL
    IF b = 0 THEN
        OUTPUT "Tidak bisa membagi dengan nol"
        RETURN 0
    ENDIF
    RETURN a / b
ENDFUNCTION
KELUARAN
StatusNilai(120) → Error: nilai harus 0 sampai 100
StatusNilai(80)  → Lulus
BagiAman(10, 0)  → Tidak bisa membagi dengan nol
PSEUDOCODE
START
    DECLARE nilai : INTEGER
    INPUT nilai
    IF nilai < 0 or nilai > 100 THEN
        OUTPUT "Error: nilai harus 0 sampai 100"
    ELSE
        IF nilai >= 75 THEN
            OUTPUT "Lulus"
        ELSE
            OUTPUT "Remedial"
        ENDIF
    ENDIF
END

Soal latihan

  1. Tulis fungsi HitungBMI(berat, tinggi) dengan guard clause: berat dan tinggi harus lebih dari 0.

    Petunjuk

    Periksa data tidak sah di awal dan RETURN lebih awal. BMI = berat / (tinggi × tinggi).

    Lihat jawaban
    CONTOH
    FUNCTION HitungBMI(berat : REAL, tinggi : REAL) RETURNS REAL
    IF berat <= 0 OR tinggi <= 0 THEN
        OUTPUT "Berat dan tinggi harus lebih dari 0"
        RETURN 0
    ENDIF
    RETURN berat / (tinggi * tinggi)
ENDFUNCTION
    KELUARAN
    HitungBMI(60, 1.6) → 23.44

  2. Ubah IF bersarang berikut menjadi guard clause:
    IF stok > 0 THEN IF saldo >= harga THEN proses beli ELSE "saldo kurang" ENDIF ELSE "stok habis" ENDIF

    Petunjuk

    Tangani setiap kasus gagal di awal, logika utama paling bawah tanpa sarang.

    Lihat jawaban
    CONTOH
    PROCEDURE Beli(stok, saldo, harga : INTEGER)
    IF stok <= 0 THEN
        OUTPUT "Stok habis"
        RETURN
    ENDIF
    IF saldo < harga THEN
        OUTPUT "Saldo kurang"
        RETURN
    ENDIF
    OUTPUT "Pembelian berhasil"
ENDPROCEDURE

Poin penting

  • Tolak data tidak sah di awal.
  • Pesan error harus jelas: apa yang salah dan apa yang benar.
  • Guard clause membuat logika utama tidak menjorok terlalu dalam.

Cek pemahaman

Tanpa penjaga, nilai 150 pada contoh menghasilkan?

Jawaban: Lulus

150 >= 75 benar, padahal datanya tidak sah.

Di mana guard clause diletakkan?

Jawaban: Di awal, sebelum logika utama

Tangani kasus buruk dulu.
