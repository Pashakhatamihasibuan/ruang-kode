Siklus pengujian (STLC) dan peran QA di Agile

Buka versi interaktif

STLC (Software Testing Life Cycle): analisis kebutuhan, perencanaan pengujian (test plan: ruang lingkup, strategi, jadwal, risiko), desain test case, persiapan lingkungan dan data uji, eksekusi, pelaporan bug, dan penutupan (laporan ringkasan).

Di tim Agile/Scrum, QA ikut sprint planning dan refinement untuk memperjelas kriteria penerimaan, menulis test case bersamaan dengan developer menulis kode, mengotomasi regresi, dan memastikan Definition of Done mencakup pengujian.

Metrik yang sering dipakai: jumlah cacat per modul, defect leakage (bug yang lolos ke produksi), cakupan otomasi, waktu rata-rata perbaikan, dan tingkat kelulusan tes. Hati-hati: metrik dipakai untuk belajar, bukan menghukum orang.

CONTOH
Test plan ringkas: Fitur Checkout v2
Ruang lingkup : keranjang, alamat, ongkir, pembayaran QRIS dan VA
Di luar lingkup: aplikasi kurir
Strategi       : unit (dev), API (QA), E2E alur utama, uji di Android 11-15
Lingkungan     : staging + data uji 200 produk, sandbox payment gateway
Risiko         : timeout payment gateway -> uji retry dan pesan error
Kriteria keluar: 0 bug kritis, 0 bug tinggi terbuka, regresi 100% lulus

Soal latihan

  1. Tulis dua kriteria penerimaan Given-When-Then untuk fitur "tambah ke keranjang".

    Petunjuk

    Satu kasus berhasil, satu kasus stok habis.

    Lihat jawaban
    CONTOH
    Given produk Kopi Gayo stok 10
When pengguna menekan 'Tambah ke keranjang'
Then jumlah di ikon keranjang bertambah 1

Given produk stok 0
When pengguna membuka halaman produk
Then tombol 'Tambah ke keranjang' nonaktif dan tertulis 'Stok habis'

Poin penting

  • STLC: rencana, desain, persiapan, eksekusi, laporan, penutupan.
  • Di Agile, QA ikut sejak refinement.
  • Kriteria keluar menentukan kapan siap rilis.
