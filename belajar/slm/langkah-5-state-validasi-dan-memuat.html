Langkah 5: state, validasi, dan memuat

Buka versi interaktif

Desain biasanya hanya menampilkan keadaan normal. Slicer melengkapi state: pesan error di bawah field yang salah, tombol nonaktif dan spinner saat memuat agar tidak ditekan dua kali, serta snackbar jika server gagal.

Validasi saat pengguna menekan Masuk, lalu validasi ulang per field setelah pengguna memperbaikinya. Tulis pesan yang menjelaskan cara memperbaiki: "Format email belum benar, contoh: nama@contoh.id", bukan "Input tidak valid".

Di Compose, simpan state di ViewModel sebagai StateFlow berisi data class UiMasuk(email, sandi, errorEmail, memuat).

KODE
Future<void> masuk() async {
  final valid = _form.currentState!.validate();
  if (!valid) return;
  setState(() => memuat = true);
  try {
    await auth.masuk(email.text.trim(), sandi.text);
    if (mounted) context.go('/beranda');
  } on AuthGagal {
    if (mounted) {
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('Email atau kata sandi salah')),
      );
    }
  } finally {
    if (mounted) setState(() => memuat = false);
  }
}

String? cekEmail(String? v) =>
    (v == null || !RegExp(r'^[^@\s]+@[^@\s]+\.[^@\s]+$').hasMatch(v.trim()))
        ? 'Format email belum benar, contoh: nama@contoh.id'
        : null;

// tombol: nonaktif + spinner saat memuat
FilledButton(
  onPressed: memuat ? null : masuk,
  child: memuat
      ? const SizedBox(width: 20, height: 20, child: CircularProgressIndicator(strokeWidth: 2))
      : const Text('Masuk'),
)

Poin penting

  • Lengkapi state error, memuat, gagal.
  • Pesan error menjelaskan cara memperbaiki.
  • Nonaktifkan tombol saat memuat.
