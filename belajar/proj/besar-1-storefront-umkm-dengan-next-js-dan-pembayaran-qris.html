Besar 1: Storefront UMKM dengan Next.js dan pembayaran QRIS

Buka versi interaktif

Masalah. UMKM ingin berjualan langsung di websitenya sendiri tanpa potongan marketplace, dengan pembayaran QRIS yang sudah umum dipakai pembeli.

Fitur wajib:
1. Katalog dengan filter kategori, pencarian, dan pagination yang ramah SEO (dirender di server)
2. Halaman produk dengan metadata, Open Graph, dan data terstruktur Product
3. Keranjang yang bertahan saat halaman dimuat ulang
4. Checkout membuat transaksi QRIS di Midtrans sandbox; status diperbarui lewat webhook
5. Core Web Vitals hijau (LCP < 2,5 s, CLS < 0,1)

Penyelesaian langkah demi langkah:
1. Rancang tabel Produk, Pesanan, ItemPesanan dengan Prisma; seed 30 produk.
2. Katalog sebagai Server Component dengan searchParams untuk filter dan halaman, sehingga URL bisa dibagikan dan diindeks.
3. Keranjang disimpan di cookie lewat Server Action agar bekerja tanpa JavaScript tambahan.
4. Checkout: hitung total di server dari harga database (jangan dari klien), buat pesanan status MENUNGGU, lalu minta QRIS ke Midtrans.
5. Webhook: verifikasi signature_key = SHA512(order_id + status_code + gross_amount + server_key), proses secara idempoten, ubah status ke DIBAYAR.
6. Optimasi gambar dengan next/image, uji E2E, deploy ke Vercel dengan database Neon.

Standar industri yang dinilai: harga dihitung di server, webhook diverifikasi dan idempoten, halaman katalog terindeks mesin pencari, Core Web Vitals dicantumkan di README

Arsitektur dan stack (Next.js 15 App Router, TypeScript, Tailwind, Prisma + PostgreSQL, Midtrans Snap/Core API sandbox, Playwright, Vercel)

// app/(toko)/page.tsx — katalog dirender di server, ramah SEO
import Link from 'next/link';
import { prisma } from '@/lib/db';

export default async function Katalog({ searchParams }: { searchParams: Promise<{ q?: string; kat?: string; hal?: string }> }) {
  const { q = '', kat, hal = '1' } = await searchParams;
  const where = { aktif: true, nama: { contains: q, mode: 'insensitive' as const }, ...(kat ? { kategori: { slug: kat } } : {}) };
  const [produk, jumlah] = await Promise.all([
    prisma.produk.findMany({ where, orderBy: { nama: 'asc' }, take: 12, skip: (Number(hal) - 1) * 12 }),
    prisma.produk.count({ where }),
  ]);
  return (
    <main>
      <form><input name="q" defaultValue={q} aria-label="Cari produk" /><button>Cari</button></form>
      {produk.length === 0 && <p>Produk "{q}" belum ada.</p>}
      <ul className="grid grid-cols-2 gap-4 md:grid-cols-4">
        {produk.map(p => <li key={p.id}><Link href={`/produk/${p.slug}`}>{p.nama} · Rp{p.harga.toLocaleString('id-ID')}</Link></li>)}
      </ul>
      <nav aria-label="Halaman">Halaman {hal} dari {Math.ceil(jumlah / 12)}</nav>
    </main>
  );
}

// app/checkout/actions.ts — total dihitung di server
'use server';
import { cookies } from 'next/headers';
import { redirect } from 'next/navigation';
export async function checkout() {
  const isi: { id: number; qty: number }[] = JSON.parse((await cookies()).get('keranjang')?.value ?? '[]');
  const produk = await prisma.produk.findMany({ where: { id: { in: isi.map(i => i.id) } } });
  const total = isi.reduce((s, i) => s + produk.find(p => p.id === i.id)!.harga * i.qty, 0);
  const pesanan = await prisma.pesanan.create({ data: { total, status: 'MENUNGGU',
    item: { create: isi.map(i => ({ produkId: i.id, qty: i.qty, harga: produk.find(p => p.id === i.id)!.harga })) } } });
  const r = await fetch('https://api.sandbox.midtrans.com/v2/charge', { method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: 'Basic ' + btoa(process.env.MIDTRANS_SERVER_KEY + ':') },
    body: JSON.stringify({ payment_type: 'qris', transaction_details: { order_id: `PSN-${pesanan.id}`, gross_amount: total } }) });
  const qris = await r.json();
  await prisma.pesanan.update({ where: { id: pesanan.id }, data: { qrUrl: qris.actions?.[0]?.url } });
  redirect(`/pesanan/${pesanan.id}`);
}

// app/api/midtrans/webhook/route.ts — verifikasi tanda tangan, idempoten
import { createHash } from 'crypto';
export async function POST(req: Request) {
  const n = await req.json();
  const sig = createHash('sha512').update(n.order_id + n.status_code + n.gross_amount + process.env.MIDTRANS_SERVER_KEY).digest('hex');
  if (sig !== n.signature_key) return new Response('signature salah', { status: 403 });
  const id = Number(n.order_id.replace('PSN-', ''));
  if (n.transaction_status === 'settlement')
    await prisma.pesanan.updateMany({ where: { id, status: 'MENUNGGU' }, data: { status: 'DIBAYAR' } });  // idempoten
  return Response.json({ ok: true });
}

Cek pemahaman

Kenapa update status memakai where status MENUNGGU?

Jawaban: Agar webhook yang terkirim dua kali tidak memproses ulang pesanan

Idempotensi: hasilnya sama walau dipanggil berkali-kali.
