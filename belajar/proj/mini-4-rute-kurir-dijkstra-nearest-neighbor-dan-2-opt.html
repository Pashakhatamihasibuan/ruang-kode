Mini 4: Rute kurir: Dijkstra, nearest neighbor, dan 2-opt

Buka versi interaktif

Masalah. Kurir UMKM harus mengantar 6 paket lalu kembali ke gudang. Rute dipilih berdasarkan perasaan, sehingga bensin dan waktu terbuang. Pemilik ingin rute yang mendekati optimal tanpa perangkat lunak mahal.

Fitur wajib:
1. Hitung jarak terpendek antar semua titik dengan Dijkstra
2. Susun rute awal dengan nearest neighbor
3. Perbaiki rute dengan 2-opt
4. Bandingkan dengan solusi optimal brute force untuk data kecil
5. Jelaskan kenapa brute force tidak bisa dipakai untuk banyak titik

Penyelesaian langkah demi langkah:
1. Jalankan Dijkstra dari setiap titik untuk mendapat matriks jarak (peta jalan tidak langsung lengkap).
2. Nearest neighbor: dari posisi sekarang selalu ke tujuan terdekat yang belum dikunjungi.
3. 2-opt: coba balik setiap segmen; ulangi selama ada perbaikan.
4. Brute force dengan itertools.permutations untuk memastikan kualitas heuristik.
5. Hitung n! untuk menunjukkan ledakan kombinasi (TSP adalah NP-hard).

Kembangkan sendiri: tambahkan jendela waktu pengantaran dan kapasitas motor, lalu bandingkan dengan pustaka OR-Tools.

PYTHON
import heapq, itertools, math

# Kurir mengantar 6 paket dari gudang. Langkah 1: jarak terpendek antar titik di peta jalan (Dijkstra).
jalan = {"Gudang": {"A": 4, "B": 2}, "A": {"Gudang": 4, "B": 1, "C": 5}, "B": {"Gudang": 2, "A": 1, "D": 8, "E": 10},
         "C": {"A": 5, "D": 2, "F": 6}, "D": {"B": 8, "C": 2, "E": 3, "F": 4}, "E": {"B": 10, "D": 3, "F": 2}, "F": {"C": 6, "D": 4, "E": 2}}

def dijkstra(src):
    dist, pq = {src: 0}, [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]: continue
        for v, w in jalan[u].items():
            if d + w < dist.get(v, math.inf): dist[v] = d + w; heapq.heappush(pq, (d + w, v))
    return dist

titik = list(jalan)
D = {a: dijkstra(a) for a in titik}                  # matriks jarak semua pasangan (km)
tujuan = ["A", "B", "C", "D", "E", "F"]

def panjang(rute): return sum(D[a][b] for a, b in zip(rute, rute[1:]))

# Langkah 2a: heuristik nearest neighbor (cepat, O(n²), belum tentu optimal)
rute, sisa = ["Gudang"], set(tujuan)
while sisa:
    nxt = min(sisa, key=lambda t: (D[rute[-1]][t], t)); rute.append(nxt); sisa.remove(nxt)
rute.append("Gudang")
print("nearest neighbor:", " -> ".join(rute), f"= {panjang(rute)} km")

# Langkah 2b: perbaikan 2-opt (balik segmen jika memperpendek)
def dua_opt(r):
    membaik = True
    while membaik:
        membaik = False
        for i in range(1, len(r) - 2):
            for j in range(i + 1, len(r) - 1):
                baru = r[:i] + r[i:j + 1][::-1] + r[j + 1:]
                if panjang(baru) < panjang(r): r, membaik = baru, True
    return r
r2 = dua_opt(rute)
print("setelah 2-opt   :", " -> ".join(r2), f"= {panjang(r2)} km")

# Langkah 3: brute force untuk membuktikan optimal (6! = 720 urutan; tidak mungkin untuk 50 titik)
terbaik = min((["Gudang", *p, "Gudang"] for p in itertools.permutations(tujuan)), key=panjang)
print("optimal (brute) :", " -> ".join(terbaik), f"= {panjang(terbaik)} km")
print(f"jumlah urutan untuk 15 titik: {math.factorial(15):,}".replace(",", "."))

Cek pemahaman

Jawaban: 50! urutan terlalu banyak untuk dihitung; heuristik memberi rute bagus dalam waktu singkat

Masalah NP-hard butuh heuristik.
