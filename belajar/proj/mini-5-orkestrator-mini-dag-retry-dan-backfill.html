Mini 5: Orkestrator mini: DAG, retry, dan backfill

Buka versi interaktif

Masalah. Sebelum memakai Airflow, tim ingin memahami cara kerja orkestrator: urutan task dari dependensi, retry saat API sumber timeout, task hilir tidak jalan bila hulu gagal, dan menjalankan ulang beberapa hari yang terlewat.

Fitur wajib:
1. Definisi DAG sebagai graf dependensi
2. Urutan eksekusi topologis
3. Retry dengan exponential backoff
4. Status upstream_failed untuk task hilir
5. Backfill beberapa logical date, satu run per tanggal

Penyelesaian langkah demi langkah:
1. graphlib.TopologicalSorter menghasilkan urutan yang menghormati dependensi.
2. Iterasi static_order(); cek semua hulu sukses sebelum menjalankan task.
3. Jeda 30, 60, 120 detik (2 ** percobaan * 30).
4. Tandai task hilir tanpa menjalankannya agar mudah dilacak.
5. Setiap run menerima ds sehingga hasilnya hanya bergantung pada tanggal itu.

Kembangkan sendiri: tulis ulang sebagai DAG Airflow dengan TaskFlow API, tambahkan sensor file, SLA, dan notifikasi kegagalan ke Slack.
