Proyek Portofolio · Modul 2 · Konsep & kode

Peta besar: perjalanan satu request

Buka versi interaktif

Aplikasi web modern dibagi tiga lapis. Frontend (React di browser) menampilkan data dan menerima input. API (Django REST Framework di server) memeriksa siapa pengguna, memvalidasi data, menjalankan aturan bisnis, lalu berbicara dengan database (PostgreSQL) yang menyimpan data secara permanen.

Ketiganya berkomunikasi lewat kontrak yang jelas: frontend mengirim HTTP request (method, URL, header, body JSON) dan API membalas dengan status code dan JSON. API menerjemahkan request menjadi query SQL lewat ORM.

Di proyek ini kita membangun KasirKu, aplikasi kasir dan stok untuk kedai kopi. Urutan pengerjaan yang disarankan justru dari bawah: rancang tabel → buat API dan uji dengan curl → baru bangun tampilan. Dengan begitu frontend dibangun di atas fondasi yang sudah pasti.

CONTOH
Pengguna klik "Simpan pesanan"
        │
        ▼
[Frontend React]  POST /api/pesanan/   Authorization: Bearer <token>
        │          body: {"item": [{"produk": 3, "jumlah": 2}]}
        ▼
[API Django REST]  1. cek token  -> siapa pengguna?
                   2. validasi    -> produk ada? jumlah > 0?
                   3. aturan bisnis -> stok cukup? hitung total
                   4. ORM -> SQL
        │
        ▼
[PostgreSQL]   BEGIN;
               SELECT ... FROM produk WHERE id=3 FOR UPDATE;
               UPDATE produk SET stok = stok - 2 WHERE id=3;
               INSERT INTO pesanan ...; INSERT INTO item_pesanan ...;
               COMMIT;
        │
        ▼
[API]  201 Created  {"id": 41, "total": "56000.00"}
        │
        ▼
[Frontend]  tampilkan "Pesanan #41 tersimpan", segarkan daftar stok

Poin penting

  • Frontend → HTTP/JSON → API → ORM/SQL → database.
  • API adalah satu-satunya pintu ke database.
  • Bangun dari bawah: database, API, lalu frontend.
