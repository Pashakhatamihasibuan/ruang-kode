Besar 3: Platform BI perusahaan dengan satu definisi metrik

Buka versi interaktif

Masalah. Grup ritel dengan 120 toko punya 47 dashboard buatan masing-masing divisi. Angka omzet di rapat direksi berbeda antara keuangan, operasional, dan pemasaran, sehingga rapat habis untuk berdebat soal angka, bukan keputusan.

Fitur wajib:
1. Inventaris dashboard dan definisi metrik yang beredar; sepakati kamus metrik
2. Model data terpusat (dbt) dengan tes kualitas dan dokumentasi
3. Semantic layer: omzet, margin, AOV, like-for-like growth didefinisikan sekali
4. Dashboard resmi bersertifikat dengan RLS per wilayah dan label kebaruan data
5. Tata kelola: pemilik metrik, proses permintaan dashboard baru, pensiun dashboard tak terpakai

Penyelesaian langkah demi langkah:
1. Kumpulkan semua definisi omzet yang beredar dan selenggarakan workshop penyepakatan dengan CFO.
2. Bangun model dbt dan tes; rekonsiliasi angka dengan laporan keuangan resmi.
3. Definisikan metrik di semantic layer dan bangun dashboard eksekutif bersertifikat.
4. Terapkan RLS, katalog data, dan proses permintaan dashboard.
5. Pensiunkan dashboard duplikat dan ukur adopsi serta waktu rapat.

Standar industri yang dinilai: satu definisi per metrik dengan pemilik, angka BI terekonsiliasi dengan laporan keuangan, kualitas data teruji otomatis, akses sesuai peran, adopsi terukur

Arsitektur dan stack (BigQuery/Snowflake, dbt Core + Semantic Layer, Airflow, Power BI/Looker, Git + CI, data catalog (DataHub/OpenMetadata))
BagianIsi
Modelstaging → marts (fakta harian per toko-produk, dimensi SCD2) dengan tes unique/not_null/relationships
Metrikkamus metrik dengan pemilik, rumus, filter, contoh; disimpan sebagai kode
AksesRLS per wilayah, data pribadi pelanggan tidak masuk lapisan BI
Kualitastes dbt gagal → banner "data tertunda", alert ke pemilik
Adopsijumlah pengguna aktif mingguan, dashboard resmi vs liar, waktu rapat untuk keputusan
Pensiundashboard tidak dibuka 60 hari diarsipkan setelah konfirmasi pemilik
SQL
-- models/marts/fct_penjualan_harian.sql (dbt) — satu definisi angka untuk semua dashboard
{{ config(materialized='incremental', unique_key=['tanggal', 'toko_id', 'produk_id'], partition_by={'field': 'tanggal', 'data_type': 'date'}) }}
select date(t.waktu, 'Asia/Jakarta') as tanggal, t.toko_id, d.produk_id,
       count(distinct t.transaksi_id) as jumlah_transaksi,
       sum(d.qty) as qty, sum(d.qty * d.harga) as omzet, sum(d.qty * p.hpp) as hpp
from {{ ref('stg_pos__transaksi') }} t
join {{ ref('stg_pos__detail') }} d using (transaksi_id)
join {{ ref('dim_produk') }} p on p.produk_id = d.produk_id and t.waktu between p.berlaku_dari and p.berlaku_sampai
where t.status = 'selesai'
{% if is_incremental() %} and date(t.waktu, 'Asia/Jakarta') >= date_sub(current_date('Asia/Jakarta'), interval 3 day) {% endif %}
group by 1, 2, 3

# models/marts/_metrics.yml — dbt Semantic Layer (MetricFlow)
semantic_models:
  - name: penjualan
    model: ref('fct_penjualan_harian')
    defaults: { agg_time_dimension: tanggal }
    entities: [{ name: toko, type: foreign, expr: toko_id }]
    measures:
      - { name: omzet, agg: sum }
      - { name: hpp, agg: sum }
    dimensions: [{ name: tanggal, type: time, type_params: { time_granularity: day } }]
metrics:
  - { name: omzet, type: simple, type_params: { measure: omzet } }
  - name: margin_kotor
    type: derived
    type_params: { expr: (omzet - hpp) / omzet, metrics: [omzet, hpp] }
