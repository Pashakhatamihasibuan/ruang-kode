Besar 4: Keamanan dan kepatuhan database data sensitif

Buka versi interaktif

Masalah. Jaringan klinik menyimpan rekam medis dan data pribadi 3 juta pasien. Audit internal menemukan analis memakai akun superuser bersama, NIK tersimpan polos, tidak ada jejak siapa membaca data pasien, dan permintaan penghapusan data sesuai UU PDP belum bisa dipenuhi.

Fitur wajib:
1. Role per fungsi dengan least privilege; tidak ada akun bersama dan superuser untuk aplikasi
2. Enkripsi kolom sensitif (envelope encryption + KMS) dan hash untuk pencarian
3. Audit akses dengan pgaudit ke SIEM; akses data pasien oleh dokter tercatat
4. View tersamar untuk analitik; akses darurat just-in-time dengan batas waktu
5. Prosedur hak subjek data (akses, koreksi, hapus) dengan jejak audit

Penyelesaian langkah demi langkah:
1. Inventarisasi data sensitif dan pemetaan siapa butuh akses apa (bersama legal & DPO).
2. Bangun role per fungsi, cabut superuser bersama, pasang akses lewat bastion dengan SSO.
3. Migrasikan kolom sensitif ke bentuk terenkripsi secara bertahap; buat view tersamar.
4. Aktifkan pgaudit + SIEM; buat alert untuk pola akses tidak wajar.
5. Implementasikan prosedur hak subjek data dan jadwalkan review akses kuartalan.

Standar industri yang dinilai: least privilege terbukti dari audit role, data sensitif tidak tersimpan polos, setiap akses data pasien tercatat, hak subjek data bisa dipenuhi dengan jejak, review akses berkala

Arsitektur dan stack (PostgreSQL 16, pgaudit, pgcrypto/enkripsi di aplikasi + KMS (AWS KMS/GCP KMS/HashiCorp Vault), RLS, SSL/TLS 1.3, SIEM (Wazuh/Elastic), Teleport/Boundary untuk akses)
BagianIsi
IdentitasSSO + akses lewat bastion (Teleport); password diganti secret dinamis dari Vault
Dataschema pii terpisah, kolom NIK/HP terenkripsi, nik_hash untuk pencarian persis

SQL
-- Keamanan & kepatuhan database layanan kesehatan (UU PDP, audit, prinsip least privilege)
-- 1) Audit: siapa membaca/mengubah data sensitif (pgaudit) -> dikirim ke SIEM
ALTER SYSTEM SET pgaudit.log = 'ddl, role, write';
ALTER ROLE dokter SET pgaudit.log = 'read, write';          -- akses rekam medis oleh dokter diaudit penuh
SELECT pg_reload_conf();

-- 2) Pemisahan data: PII di schema terpisah, kolom sensitif dienkripsi di aplikasi (envelope encryption + KMS)
CREATE SCHEMA pii AUTHORIZATION pemilik_data;
CREATE TABLE pii.pasien (id uuid PRIMARY KEY, nik_hash bytea UNIQUE, nik_enc bytea, nama text, tgl_lahir date, hp_enc bytea);
REVOKE ALL ON SCHEMA pii FROM PUBLIC;

-- 3) View tersamar untuk analis: tidak pernah melihat NIK/HP asli, umur dibulatkan per 5 tahun
CREATE VIEW analitik.pasien_tersamar WITH (security_barrier) AS
SELECT id, left(nama, 1) || '***' AS inisial, (date_part('year', age(tgl_lahir))::int / 5) * 5 AS kelompok_umur
FROM pii.pasien;
GRANT SELECT ON analitik.pasien_tersamar TO analis;

-- 4) Akses just-in-time: role darurat aktif maksimal 2 jam, dicatat dan disetujui lewat tiket
CREATE ROLE dba_darurat NOLOGIN;
-- (otomasi) GRANT dba_darurat TO budi;  ALTER ROLE budi VALID UNTIL now() + interval '2 hours';

-- 5) Hak subjek data: penghapusan (right to erasure) dengan jejak audit, bukan DELETE diam-diam
CREATE PROCEDURE pii.hapus_pasien(p_id uuid, p_tiket text) LANGUAGE plpgsql SECURITY DEFINER SET search_path = pii, pg_temp AS $$
BEGIN
  UPDATE pii.pasien SET nik_enc = NULL, hp_enc = NULL, nama = '[dihapus]' WHERE id = p_id;
  INSERT INTO audit.permintaan_data (pasien_id, jenis, tiket, waktu) VALUES (p_id, 'hapus', p_tiket, now());
END $$;
REVOKE ALL ON PROCEDURE pii.hapus_pasien FROM PUBLIC;
GRANT EXECUTE ON PROCEDURE pii.hapus_pasien TO petugas_privasi;

-- 6) Pemeriksaan berkala: role dengan hak berlebih, password kedaluwarsa, koneksi tanpa SSL
SELECT rolname, rolsuper, rolbypassrls, rolvaliduntil FROM pg_roles WHERE rolsuper OR rolbypassrls ORDER BY 1;
SELECT usename, client_addr, ssl FROM pg_stat_ssl JOIN pg_stat_activity USING (pid) WHERE NOT ssl AND client_addr IS NOT NULL;

Cek pemahaman

Kenapa NIK disimpan sebagai hash (untuk pencarian) dan ciphertext (untuk ditampilkan) secara terpisah?

Jawaban: Hash memungkinkan pencarian persis tanpa mendekripsi, sedangkan ciphertext hanya didekripsi oleh layanan berizin saat benar-benar perlu
