Kualitas kode: lint, test, dan CI

Buka versi interaktif

Di tim, setiap perubahan otomatis dicek sebelum digabung. Siapkan tiga lapis: formatter dan linter (Ruff untuk Python, ESLint + Prettier untuk TypeScript), test otomatis (pytest, Vitest), dan CI (GitHub Actions) yang menjalankan keduanya di setiap push dan pull request.

Tidak perlu cakupan test 100%. Uji hal yang paling mahal jika rusak: aturan bisnis (stok tidak boleh minus, total harga benar), izin akses (kasir tidak boleh menghapus produk), dan alur utama pengguna.

Badge CI hijau di README memberi sinyal cepat ke perekrut bahwa proyekmu benar-benar jalan.

TERMINAL
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  backend:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16
        env: { POSTGRES_PASSWORD: rahasia, POSTGRES_DB: kasirku }
        ports: ['5432:5432']
    defaults: { run: { working-directory: backend } }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.12' }
      - run: pip install -r requirements.txt
      - run: ruff check .
      - run: pytest
        env: { DATABASE_URL: postgres://postgres:rahasia@localhost:5432/kasirku }
  frontend:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: frontend } }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci
      - run: npm run lint
      - run: npm test -- --run
      - run: npm run build

Poin penting

  • Formatter/linter + test + CI di setiap PR.
  • Uji aturan bisnis, izin akses, alur utama.
  • Badge CI hijau di README.
