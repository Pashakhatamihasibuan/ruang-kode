Proyek Portofolio · Modul 2 · Konsep & kode

Merancang database PostgreSQL

Buka versi interaktif

Turunkan tabel dari kata benda di user story: kategori, produk, pesanan, dan item_pesanan (tabel penghubung karena satu pesanan berisi banyak produk). Tabel pengguna disediakan Django.

Pasang aturan di database, bukan hanya di kode: NOT NULL, UNIQUE, CHECK (stok >= 0), dan FOREIGN KEY. Jika suatu hari ada bug di API, database tetap menolak data yang salah. Simpan uang dengan NUMERIC(12,2), bukan float.

Salin harga saat transaksi ke item_pesanan. Jika harga produk naik besok, laporan penjualan kemarin tidak ikut berubah. Tambahkan index untuk kolom yang sering dicari atau di-join.

SQL
CREATE TABLE kategori (
  id    SERIAL PRIMARY KEY,
  nama  VARCHAR(60) NOT NULL UNIQUE
);

CREATE TABLE produk (
  id           SERIAL PRIMARY KEY,
  kategori_id  INT NOT NULL REFERENCES kategori(id),
  nama         VARCHAR(120) NOT NULL,
  harga        NUMERIC(12,2) NOT NULL CHECK (harga > 0),
  stok         INT NOT NULL DEFAULT 0 CHECK (stok >= 0),
  aktif        BOOLEAN NOT NULL DEFAULT TRUE,
  dibuat       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_produk_nama ON produk (lower(nama));

CREATE TABLE pesanan (
  id       SERIAL PRIMARY KEY,
  kasir_id INT NOT NULL REFERENCES auth_user(id),
  total    NUMERIC(12,2) NOT NULL,
  dibuat   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_pesanan_dibuat ON pesanan (dibuat);

CREATE TABLE item_pesanan (
  id          SERIAL PRIMARY KEY,
  pesanan_id  INT NOT NULL REFERENCES pesanan(id) ON DELETE CASCADE,
  produk_id   INT NOT NULL REFERENCES produk(id),
  jumlah      INT NOT NULL CHECK (jumlah > 0),
  harga_saat  NUMERIC(12,2) NOT NULL      -- harga ketika dijual
);

Poin penting

  • Tabel dari kata benda; banyak-ke-banyak lewat tabel penghubung.
  • Constraint di database: CHECK, FK, UNIQUE, NOT NULL.
  • Uang = NUMERIC; simpan harga saat transaksi.
