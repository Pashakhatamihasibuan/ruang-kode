Besar 1: PostgreSQL high availability di Kubernetes dengan backup dan PITR

Buka versi interaktif

Masalah. Marketplace menjalankan PostgreSQL di satu VM tanpa replika. Saat disk rusak, toko mati 6 jam dan data 4 jam terakhir hilang. Targetnya RPO 0 untuk transaksi, RTO < 1 menit, dan restore yang teruji setiap bulan.

Fitur wajib:
1. Cluster 3 instance di zona berbeda dengan failover otomatis
2. Replikasi sinkron minimal 1 standby (RPO 0)
3. Backup harian + arsip WAL terus-menerus ke object storage, retensi 30 hari
4. Connection pooler (PgBouncer) dan pemisahan endpoint baca/tulis
5. Restore drill bulanan dan uji failover kuartalan dengan hasil terukur

Penyelesaian langkah demi langkah:
1. Ukur kebutuhan: ukuran data, laju WAL per jam, RPO/RTO yang disepakati bisnis.
2. Pasang operator dan cluster di staging; uji failover dengan mematikan pod primary.
3. Konfigurasikan backup + arsip WAL, lakukan PITR percobaan ke cluster baru.
4. Migrasikan data produksi (logical replication) dan pindahkan aplikasi lewat Pooler.
5. Jadwalkan drill, dokumentasikan runbook, dan pantau SLO.

Standar industri yang dinilai: RPO dan RTO tertulis dan terbukti lewat drill, backup diuji secara berkala, failover otomatis teruji, akses lewat pooler, pemantauan dan runbook tersedia

Arsitektur dan stack (Kubernetes, CloudNativePG (atau Patroni di VM), PgBouncer, S3/GCS dengan IAM, Prometheus + Grafana, pgaudit)
BagianIsi
Topologi1 primary + 2 standby anti-affinity per zona; WAL di volume terpisah
Durabilitassynchronous standby 1, wal_compression zstd, arsip WAL ke object storage
AksesPooler rw (transaction mode) dan ro untuk laporan; aplikasi tidak tahu primary mana
Backupbase backup harian 01.00 WIB + WAL kontinu; PITR ke detik mana pun dalam 30 hari
Pemantauanlag replikasi, umur backup terakhir, ruang disk, koneksi, query lambat; alert ke on-call
Ujirestore drill bulanan (catat durasi & validasi data), failover kuartalan (target < 30 s)
