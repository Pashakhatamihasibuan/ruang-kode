Mini 3: Penjaga kualitas data dengan kontrak dan laporan

Buka versi interaktif

Masalah. Perusahaan payment gateway sering menerima data transaksi rusak dari tim aplikasi (nominal 0, metode pembayaran baru tanpa pemberitahuan). Dashboard keuangan sudah terlanjur salah sebelum ada yang sadar.

Fitur wajib:
1. Kontrak data ditulis sebagai model Pydantic (pola ID, rentang nominal, nilai metode yang diizinkan)
2. Hitung pelanggaran per aturan, bukan berhenti di error pertama
3. Cek tingkat batch: persentase valid, freshness, keunikan, volume
4. Laporan JSON yang bisa dikirim ke Slack atau disimpan
5. Exit code 1 saat gagal agar orkestrator menghentikan pipeline

Penyelesaian langkah demi langkah:
1. Field(pattern=..., gt=0, le=...) menerjemahkan kesepakatan menjadi kode.
2. ValidationError.errors() memberi lokasi dan jenis setiap pelanggaran.
3. Ambang dibuat eksplisit, misalnya ≥ 95% baris valid.
4. json.dumps(laporan, indent=2).
5. sys.exit(kode_keluar) di skrip asli.

Kembangkan sendiri: pindahkan aturan ke dbt tests atau Great Expectations/Soda, simpan histori hasil cek, dan tampilkan tren kualitas di dashboard.
