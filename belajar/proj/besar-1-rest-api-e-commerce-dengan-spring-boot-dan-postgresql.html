Besar 1: REST API e-commerce dengan Spring Boot dan PostgreSQL

Buka versi interaktif

Masalah. UMKM fesyen ingin pindah dari marketplace ke toko sendiri. Mereka butuh backend untuk katalog, keranjang, checkout, dan panel admin yang aman, terdokumentasi, dan siap dipakai aplikasi web serta mobile.

Fitur wajib:
1. API REST berversi (/api/v1) dengan validasi dan format error standar (RFC 9457 Problem Details)
2. Autentikasi JWT + refresh token, peran ADMIN dan PELANGGAN
3. Migrasi database dengan Flyway, tidak ada perubahan skema manual
4. Checkout transaksional: stok berkurang dan pesanan tercatat bersama
5. Integration test dengan Testcontainers (PostgreSQL asli) dan dokumentasi OpenAPI

Penyelesaian langkah demi langkah:
1. Rancang ERD dan kontrak API (OpenAPI) dulu; sepakati dengan tim frontend.
2. Buat migrasi Flyway dan entity; uji repository dengan Testcontainers.
3. Tulis service checkout dengan @Transactional dan pengurangan stok bersyarat.
4. Tambahkan Spring Security: endpoint publik (katalog), pelanggan (keranjang), admin (kelola produk).
5. Seragamkan error dengan @RestControllerAdvice + ProblemDetail.
6. Kemas dengan Docker, jalankan CI, dan tulis README dengan cara menjalankan dalam satu perintah.

Standar industri yang dinilai: migrasi berversi, validasi input, error format standar, transaksi teruji dengan database asli, OpenAPI, CI hijau, satu perintah untuk menjalankan

Arsitektur dan stack (Java 21, Spring Boot 3, Spring Security, Spring Data JPA, PostgreSQL 16, Flyway, Testcontainers, springdoc-openapi, Docker)

  • Stack: Java 21, Spring Boot 3, Spring Security, Spring Data JPA, PostgreSQL 16, Flyway, Testcontainers, springdoc-openapi, Docker.
  • Kerjakan dulu sendiri, lalu buka kode final untuk code review.

Cek pemahaman

Kenapa integration test memakai Testcontainers, bukan H2 in-memory?

Jawaban: Perilaku PostgreSQL asli (constraint, tipe data, query) bisa berbeda dari H2, jadi bug baru ketahuan di produksi

Uji dengan database yang sama dengan produksi.
