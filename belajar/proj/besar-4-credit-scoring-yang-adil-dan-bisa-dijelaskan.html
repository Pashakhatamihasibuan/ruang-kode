Besar 4: Credit scoring yang adil dan bisa dijelaskan

Buka versi interaktif

Masalah. Fintech pinjaman produktif untuk UMKM ingin model skor kredit yang lebih akurat dari scorecard lama, tetapi wajib bisa menjelaskan alasan penolakan ke nasabah dan regulator, serta tidak diskriminatif.

Fitur wajib:
1. Definisi target: gagal bayar 90+ hari dalam 12 bulan
2. Validasi out-of-time dan metrik industri: AUC, Gini, KS
3. Penjelasan per nasabah (SHAP) dan kode alasan penolakan
4. Uji keadilan antar kelompok (wilayah, jenis kelamin) dan pemantauan PSI
5. Dokumentasi model risk: model card, batasan, rencana pemantauan

Penyelesaian langkah demi langkah:
1. Tetapkan target, jendela observasi, dan populasi; buang fitur yang tidak tersedia saat aplikasi diajukan.
2. Latih LightGBM dengan constraint monotonik agar perilaku model masuk akal bagi analis risiko.
3. Validasi out-of-time; bandingkan Gini dengan scorecard lama.
4. Hitung SHAP untuk setiap keputusan dan petakan fitur ke kode alasan yang dimengerti nasabah.
5. Ukur keadilan antar kelompok; dokumentasikan temuan dan mitigasi.
6. Tulis model card dan pasang pemantauan PSI bulanan.

Standar industri yang dinilai: validasi out-of-time, Gini dan KS dilaporkan, kode alasan per keputusan, uji keadilan, PSI dipantau, model card untuk model risk management

Arsitektur dan stack (Python, LightGBM monotonik, SHAP, scikit-learn, PostgreSQL, laporan dengan Quarto)
BagianIsi
Dataaplikasi pinjaman, riwayat transaksi e-wallet/QRIS UMKM (dengan persetujuan), biro kredit
ModelLightGBM dengan constraint monotonik (mis. makin tinggi omzet → risiko tidak naik)
Validasilatih 2023–2024, uji out-of-time 2025; AUC, Gini = 2·AUC − 1, KS
PenjelasanSHAP per nasabah → 3 kode alasan teratas
Keadilanrasio persetujuan dan TPR antar kelompok; atribut sensitif tidak dipakai sebagai fitur
PemantauanPSI skor dan fitur bulanan; ambang 0,1 waspada, 0,25 tindakan
PYTHON
import lightgbm as lgb, numpy as np, pandas as pd, shap
from sklearn.metrics import roc_auc_score, roc_curve

df = pd.read_parquet('aplikasi_kredit.parquet')
latih, oot = df[df.tgl_aplikasi < '2025-01-01'], df[df.tgl_aplikasi >= '2025-01-01']
FITUR = ['omzet_bulanan', 'umur_usaha_bln', 'transaksi_qris_90h', 'rasio_cicilan', 'telat_bayar_12b', 'jumlah_pinjaman']
MONO = [-1, -1, -1, 1, 1, 1]  # arah yang diizinkan terhadap risiko

m = lgb.LGBMClassifier(n_estimators=500, learning_rate=0.03, num_leaves=15, monotone_constraints=MONO, min_child_samples=200)
m.fit(latih[FITUR], latih.gagal_bayar)
p = m.predict_proba(oot[FITUR])[:, 1]
auc = roc_auc_score(oot.gagal_bayar, p)
fpr, tpr, _ = roc_curve(oot.gagal_bayar, p)
print(f'OOT AUC {auc:.3f} | Gini {2 * auc - 1:.3f} | KS {np.max(tpr - fpr):.3f}')

# Kode alasan per nasabah dari SHAP
ALASAN = {'telat_bayar_12b': 'R01 Riwayat keterlambatan pembayaran', 'rasio_cicilan': 'R02 Cicilan terlalu besar dibanding pendapatan',
          'omzet_bulanan': 'R03 Omzet usaha belum mencukupi', 'umur_usaha_bln': 'R04 Usia usaha masih singkat',
          'transaksi_qris_90h': 'R05 Aktivitas transaksi usaha rendah', 'jumlah_pinjaman': 'R06 Jumlah pinjaman yang diajukan tinggi'}
ex = shap.TreeExplainer(m)
sv = ex.shap_values(oot[FITUR])
def alasan(i, k=3):
    urut = np.argsort(-sv[i])[:k]
    return [ALASAN[FITUR[j]] for j in urut if sv[i][j] > 0]

# Keadilan: rasio persetujuan antar kelompok (atribut sensitif TIDAK jadi fitur)
oot = oot.assign(setuju=p < 0.08)
grup = oot.groupby('wilayah').agg(rasio_setuju=('setuju', 'mean'), n=('setuju', 'size'))
grup['rasio_vs_tertinggi'] = grup.rasio_setuju / grup.rasio_setuju.max()
print(grup.round(3))  # tandai kelompok < 0.8 (aturan empat-perlima) untuk investigasi

# PSI bulanan
def psi(ref, kini, bins=10):
    q = np.quantile(ref, np.linspace(0, 1, bins + 1)); q[0], q[-1] = -np.inf, np.inf
    a = np.histogram(ref, q)[0] / len(ref) + 1e-6; b = np.histogram(kini, q)[0] / len(kini) + 1e-6
    return np.sum((b - a) * np.log(b / a))
