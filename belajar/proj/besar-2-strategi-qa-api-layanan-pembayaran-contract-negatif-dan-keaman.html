Besar 2: Strategi QA API layanan pembayaran: contract, negatif, dan keamanan

Buka versi interaktif

Masalah. Fintech payment gateway punya 14 microservice dan 3 aplikasi klien. Perubahan field kecil di satu layanan pernah membuat aplikasi mobile gagal membayar selama 2 jam. Callback bank yang dikirim ganda juga pernah menggandakan saldo merchant.

Fitur wajib:
1. Consumer-driven contract testing dengan Pact dan Pact Broker (can-i-deploy)
2. Suite API pytest: batas nominal, status code, skema, idempotensi
3. Uji keamanan API berdasarkan OWASP API Top 10 (BOLA/IDOR, autentikasi webhook)
4. Lingkungan uji dengan sandbox bank tiruan (WireMock) dan data sintetis
5. Pipeline: contract → API → smoke di staging → deploy bertahap

Penyelesaian langkah demi langkah:
1. Petakan layanan, konsumen, dan endpoint kritis bersama tim arsitektur.
2. Mulai Pact untuk satu pasangan (app-mobile → layanan-pembayaran) dan pasang can-i-deploy.
3. Bangun suite API dengan fixture Testcontainers dan WireMock; tambahkan kasus negatif dan keamanan.
4. Jalankan Schemathesis terhadap OpenAPI untuk fuzzing otomatis.
5. Integrasikan ke pipeline dan buat dashboard kualitas per layanan.

Standar industri yang dinilai: tidak ada perubahan API yang merusak klien lolos ke produksi, idempotensi dan keamanan diuji otomatis, lingkungan uji dapat dibuat ulang, nol data produksi di pengujian

Arsitektur dan stack (Python + pytest + httpx, Pact + Pact Broker, OpenAPI + Schemathesis, WireMock, Docker Compose/Testcontainers, OWASP ZAP, GitHub Actions)
BagianIsi
Lapisan tesunit (developer) → contract (Pact) → API (pytest) → E2E tipis (alur bayar utama)
Kontrakkonsumen menulis harapan, penyedia memverifikasi di CI; deploy diblok jika kontrak rusak
Negatifnominal batas, mata uang salah, token kedaluwarsa, merchant nonaktif, callback ganda/terlambat
Keamananakses lintas merchant, tanda tangan webhook, rate limit, data kartu tidak muncul di log
LingkunganTestcontainers (PostgreSQL, Redis, Kafka) + WireMock untuk bank; data sintetis, nol data produksi
Metrikinsiden kontrak = 0, cakupan endpoint, waktu pipeline, bug keamanan per rilis
