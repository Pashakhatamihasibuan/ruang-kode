Besar 3: Sistem reservasi klinik berkapasitas tinggi

Buka versi interaktif

Masalah. Jaringan klinik dengan 40 cabang membuka pendaftaran online pukul 06.00 setiap hari dan diserbu ribuan pasien sekaligus. Sistem lama sering down dan terjadi double booking pada slot dokter.

Fitur wajib:
1. Slot dokter per 15 menit tanpa double booking (constraint database)
2. Tahan lonjakan 2.000 request/detik saat pembukaan
3. Antrean virtual saat beban puncak dan notifikasi WhatsApp/SMS asinkron
4. Cache jadwal di Redis dengan invalidasi saat slot berubah
5. Uji beban (k6) dan target SLO: p95 < 300 ms, error < 0,1%

Penyelesaian langkah demi langkah:
1. Tentukan SLO dan skenario beban bersama tim operasional klinik.
2. Rancang tabel dengan unique constraint sebagai pertahanan terakhir terhadap double booking.
3. Aktifkan virtual thread dan ukur; batasi pool koneksi agar database tidak tumbang.
4. Tambahkan cache Redis untuk endpoint jadwal (paling sering dibaca).
5. Kirim notifikasi lewat antrean agar API tetap cepat walau penyedia SMS lambat.
6. Jalankan k6, temukan bottleneck dengan metrik dan trace, ulangi sampai SLO tercapai.

Standar industri yang dinilai: tidak ada double booking dalam uji beban, SLO tercapai dan dibuktikan dengan laporan k6, notifikasi asinkron, cache dengan invalidasi

Arsitektur dan stack (Java 21 (virtual thread), Spring Boot 3, PostgreSQL, Redis, RabbitMQ, k6, Grafana)
BagianIsi
Dataslot(dokter_id, mulai, status) dengan UNIQUE(dokter_id, mulai); reservasi(slot_id UNIQUE, pasien_id)
KonkurensiINSERT reservasi dengan unique constraint: pemenang tunggal per slot, yang kalah mendapat 409
Skalaspring.threads.virtual.enabled=true; HikariCP dibatasi sesuai kapasitas DB
Cachejadwal per cabang per hari di Redis, TTL 30 detik + invalidasi event
Asinkronevent ReservasiDibuat → RabbitMQ → layanan notifikasi
Ujik6: ramp 0 → 2.000 rps dalam 60 detik; ambang p95 dan error rate di CI

# application.yml
spring:
  threads.virtual.enabled: true
  datasource.hikari.maximum-pool-size: 40      # batas koneksi DB, bukan batas request
  data.redis.host: redis

// ReservasiService.java
@Service
@RequiredArgsConstructor
class ReservasiService {
    private final JdbcClient jdbc;
    private final RabbitTemplate mq;
    private final CacheManager cache;

    @Transactional
    public Reservasi pesan(long slotId, long pasienId) {
        try {
            long id = jdbc.sql("INSERT INTO reservasi (slot_id, pasien_id) VALUES (?, ?) RETURNING id")
                          .params(slotId, pasienId).query(Long.class).single();
            jdbc.sql("UPDATE slot SET status = 'TERISI' WHERE id = ?").param(slotId).update();
            mq.convertAndSend("reservasi", "dibuat", new ReservasiDibuat(id, slotId, pasienId));
            cache.getCache("jadwal").evict(cabangDari(slotId));
            return new Reservasi(id, slotId, pasienId);
        } catch (DuplicateKeyException e) {
            throw new SlotSudahTerisi(slotId); // -> 409 Conflict, frontend menawarkan slot lain
        }
    }

    @Cacheable(value = "jadwal", key = "#cabangId + ':' + #tanggal")
    public List<SlotDto> jadwal(long cabangId, LocalDate tanggal) {
        return jdbc.sql("SELECT s.id, s.mulai, d.nama, s.status FROM slot s JOIN dokter d ON d.id = s.dokter_id WHERE d.cabang_id = ? AND s.mulai::date = ?")
                   .params(cabangId, tanggal).query(SlotDto.class).list();
    }
}

// k6/pembukaan.js
import http from 'k6/http';
import { check } from 'k6';
export const options = {
  scenarios: { buka: { executor: 'ramping-arrival-rate', startRate: 0, timeUnit: '1s', preAllocatedVUs: 3000,
                       stages: [{ target: 2000, duration: '60s' }, { target: 2000, duration: '120s' }] } },
  thresholds: { http_req_duration: ['p(95)<300'], http_req_failed: ['rate<0.001'] },
};
export default function () {
  const slot = 1 + Math.floor(Math.random() * 5000);
  const r = http.post(`${__ENV.BASE}/api/v1/reservasi`, JSON.stringify({ slotId: slot }), { headers: { 'Content-Type': 'application/json' } });
  check(r, { '201 atau 409': (x) => x.status === 201 || x.status === 409 });
}
