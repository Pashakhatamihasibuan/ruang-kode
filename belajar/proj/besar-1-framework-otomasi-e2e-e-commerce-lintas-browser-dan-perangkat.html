Besar 1: Framework otomasi E2E e-commerce lintas browser dan perangkat

Buka versi interaktif

Masalah. Marketplace dengan rilis mingguan menjalankan 600 test case regresi manual selama 3 hari sebelum setiap rilis. Bug di checkout tetap lolos, dan QA kelelahan. Targetnya: regresi kritis berjalan otomatis kurang dari 15 menit di setiap PR.

Fitur wajib:
1. Framework Playwright + TypeScript dengan Page Object dan fixture
2. Data uji dibuat dan dihapus lewat API, login sekali dengan storageState
3. Proyek desktop, Android, dan iPhone (WebKit); tag @smoke/@regresi/@visual
4. Sharding paralel di CI, laporan HTML + JUnit + notifikasi Slack
5. Kebijakan flaky: trace saat retry, karantina bertiket, dashboard stabilitas

Penyelesaian langkah demi langkah:
1. Pilih 40 alur paling kritis dari analitik dan riwayat insiden; mulai dari sana, bukan dari semua test case.
2. Bangun kerangka: konfigurasi, POM, fixture data via API, global setup login.
3. Otomasikan alur kritis dengan locator berbasis peran; review kode tes seperti kode produksi.
4. Integrasikan ke CI dengan sharding, laporan, dan aturan merge (smoke wajib hijau).
5. Pantau flakiness mingguan, perbaiki atau karantina, dan perluas cakupan bertahap.

Standar industri yang dinilai: regresi kritis < 15 menit di setiap PR, tes independen dan deterministik, flakiness < 2%, laporan dapat ditindaklanjuti, kode tes direview

Arsitektur dan stack (Playwright, TypeScript, GitHub Actions/GitLab CI, Docker, Allure/HTML reporter, Slack, BrowserStack (perangkat nyata, opsional))
BagianIsi
Strukturpages/ (POM), fixtures/ (data & klien API), tests/ per domain, reporters/
Data ujifactory via API, data unik per tes, pembersihan otomatis, tidak memakai data produksi
Pemilihan tes@smoke di setiap deploy (≤ 5 menit), @regresi tiap malam, @visual di PR UI
Stabilitaslocator berbasis peran, tanpa sleep, mock layanan pihak ketiga, jam & zona waktu tetap
PelaporanJUnit untuk CI, HTML + trace untuk debugging, ringkasan ke Slack, tren pass rate
Metrikwaktu regresi, % kasus kritis terotomasi, flakiness rate < 2%, bug lolos ke produksi

Poin penting

  • Proyek besar: Framework otomasi E2E e-commerce lintas browser dan perangkat.
  • Stack: Playwright, TypeScript, GitHub Actions/GitLab CI, Docker, Allure/HTML reporter, Slack, BrowserStack (perangkat nyata, opsional).
  • Kerjakan dulu sendiri, lalu buka kode final untuk code review.

Jawaban: Lebih cepat dan stabil; UI cukup diuji pada alur yang memang sedang diuji

Setup lewat API, verifikasi perilaku lewat UI.
