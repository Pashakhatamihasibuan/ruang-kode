Apa yang dinilai dari proyek portofolio

Buka versi interaktif

Perekrut dan engineer yang mewawancarai biasanya hanya membuka proyekmu 2–5 menit. Yang mereka cari bukan jumlah proyek, tetapi bukti bahwa kamu bisa bekerja seperti di tim sungguhan: memahami masalah, menulis kode yang rapi, menguji, dan merilis.

Satu proyek besar yang selesai, ter-deploy, dan terdokumentasi lebih bernilai daripada sepuluh tutorial yang disalin. Proyek mini dipakai untuk menunjukkan satu keterampilan secara fokus (misalnya form dengan validasi, atau query analitik), proyek besar untuk menunjukkan kamu bisa menyatukan semuanya.

Hindari proyek "klon tutorial" tanpa perubahan. Ambil masalah nyata di sekitarmu (kedai kopi keluarga, koperasi kampus, data kota), lalu tambahkan keputusan teknis milikmu sendiri dan tuliskan alasannya di README.

Rubrik penilaian proyek (dipakai di semua proyek jalur ini)
AspekBelum siapSiap kerja
MasalahFitur acak tanpa tujuanMasalah dan pengguna jelas di README
FungsiHanya jalur suksesValidasi, error, data kosong ditangani
KodeSatu file panjangDipisah per tanggung jawab, nama jelas
KualitasTidak ada testTest otomatis + lint + CI hijau
RilisHanya jalan di laptopTer-deploy, ada link demo
DokumentasiREADME bawaanCara menjalankan, keputusan teknis, screenshot
GitSatu commit besarCommit kecil bermakna, branch dan PR
CONTOH
Daftar periksa 5 menit perekrut

[ ] Ada link demo yang bisa dibuka (atau video 1-2 menit)
[ ] README menjelaskan masalah, fitur, stack, dan cara menjalankan
[ ] Screenshot atau GIF di bagian atas README
[ ] Struktur folder rapi, nama file dan variabel jelas
[ ] Ada test dan CI yang hijau
[ ] Riwayat commit bermakna, bukan satu commit 'final'
[ ] Tidak ada password/API key di repo
[ ] Menangani kasus gagal: input salah, data kosong, server error

Poin penting

  • Perekrut hanya punya beberapa menit: demo dan README paling penting.
  • Satu proyek besar yang tuntas mengalahkan banyak tutorial.
  • Pakai rubrik untuk menilai proyekmu sendiri.
