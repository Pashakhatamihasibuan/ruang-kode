Mini 4: Rate limiter dan cache untuk API publik

Buka versi interaktif

Masalah. API katalog produk sering dibanjiri request dari satu klien sehingga melambat untuk semua orang. Tim butuh pembatas laju per API key dan cache untuk produk yang sering diminta.

Fitur wajib:
1. Token bucket: burst 5 request, lalu 2 request/detik per API key
2. Balas 429 Too Many Requests saat token habis
3. Jam bisa dipalsukan agar perilaku bisa diuji tanpa menunggu
4. LRU cache dengan statistik hit dan miss

Penyelesaian langkah demi langkah:
1. Simpan (token, waktu terakhir) per key; isi ulang token sebanding waktu yang berlalu.
2. Method synchronized agar aman dipanggil banyak thread.
3. Antarmuka Jam dengan implementasi palsu untuk tes.
4. LinkedHashMap dengan access-order dan removeEldestEntry.

Kembangkan sendiri: pindahkan penyimpanan token ke Redis agar berlaku di banyak instance server, dan tambahkan header Retry-After.
