Besar 1: Aplikasi ojek dan pesan antar dengan pelacakan real-time (Flutter)

Buka versi interaktif

Masalah. Startup logistik lokal di Makassar ingin menyaingi aplikasi besar dengan fokus kota lapis kedua. Pelanggan harus bisa memesan, melihat driver bergerak di peta secara langsung, dan aplikasi harus tetap bisa dipakai di sinyal naik-turun.

Fitur wajib:
1. Clean Architecture per fitur (domain, data, presentation) dengan Riverpod
2. Pelacakan real-time lewat WebSocket dengan reconnect exponential backoff dan fallback REST
3. Peta dan rute (google_maps_flutter atau flutter_map), estimasi waktu tiba
4. Push notification FCM untuk perubahan status pesanan
5. E2E test alur utama dengan Patrol, CI/CD fastlane ke Play internal track dan TestFlight

Penyelesaian langkah demi langkah:
1. Petakan status pesanan menjadi sealed class; UI wajib menangani semua kasus.
2. Bangun repository WebSocket dengan reconnect dan uji dengan server palsu.
3. Hubungkan peta: marker driver dianimasikan antar-posisi agar tidak melompat.
4. Integrasikan FCM: notifikasi membuka layar lacak lewat deep link.
5. Siapkan flavor, Crashlytics, dan pipeline CI yang menjalankan analyze, test, dan Patrol sebelum rilis.

Standar industri yang dinilai: arsitektur berlapis yang bisa dites, real-time tahan putus koneksi, crash-free users ≥ 99,5%, cold start < 2 detik di HP entry-level, rilis bertahap dengan feature flag

Arsitektur dan stack (Flutter 3.3x, Dart 3, Riverpod (riverpod_generator), go_router, Dio, web_socket_channel, Firebase (FCM, Crashlytics, Remote Config), Patrol, fastlane, GitHub Actions)
BagianIsi
Strukturlib/features/{auth,pesan,lacak,riwayat}/{domain,data,presentation}; lib/core untuk network, theme, error
StateRiverpod: StreamProvider untuk status real-time, AsyncNotifier untuk aksi (pesan, batal)
Real-timeWebSocket per pesanan; backoff 1-30 detik; status final menutup stream
OfflineRiwayat pesanan di cache lokal (drift/isar); antrean aksi saat offline
ObservabilitasCrashlytics + analytics event funnel (buka → pesan → driver ditemukan → selesai)
RilisFlavor dev/staging/prod, Remote Config untuk feature flag, staged rollout 10% → 100%
