Proyek besar (capstone) jalur Database Administrator. Masalahnya nyata: Aplikasi kasir mulai lambat dan pemilik takut kehilangan data. Kerjakan dalam sekitar 4 minggu dengan rencana mingguan di bawah.

Perlakukan seperti pekerjaan di tim: tulis kebutuhan dulu, pecah menjadi issue di GitHub Projects, kerjakan per branch dan pull request, dan catat keputusan teknis di README. Nilai dirimu dengan rubrik di modul pertama jalur ini.

Yang membedakan proyek ini dari tutorial: pemulihan benar-benar diuji, metrik sebelum/sesudah tuning, runbook langkah demi langkah. Itulah yang akan kamu ceritakan saat wawancara.

PROYEK BESAR: Operasional PostgreSQL untuk aplikasi kasir

Masalah
  Aplikasi kasir mulai lambat dan pemilik takut kehilangan data.

Fitur wajib
  1. Replikasi streaming primary-replica
  2. Backup otomatis dan uji pemulihan berkala
  3. Pemantauan (Prometheus + Grafana): koneksi, lag, query lambat
  4. Tuning konfigurasi dan index berdasarkan beban
  5. Runbook insiden

Stack yang disarankan
  PostgreSQL 16, pgBackRest, Patroni (opsional), Prometheus, postgres_exporter, Grafana, Docker Compose

Rencana 4 minggu
  Minggu 1: instalasi, konfigurasi, peran
  Minggu 2: backup dan pemulihan
  Minggu 3: replikasi dan failover
  Minggu 4: pemantauan, tuning, runbook

Standar industri yang dinilai
  Pemulihan benar-benar diuji, metrik sebelum/sesudah tuning, runbook langkah demi langkah

Keluaran
  [ ] Repo dengan README lengkap, keputusan teknis, dan screenshot
  [ ] Demo online atau video 2 menit
  [ ] Test/bukti pengujian dan CI hijau (untuk proyek kode)
  [ ] Ringkasan 1 paragraf untuk CV dan LinkedIn

Poin penting

  • Masalah: Aplikasi kasir mulai lambat dan pemilik takut kehilangan data.
  • Stack: PostgreSQL 16, pgBackRest, Patroni (opsional), Prometheus, postgres_exporter, Grafana, Docker Compose.
  • Rencana 4 minggu; dinilai dengan rubrik standar industri.
