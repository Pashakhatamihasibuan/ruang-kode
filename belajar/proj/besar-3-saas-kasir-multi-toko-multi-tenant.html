Besar 3: SaaS kasir multi-toko (multi-tenant)

Buka versi interaktif

Masalah. Satu aplikasi kasir dipakai ratusan toko. Data toko A tidak boleh pernah terlihat oleh toko B, dan setiap toko bisa mengundang karyawannya sendiri.

Fitur wajib:
1. Pendaftaran toko (tenant) dan undangan karyawan dengan peran pemilik/kasir
2. Semua data (produk, pesanan) otomatis terikat ke tenant
3. Isolasi dijamin dua lapis: aplikasi dan Row-Level Security PostgreSQL
4. Paket langganan dengan batas (misal 2 kasir di paket gratis)
5. Log audit: siapa mengubah apa

Penyelesaian langkah demi langkah:
1. Tambahkan toko_id ke setiap tabel bisnis dan index komposit (toko_id, ...).
2. Middleware memvalidasi keanggotaan pengguna di toko yang diminta, lalu menjalankan SET LOCAL app.toko_id di awal transaksi.
3. Aktifkan RLS di PostgreSQL sebagai jaring pengaman: query yang lupa filter tetap tidak bisa membaca toko lain.
4. Batas paket diperiksa di service layer (bukan di view) dan diuji.
5. Test isolasi: buat dua toko, pastikan semua endpoint tidak membocorkan data silang.

Standar industri yang dinilai: isolasi tenant dua lapis (aplikasi + RLS) dengan test untuk setiap endpoint, aturan paket di service layer, log audit

Arsitektur dan stack (Django 5, DRF, PostgreSQL RLS, SimpleJWT, Stripe/Midtrans subscription sandbox, pytest, Docker)
BagianIsi
TenantModel Toko; Keanggotaan(user, toko, peran); header X-Toko atau subdomain menentukan toko aktif
Isolasi appMiddleware menyimpan toko aktif; manager TenantQuerySet memfilter otomatis
Isolasi DBRLS: USING (toko_id = current_setting('app.toko_id')::int)
AuditSinyal post_save/post_delete menulis ke tabel AuditLog

# tenant/middleware.py
from django.db import connection
from django.http import JsonResponse

class TokoAktifMiddleware:
    def __init__(self, get_response): self.get_response = get_response

    def __call__(self, req):
        kode = req.headers.get('X-Toko')
        if kode and req.user.is_authenticated:
            anggota = Keanggotaan.objects.select_related('toko').filter(user=req.user, toko__kode=kode).first()
            if not anggota:
                return JsonResponse({'detail': 'Kamu bukan anggota toko ini.'}, status=403)
            req.toko, req.peran = anggota.toko, anggota.peran
            with connection.cursor() as c:
                c.execute("SELECT set_config('app.toko_id', %s, false)", [str(anggota.toko_id)])
        return self.get_response(req)

# tenant/models.py
class TenantQuerySet(models.QuerySet):
    def milik(self, toko): return self.filter(toko=toko)

class TenantModel(models.Model):
    toko = models.ForeignKey('Toko', on_delete=models.CASCADE, db_index=True)
    objects = TenantQuerySet.as_manager()
    class Meta: abstract = True

class Produk(TenantModel):
    nama = models.CharField(max_length=120)
    harga = models.DecimalField(max_digits=12, decimal_places=2)

# migrasi: jaring pengaman Row-Level Security
RLS = '''
ALTER TABLE toko_produk ENABLE ROW LEVEL SECURITY;
ALTER TABLE toko_produk FORCE ROW LEVEL SECURITY;
CREATE POLICY isolasi_toko ON toko_produk
  USING (toko_id = current_setting('app.toko_id', true)::int);
'''

def undang_kasir(toko, email):
    if toko.paket == 'GRATIS' and toko.keanggotaan.filter(peran='KASIR').count() >= 2:
        raise BatasPaket('Paket gratis maksimal 2 kasir. Upgrade untuk menambah.')
    return Undangan.objects.create(toko=toko, email=email, token=secrets.token_urlsafe(24))

# tests/test_isolasi.py
@pytest.mark.parametrize('url', ['/api/produk/', '/api/pesanan/', '/api/laporan/harian/'])
def test_toko_b_tidak_melihat_data_toko_a(url, api_toko_b, data_toko_a):
    r = api_toko_b.get(url)
    assert all(item['toko'] != data_toko_a.id for item in r.data.get('results', []))
