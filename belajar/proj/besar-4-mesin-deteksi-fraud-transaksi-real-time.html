Besar 4: Mesin deteksi fraud transaksi real-time

Buka versi interaktif

Masalah. Dompet digital kehilangan ratusan juta rupiah per bulan karena akun curian, akun ternak promo, dan transaksi tidak wajar. Keputusan setuju/tolak harus diambil dalam puluhan milidetik tanpa mengganggu pengguna jujur.

Fitur wajib:
1. Fitur streaming per pengguna dengan sliding window (5 menit, 24 jam)
2. Deteksi sindikat akun yang berbagi device/IP dengan Union-Find
3. Rule engine berbasis data dengan skor dan keputusan bertingkat (setuju, OTP, tolak)
4. Antrean kasus untuk analis dengan priority queue
5. Evaluasi precision/recall, shadow mode, dan audit log

Penyelesaian langkah demi langkah:
1. Kumpulkan data berlabel (chargeback, laporan pengguna) dan definisikan biaya salah tolak vs fraud lolos.
2. Bangun fitur jendela dan Union-Find; uji dengan data replay.
3. Tulis aturan awal bersama tim risk, ukur precision/recall per aturan.
4. Jalankan shadow mode dua minggu, kalibrasi ambang, lalu aktifkan bertahap.
5. Pantau metrik harian, tinjau kasus, dan perbarui aturan dari temuan analis.

Standar industri yang dinilai: latensi keputusan di bawah target, setiap keputusan dapat dijelaskan dan diaudit, aturan diukur dengan data berlabel, rilis lewat shadow mode, dan data pribadi diminimalkan

Arsitektur dan stack (Python 3.12, aiokafka, Redis, PostgreSQL, Prometheus/Grafana, pandas untuk evaluasi offline)
BagianIsi
Streamingkonsumen Kafka async; state jendela di Redis dengan TTL
Fiturvelocity, median nominal 24 jam, kecepatan perpindahan lokasi, device baru
GraphUnion-Find dengan path compression dan union by size untuk cluster akun
Aturandaftar aturan sebagai data, bobot skor, ambang dikalibrasi mingguan
Operasionalheap kasus untuk analis, SLA tinjauan, umpan balik label ke evaluasi
Tata kelolashadow mode, A/B ambang, audit log, minimisasi data pribadi
