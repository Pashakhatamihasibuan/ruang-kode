Mini 6: Notifikasi email terjadwal dengan Celery dan retry

Buka versi interaktif

Masalah. Murid lupa tenggat tugas. Sistem perlu mengirim pengingat H-1 setiap pagi tanpa memperlambat request, dan tetap terkirim walau server email sedang gangguan.

Fitur wajib:
1. Tugas terjadwal setiap 07.00 WIB mencari tenggat besok
2. Kirim email per murid di latar belakang
3. Ulangi otomatis dengan jeda bertambah jika server email gagal
4. Tidak mengirim pengingat ganda

Penyelesaian langkah demi langkah:
1. Pasang Celery dengan broker Redis dan Celery Beat untuk jadwal (crontab(hour=7), zona waktu Asia/Jakarta).
2. Tugas penjadwal hanya mencari data lalu memecahnya menjadi tugas kecil per murid.
3. Tugas kirim memakai autoretry_for, retry_backoff, dan max_retries.
4. Catat pengingat terkirim di tabel dengan UniqueConstraint(tugas, murid) agar idempoten.

Kembangkan sendiri: kanal WhatsApp (Business API) sebagai pilihan, dan halaman preferensi notifikasi murid.

PYTHON
# config/celery.py
from celery import Celery
from celery.schedules import crontab

app = Celery('kelas')
app.config_from_object('django.conf:settings', namespace='CELERY')
app.conf.timezone = 'Asia/Jakarta'
app.conf.beat_schedule = {'pengingat-tenggat': {'task': 'kelas.tasks.jadwalkan_pengingat', 'schedule': crontab(hour=7, minute=0)}}
app.autodiscover_tasks()

# kelas/models.py (potongan)
class PengingatTerkirim(models.Model):
    tugas = models.ForeignKey('Tugas', on_delete=models.CASCADE)
    murid = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE)
    waktu = models.DateTimeField(auto_now_add=True)
    class Meta:
        constraints = [models.UniqueConstraint(fields=['tugas', 'murid'], name='satu_pengingat')]

# kelas/tasks.py
from datetime import timedelta
from smtplib import SMTPException
from celery import shared_task
from django.core.mail import send_mail
from django.db import IntegrityError
from django.utils import timezone

@shared_task
def jadwalkan_pengingat():
    besok = timezone.localdate() + timedelta(days=1)
    for tugas in Tugas.objects.filter(tenggat__date=besok).prefetch_related('kelas__murid'):
        for murid in tugas.kelas.murid.exclude(pengumpulan__tugas=tugas):
            kirim_pengingat.delay(tugas.id, murid.id)

@shared_task(autoretry_for=(SMTPException, ConnectionError), retry_backoff=30, retry_jitter=True, max_retries=5)
def kirim_pengingat(tugas_id, murid_id):
    try:
        catat = PengingatTerkirim.objects.create(tugas_id=tugas_id, murid_id=murid_id)
    except IntegrityError:
        return 'sudah pernah dikirim'
    t, m = catat.tugas, catat.murid
    try:
        send_mail(f'Pengingat: {t.judul} besok', f'Halo {m.first_name}, tugas "{t.judul}" ditutup {t.tenggat:%d/%m %H.%M}.',
                  None, [m.email])
    except Exception:
        catat.delete()          # biarkan retry mencoba lagi
        raise
    return 'terkirim'

Cek pemahaman

Kenapa pengiriman dipecah menjadi satu tugas per murid?

Jawaban: Agar kegagalan satu email tidak menggagalkan semua, dan bisa di-retry sendiri

Tugas kecil, independen, idempoten.
