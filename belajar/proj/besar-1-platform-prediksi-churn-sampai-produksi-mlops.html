Besar 1: Platform prediksi churn sampai produksi (MLOps)

Buka versi interaktif

Masalah. Operator telekomunikasi ingin skor risiko churn harian untuk 2 juta pelanggan, bisa dipanggil dari CRM, dipantau kualitasnya, dan dilatih ulang otomatis bila performa turun.

Fitur wajib:
1. Pipeline fitur yang sama untuk latih dan prediksi (tidak ada training-serving skew)
2. Eksperimen tercatat: parameter, metrik, dan artefak model
3. API prediksi dengan validasi input dan versi model
4. Pemantauan data drift dan performa, dengan pemicu latih ulang
5. Model card: tujuan, data, metrik per segmen, batasan

Penyelesaian langkah demi langkah:
1. Definisikan label dan jendela waktu: fitur dari data sampai tanggal T, churn dihitung T+1 s.d. T+30.
2. Tulis modul fitur bersama (fitur.py) yang dipakai saat latih dan saat prediksi.
3. Latih dengan split berbasis waktu, catat semuanya ke MLflow, daftarkan model yang lolos ambang.
4. Bungkus model dengan FastAPI + Pydantic, kemas dengan Docker, sertakan versi model di respons.
5. Jadwalkan batch harian dan laporan drift mingguan; latih ulang jika presisi@20% turun di bawah ambang.
6. Tulis model card dan dokumentasi API untuk tim CRM.

Standar industri yang dinilai: split berbasis waktu, eksperimen terlacak, model registry, API tervalidasi, drift dipantau, model card tertulis

Arsitektur dan stack (Python, scikit-learn/LightGBM, MLflow, FastAPI, Docker, PostgreSQL, Evidently, GitHub Actions)
BagianIsi
Datatabel fitur harian di PostgreSQL/warehouse; label churn 30 hari ke depan
Pelatihantrain.py: split berbasis waktu, LightGBM, kalibrasi, log ke MLflow
RegistryMLflow Model Registry: Staging → Production setelah lolos ambang metrik
ServingFastAPI /predict dan batch harian; model dimuat dari registry
MonitoringEvidently: drift fitur (PSI/KS) mingguan, presisi@k saat label tiba
CI/CDtest unit + test data (Great Expectations/pandera) + build image

  • Kerjakan dulu sendiri, lalu buka kode final untuk code review.
