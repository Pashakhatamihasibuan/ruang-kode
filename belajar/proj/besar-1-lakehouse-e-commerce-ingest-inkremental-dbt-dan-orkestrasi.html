Besar 1: Lakehouse e-commerce: ingest inkremental, dbt, dan orkestrasi

Buka versi interaktif

Masalah. Brand ritel omnichannel punya data di marketplace, toko online, POS 60 gerai, dan iklan digital. Setiap tim punya angka omzet berbeda. Mereka butuh satu platform data dengan definisi metrik tunggal yang diperbarui setiap pagi.

Fitur wajib:
1. Ingest inkremental dari API dan database ke lapisan bronze (Parquet/Iceberg di object storage)
2. Transformasi dbt berlapis: staging → intermediate → marts, dengan model contract
3. Tes data otomatis (unique, not_null, relationships, accepted_values, freshness)
4. Orkestrasi Airflow dengan dbt per model sebagai task, retry, dan SLA jam 07.00
5. Dokumentasi dan lineage otomatis; semantic layer untuk metrik omzet, AOV, repeat rate

Penyelesaian langkah demi langkah:
1. Inventarisasi sumber dan definisikan metrik bersama bisnis (tulis di dokumen definisi metrik).
2. Bangun ingest inkremental satu sumber dulu sampai stabil, lalu tambah sumber lain.
3. Tulis model dbt staging dengan contract dan tes, kemudian marts fakta/dimensi.
4. Hubungkan Airflow + Cosmos; tambah SLA, retry, dan alert.
5. Publikasikan dokumentasi, lineage, dan semantic layer; matikan spreadsheet lama.

Standar industri yang dinilai: satu definisi metrik, pipeline idempoten dan inkremental, tes data di setiap model, SLA terpantau, biaya per query terkendali, dokumentasi dan lineage tersedia
