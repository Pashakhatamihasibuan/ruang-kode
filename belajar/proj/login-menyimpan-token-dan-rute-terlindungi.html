Proyek Portofolio · Modul 2 · Konsep & kode

Login, menyimpan token, dan rute terlindungi

Buka versi interaktif

Halaman login mengirim username dan password ke /api/auth/token/, lalu menyimpan access token. Untuk portofolio, localStorage sudah umum dipakai; di produksi yang lebih ketat, refresh token disimpan di cookie httpOnly agar tidak bisa dibaca skrip jahat (XSS).

Buat komponen RuteTerlindungi: jika tidak ada token, arahkan ke /login. Jika API membalas 401 (token kedaluwarsa), coba perbarui dengan refresh token; jika gagal, keluarkan pengguna.

Ingat: menyembunyikan tombol di frontend bukan pengamanan. Itu hanya kenyamanan. Pengamanan sebenarnya adalah permission di API yang sudah kita buat.

KODE
// src/auth.tsx
import { Navigate, Outlet } from 'react-router-dom';
import { api } from './api/client';

export async function masuk(username: string, password: string) {
  const t = await api<{ access: string; refresh: string }>('/auth/token/', {
    method: 'POST', body: JSON.stringify({ username, password }),
  });
  localStorage.setItem('access', t.access);
  localStorage.setItem('refresh', t.refresh);
}

export function keluar() {
  localStorage.removeItem('access');
  localStorage.removeItem('refresh');
  window.location.assign('/login');
}

export function RuteTerlindungi() {
  return localStorage.getItem('access') ? <Outlet /> : <Navigate to="/login" replace />;
}

Poin penting

  • Login menyimpan token; rute terlindungi mengarahkan ke /login.
  • Tangani 401 dengan refresh atau keluar.
  • Keamanan sebenarnya ada di API, bukan menyembunyikan tombol.

Cek pemahaman

Menyembunyikan tombol "Hapus" untuk kasir di frontend sudah cukup aman?

Jawaban: Tidak, API tetap harus menolak dengan 403

Request bisa dikirim langsung tanpa tombol.
