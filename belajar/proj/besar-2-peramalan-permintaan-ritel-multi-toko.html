Besar 2: Peramalan permintaan ritel multi-toko

Buka versi interaktif

Masalah. Jaringan minimarket dengan 300 toko dan 2.000 SKU ingin meramal permintaan 14 hari ke depan per toko per SKU untuk otomatisasi pemesanan, termasuk lonjakan saat Ramadan dan libur panjang.

Fitur wajib:
1. Satu model global untuk semua seri (bukan 600 ribu model kecil)
2. Fitur kalender Indonesia: libur nasional, Ramadan, gajian, cuti bersama
3. Backtest bergulir dan metrik WAPE serta bias per kategori
4. Prediksi kuantil (P50, P90) untuk stok pengaman
5. Pipeline terjadwal dan dashboard akurasi untuk tim supply chain

Penyelesaian langkah demi langkah:
1. Bangun tabel harian lengkap (isi 0 untuk hari tanpa penjualan) dan tandai stok habis agar tidak dikira permintaan nol.
2. Buat fitur dengan lag ≥ horizon (14 hari) agar tidak bocor.
3. Latih model global LightGBM dengan objektif tweedie untuk data banyak nol.
4. Backtest bergulir; bandingkan dengan seasonal naive dan rata-rata 4 minggu.
5. Latih model kuantil P90 untuk stok pengaman; cek coverage mendekati 90%.
6. Jadwalkan flow harian dan sajikan akurasi per kategori untuk tim supply chain.

Standar industri yang dinilai: backtest bergulir, baseline naif dikalahkan, WAPE dan bias per kategori, coverage kuantil dicek, stok habis ditangani

Arsitektur dan stack (Python, LightGBM, pandas/Polars, DuckDB atau BigQuery, Prefect/Airflow, Streamlit)
