Proyek Portofolio · Modul 1 · Konsep & kode

Struktur repo, branch, dan commit

Buka versi interaktif

Pisahkan kode berdasarkan tanggung jawab. Untuk proyek full-stack, pola monorepo sederhana sudah cukup: folder backend/, frontend/, dan berkas bersama di akar (README, docker-compose, workflow CI).

Kerjakan setiap fitur di branch sendiri lalu gabungkan lewat pull request, walaupun kamu bekerja sendiri. Riwayat PR menunjukkan cara kamu memecah pekerjaan. Tulis pesan commit dengan format Conventional Commits: feat:, fix:, docs:, test:, refactor:, chore:.

Simpan konfigurasi rahasia di .env yang masuk .gitignore, lalu sediakan .env.example berisi nama variabel tanpa nilai rahasia.

CONTOH
kasirku/
├── backend/               # Django + Django REST Framework
│   ├── config/            # settings, urls
│   ├── toko/              # app: models, serializers, views, tests
│   ├── requirements.txt
│   └── Dockerfile
├── frontend/              # React + TypeScript (Vite)
│   ├── src/
│   │   ├── api/           # klien HTTP
│   │   ├── components/
│   │   ├── pages/
│   │   └── main.tsx
│   ├── package.json
│   └── Dockerfile
├── docs/                  # ERD, kontrak API, screenshot
├── .github/workflows/ci.yml
├── docker-compose.yml
├── .env.example
└── README.md

# contoh riwayat commit yang baik
feat(api): endpoint daftar produk dengan pagination
feat(web): halaman produk dengan status loading dan error
test(api): uji stok tidak boleh negatif
fix(api): pesanan gagal jika stok kurang
docs: tambah ERD dan cara menjalankan

Poin penting

  • Monorepo: backend/, frontend/, docs/, CI di akar.
  • Satu fitur = satu branch = satu PR.
  • Conventional Commits; rahasia di .env, contoh di .env.example.
