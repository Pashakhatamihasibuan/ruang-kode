Proyek Portofolio · Modul 2 · Konsep & kode

Kebutuhan, user story, dan kontrak API

Buka versi interaktif

Sebelum menulis kode, tulis user story: "Sebagai [peran], saya ingin [aksi], agar [manfaat]", lengkap dengan kriteria penerimaan yang bisa diuji. Ini juga yang dilakukan tim produk sungguhan.

Dari user story, turunkan kontrak API: daftar endpoint, method, siapa yang boleh, dan bentuk request/response. Kontrak ini membuat frontend dan backend bisa dikerjakan paralel. Ikuti konvensi REST: kata benda jamak untuk URL, method untuk aksi, status code yang tepat.

Simpan kontrak di docs/api.md atau biarkan DRF membuat dokumentasi OpenAPI otomatis dengan drf-spectacular di /api/docs/.

CONTOH
User story
1. Sebagai kasir, saya ingin mencari produk berdasarkan nama,
   agar bisa melayani pembeli dengan cepat.
   Kriteria: hasil muncul < 1 detik, menampilkan harga dan stok.
2. Sebagai kasir, saya ingin mencatat pesanan beberapa produk,
   agar stok berkurang otomatis.
   Kriteria: pesanan ditolak jika stok kurang; total dihitung server.
3. Sebagai admin, saya ingin menambah dan mengubah produk.
   Kriteria: kasir tidak boleh mengubah produk (403).
4. Sebagai pemilik, saya ingin melihat penjualan per hari.

Poin penting

  • User story + kriteria penerimaan yang bisa diuji.
  • Kontrak API: method, URL, peran, response.
  • Status code: 200, 201, 400, 401, 403, 404.

Cek pemahaman

Jawaban: 403 Forbidden

Sudah login, tetapi tidak berhak.
