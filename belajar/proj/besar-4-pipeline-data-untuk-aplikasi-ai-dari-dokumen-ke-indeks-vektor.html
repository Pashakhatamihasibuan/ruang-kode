Besar 4: Pipeline data untuk aplikasi AI: dari dokumen ke indeks vektor

Buka versi interaktif

Masalah. Perusahaan logistik nasional membangun asisten AI internal yang menjawab pertanyaan karyawan dari 4.000 dokumen SOP, kebijakan HR, dan tarif. Masalah terbesarnya bukan model, tetapi data: dokumen usang masih dijawab, data pribadi bocor ke indeks, dan karyawan cabang bisa membaca dokumen direksi.

Fitur wajib:
1. Ingest inkremental dokumen dari Google Drive/Confluence/SharePoint beserta versi dan hak aksesnya
2. Pembersihan dan masking PII sebelum chunking
3. Chunking berbasis struktur (judul bagian) dengan tumpang tindih; embed ulang hanya potongan yang berubah
4. Indeks vektor dengan filter hak akses per pengguna (pgvector atau vector DB)
5. Monitoring kualitas data AI: freshness, coverage, recall@k pada golden set, audit PII

Penyelesaian langkah demi langkah:
1. Petakan sumber dokumen, pemilik, dan model hak aksesnya.
2. Bangun parser + masking PII dan uji pada 50 dokumen beragam (PDF scan, tabel tarif).
3. Implementasikan chunking dan sinkronisasi inkremental berbasis hash.
4. Buat indeks dengan filter akses dan uji dengan akun cabang vs direksi.
5. Siapkan evaluasi harian dan dashboard kualitas; libatkan pemilik SOP untuk memperbaiki dokumen yang sering salah dijawab.

Standar industri yang dinilai: dokumen usang tidak pernah dijawab, nol PII di indeks, hak akses dihormati di setiap query, indeks segar ≤ 30 menit, kualitas pencarian diukur dengan golden set

Arsitektur dan stack (Python, Airflow/Dagster, Unstructured/Docling untuk parsing, PostgreSQL + pgvector (atau Qdrant/Weaviate), model embedding multibahasa, Claude/LLM API, OpenLineage, Grafana)

# pipeline/dokumen_ke_vektor.py  — data pipeline untuk aplikasi GenAI (asisten internal SOP perusahaan)
from dataclasses import dataclass
import hashlib, re

@dataclass
class Potongan:
    doc_id: str; versi: str; urutan: int; teks: str; judul: str; akses: list[str]; hash: str

def bersihkan(teks: str) -> str:
    teks = re.sub(r"\b\d{16}\b", "[NIK]", teks)                          # PII tidak boleh masuk indeks
    teks = re.sub(r"(\+62|0)8\d{8,11}", "[HP]", teks)
    return re.sub(r"\s+", " ", teks).strip()

def potong(doc, ukuran=800, tumpang=120):
    """Potong per judul bagian dulu, baru per jumlah karakter, dengan tumpang tindih agar konteks tidak terputus."""
    for b, bagian in enumerate(doc.bagian):
        teks = bersihkan(bagian.isi)
        for i in range(0, max(len(teks) - tumpang, 1), ukuran - tumpang):
            isi = teks[i:i + ukuran]
            yield Potongan(doc.id, doc.versi, b * 1000 + i // (ukuran - tumpang), isi, bagian.judul,
                           doc.akses, hashlib.sha256(isi.encode()).hexdigest())

def sinkron_indeks(dokumen_berubah, db, embed):
    """Inkremental: hanya potongan yang hash-nya berubah yang di-embed ulang (hemat biaya API)."""
    for doc in dokumen_berubah:
        lama = {r.hash for r in db.potongan_milik(doc.id)}
        baru = list(potong(doc))
        perlu = [p for p in baru if p.hash not in lama]
        vektor = embed([p.teks for p in perlu]) if perlu else []
        with db.transaksi():
            db.hapus_potongan_selain(doc.id, {p.hash for p in baru})       # versi lama tidak boleh dijawab lagi
            db.simpan(perlu, vektor)

-- pgvector: pencarian hybrid dengan filter hak akses (row-level)
SELECT id, judul, teks, 1 - (embedding <=> :q) AS skor
FROM potongan
WHERE akses && :grup_pengguna                       -- pengguna hanya melihat dokumen yang boleh dibaca
  AND berlaku = true
ORDER BY embedding <=> :q
LIMIT 8;
