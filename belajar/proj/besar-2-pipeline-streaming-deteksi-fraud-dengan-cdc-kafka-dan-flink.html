Besar 2: Pipeline streaming deteksi fraud dengan CDC, Kafka, dan Flink

Buka versi interaktif

Masalah. Payment gateway memproses 3 juta transaksi per hari. Fraud dideteksi keesokan harinya dari laporan batch, ketika uang sudah hilang. Targetnya: transaksi mencurigakan ditandai kurang dari 5 detik setelah terjadi.

Fitur wajib:
1. CDC dari PostgreSQL ke Kafka dengan Debezium (tanpa membebani aplikasi)
2. Schema Registry dan format Avro; perubahan skema dicek kompatibilitasnya
3. Fitur real-time per kartu dan merchant dengan jendela geser (Flink SQL), watermark untuk event terlambat
4. Aturan + skor model, alert ke tim risiko dalam < 5 detik
5. Penyimpanan analitik real-time (ClickHouse) untuk investigasi dan dashboard

Penyelesaian langkah demi langkah:
1. Aktifkan logical replication di PostgreSQL dan jalankan Debezium untuk satu tabel.
2. Daftarkan skema Avro dan uji perubahan kolom kompatibel vs tidak.
3. Tulis Flink SQL untuk fitur jendela 10 menit; uji dengan data replay dari Kafka.
4. Tambahkan aturan dan integrasi skor model; kirim alert ke topik dan Slack/PagerDuty.
5. Muat ke ClickHouse, bangun dashboard investigasi, ukur latensi end-to-end.

Standar industri yang dinilai: latensi deteksi p99 < 5 detik, tidak ada transaksi hilang atau terhitung ganda, skema terkelola, lag terpantau, data kartu tidak pernah tersimpan mentah

Arsitektur dan stack (PostgreSQL, Debezium, Apache Kafka (Confluent/Redpanda/MSK), Schema Registry, Apache Flink (SQL), ClickHouse, Grafana, Kubernetes)

SQL
-- 1) CDC: Debezium membaca WAL PostgreSQL -> topik Kafka pg.public.transaksi (Avro + Schema Registry)
-- connector.json (potongan)
-- { "connector.class": "io.debezium.connector.postgresql.PostgresConnector",
--   "plugin.name": "pgoutput", "table.include.list": "public.transaksi",
--   "topic.prefix": "pg", "snapshot.mode": "initial" }

-- 2) Flink SQL: fitur real-time per kartu dalam jendela geser 10 menit
CREATE TABLE transaksi (
  trx_id STRING, kartu_hash STRING, merchant_id BIGINT, nominal DECIMAL(14,0),
  kota STRING, waktu TIMESTAMP(3),
  WATERMARK FOR waktu AS waktu - INTERVAL '30' SECOND
) WITH ('connector' = 'kafka', 'topic' = 'pg.public.transaksi', 'format' = 'debezium-avro-confluent', ...);

CREATE TABLE fitur_kartu WITH ('connector' = 'upsert-kafka', 'topic' = 'fitur.kartu', ...) AS
SELECT kartu_hash,
       HOP_END(waktu, INTERVAL '1' MINUTE, INTERVAL '10' MINUTE) AS sampai,
       COUNT(*)                     AS trx_10m,
       SUM(nominal)                 AS nominal_10m,
       COUNT(DISTINCT kota)         AS kota_10m,
       COUNT(DISTINCT merchant_id)  AS merchant_10m
FROM transaksi
GROUP BY kartu_hash, HOP(waktu, INTERVAL '1' MINUTE, INTERVAL '10' MINUTE);

-- 3) Aturan + skor model: kota berbeda >= 3 dalam 10 menit = impossible travel
INSERT INTO alert_risiko
SELECT kartu_hash, sampai, 'IMPOSSIBLE_TRAVEL' AS jenis, kota_10m
FROM fitur_kartu WHERE kota_10m >= 3;

-- 4) ClickHouse untuk dashboard investigasi (latensi query < 1 detik)
CREATE TABLE risiko.transaksi
( trx_id String, kartu_hash String, merchant_id UInt64, nominal Decimal(14,0), kota LowCardinality(String), waktu DateTime64(3, 'Asia/Jakarta') )
ENGINE = ReplacingMergeTree ORDER BY (kartu_hash, waktu, trx_id) PARTITION BY toYYYYMMDD(waktu) TTL toDate(waktu) + INTERVAL 400 DAY;
