Mini 6: Migrasi skema tanpa downtime

Buka versi interaktif

Masalah. Tim produk butuh kolom cabang wajib, flag verifikasi, indeks, dan foreign key di tabel pengguna yang sedang melayani ribuan request per detik. Migrasi naif dengan ALTER TABLE ... NOT NULL dan CREATE INDEX biasa bisa mengunci tabel bermenit-menit.

Fitur wajib:
1. lock_timeout agar migrasi gagal cepat alih-alih menahan antrean
2. Kolom dengan DEFAULT konstan (instan sejak PostgreSQL 11)
3. Backfill bertahap per batch dengan COMMIT di prosedur
4. CHECK/FK NOT VALID lalu VALIDATE, dan CREATE INDEX CONCURRENTLY

Penyelesaian langkah demi langkah:
1. Set lock_timeout di awal setiap skrip migrasi.
2. Tambahkan kolom; isi kolom baru dalam batch kecil dengan DO block yang melakukan COMMIT per batch.
3. Tambahkan constraint NOT VALID (cepat), lalu VALIDATE (tidak memblokir tulisan).
4. Buat indeks dengan CONCURRENTLY dan periksa hasil akhir dengan \d.

Kembangkan sendiri: kemas langkah-langkah ini sebagai migrasi Flyway/sqitch dengan versi, dan uji di salinan database produksi (dari backup) sebelum dijalankan.
