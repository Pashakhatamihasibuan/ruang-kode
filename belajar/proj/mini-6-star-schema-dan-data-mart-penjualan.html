Mini 6: Star schema dan data mart penjualan

Buka versi interaktif

Masalah. Analis menulis query panjang langsung ke tabel order mentah dan hasilnya berbeda-beda antar orang. Manajer ingin satu data mart dengan definisi yang sama untuk semua laporan.

Fitur wajib:
1. Dimensi tanggal (hari, akhir pekan), produk, dan pelanggan dengan surrogate key
2. Tabel fakta berisi kunci dimensi dan ukuran (qty, total)
3. Rekonsiliasi: jumlah baris dan omzet fakta sama dengan sumber
4. Query bisnis: kategori akhir pekan vs hari kerja
5. Top 3 pelanggan per kota dengan window function

Penyelesaian langkah demi langkah:
1. dim_tanggal dibuat sekali per hari kalender, kunci YYYYMMDD.
2. INSERT ... SELECT dengan JOIN ke dimensi untuk mendapat surrogate key.
3. Bandingkan COUNT dan SUM sumber vs fakta sebelum mart dipublikasikan.
4. SUM(CASE WHEN akhir_pekan = 1 ...).
5. ROW_NUMBER() OVER (PARTITION BY kota ORDER BY omzet DESC).

Kembangkan sendiri: tulis ulang sebagai proyek dbt (staging → intermediate → marts) dengan tes unique/not_null/relationships dan dokumentasi otomatis.
