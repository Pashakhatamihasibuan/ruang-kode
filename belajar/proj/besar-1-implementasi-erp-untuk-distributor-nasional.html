Besar 1: Implementasi ERP untuk distributor nasional

Buka versi interaktif

Masalah. Distributor barang konsumsi dengan 6 gudang dan 900 pelanggan toko memakai sistem akuntansi lama, Excel untuk stok, dan WhatsApp untuk order sales. Tutup buku butuh 18 hari, stok selisih 6%, dan piutang macet tidak terpantau. Direksi memutuskan mengimplementasikan ERP.

Fitur wajib:
1. Fit-gap analysis proses O2C, P2P, persediaan multi-gudang, dan akuntansi (termasuk e-Faktur)
2. Desain proses to-be dengan prinsip adopsi standar dan kustomisasi minimal
3. Migrasi data bertahap: master (golden record), saldo awal, rekonsiliasi
4. UAT berbasis skenario bisnis dan pelatihan key user
5. Cut-over, hypercare 30 hari, dan pengukuran manfaat (tutup buku, selisih stok, DSO)

Penyelesaian langkah demi langkah:
1. Petakan proses as-is dan lakukan fit-gap bersama key user.
2. Rancang to-be, putuskan setiap gap: ubah proses, konfigurasi, atau kustomisasi berbiaya jelas.
3. Bersihkan dan migrasikan data dalam beberapa putaran percobaan dengan rekonsiliasi.
4. Jalankan UAT, latih pengguna, siapkan runbook cut-over.
5. Go-live, hypercare, lalu ukur manfaat terhadap business case.

Standar industri yang dinilai: proses standar diadopsi sebanyak mungkin, data migrasi terekonsiliasi dan disetujui pemilik, UAT berbasis skenario nyata, manfaat diukur setelah go-live

Arsitektur dan stack (Odoo 18 / SAP Business One / Microsoft Dynamics 365 BC, Python untuk migrasi data, BPMN (Camunda Modeler/Bizagi), Jira untuk tiket UAT, Power BI untuk laporan manajemen)
BagianIsi
LingkupPenjualan, pembelian, persediaan (lot & kedaluwarsa), akuntansi, aplikasi sales mobile
Timsponsor CFO, PM, 2 BA, konsultan vendor, key user per departemen
Datapembersihan & dedup master, 3 kali migrasi percobaan, rekonsiliasi ditandatangani
Pengujian120 skenario UAT end-to-end, 0 isu kritis sebagai syarat go-live
Perubahanrencana komunikasi, pelatihan per peran, champion di tiap gudang
Ukuran suksestutup buku ≤ 5 hari, selisih stok < 1%, DSO turun 10 hari dalam 6 bulan

# migrasi/impor_master.py — migrasi data distributor ke Odoo 18 lewat XML-RPC (dijalankan setelah UAT data)
import csv, xmlrpc.client
URL, DB = "https://erp.distributor-contoh.id", "prod"
uid = xmlrpc.client.ServerProxy(f"{URL}/xmlrpc/2/common").authenticate(DB, "migrasi@contoh.id", API_KEY, {})
odoo = xmlrpc.client.ServerProxy(f"{URL}/xmlrpc/2/object")
def panggil(model, metode, *args, **kw): return odoo.execute_kw(DB, uid, API_KEY, model, metode, list(args), kw)

laporan = {"dibuat": 0, "diperbarui": 0, "ditolak": []}
for r in csv.DictReader(open("bersih/pelanggan_golden.csv")):          # hasil MDM: sudah dedup & divalidasi
    if not r["npwp"] and r["tipe"] == "perusahaan":
        laporan["ditolak"].append((r["kode"], "NPWP wajib untuk faktur pajak")); continue
    nilai = {"name": r["nama"], "ref": r["kode"], "vat": r["npwp"], "phone": r["telepon"], "street": r["alamat"],
             "property_payment_term_id": TERMIN[r["termin"]], "credit_limit": float(r["limit_kredit"])}
    ada = panggil("res.partner", "search", [["ref", "=", r["kode"]]])
    if ada: panggil("res.partner", "write", ada, nilai); laporan["diperbarui"] += 1
    else:   panggil("res.partner", "create", nilai);   laporan["dibuat"] += 1
print(laporan)

Cek pemahaman

Kenapa prinsip "adopsi proses standar, kustomisasi minimal" penting dalam implementasi ERP?

Jawaban: Kustomisasi menambah biaya, risiko, dan menyulitkan upgrade; proses standar ERP umumnya sudah mewakili praktik terbaik

Biaya jangka panjang kustomisasi.
