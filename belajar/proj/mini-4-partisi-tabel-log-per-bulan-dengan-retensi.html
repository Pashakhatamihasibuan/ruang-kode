Mini 4: Partisi tabel log per bulan dengan retensi

Buka versi interaktif

Masalah. Tabel log aktivitas tumbuh 40 juta baris per bulan. DELETE data lama tiap malam memakan berjam-jam dan membuat bloat. Ubah menjadi tabel berpartisi per bulan, buktikan partition pruning, dan terapkan retensi dengan melepas partisi.

Fitur wajib:
1. Declarative partitioning RANGE per bulan dibuat dengan perulangan
2. Partisi DEFAULT untuk data bertanggal di luar rentang
3. Indeks di tabel induk yang otomatis menurun ke setiap partisi
4. Retensi: DETACH lalu DROP partisi lama, bukan DELETE

Penyelesaian langkah demi langkah:
1. Buat tabel induk PARTITION BY RANGE (waktu) dengan primary key yang menyertakan waktu.
2. Gunakan DO block + format() untuk membuat partisi bulanan.
3. Isi data, lalu periksa sebaran baris per partisi dan EXPLAIN untuk query satu minggu.
4. Lepas partisi tertua dan pastikan data tertua kini bulan berikutnya.

Kembangkan sendiri: otomatiskan pembuatan partisi bulan depan dan penghapusan partisi lama dengan pg_partman + pg_cron, dan arsipkan partisi ke Parquet di object storage sebelum DROP.

Cek pemahaman

Kenapa menghapus data lama dengan DROP partisi lebih baik daripada DELETE?

Jawaban: DROP partisi instan dan tidak meninggalkan dead tuple, sedangkan DELETE jutaan baris lambat, menghasilkan WAL besar, dan bloat

Retensi berbasis partisi.
