Buka versi interaktif

Proyek besar (capstone) jalur QA Engineer. Masalahnya nyata: Tim ingin rilis setiap minggu tanpa takut merusak fitur lama. Kerjakan dalam sekitar 4 minggu dengan rencana mingguan di bawah.

Perlakukan seperti pekerjaan di tim: tulis kebutuhan dulu, pecah menjadi issue di GitHub Projects, kerjakan per branch dan pull request, dan catat keputusan teknis di README. Nilai dirimu dengan rubrik di modul pertama jalur ini.

Yang membedakan proyek ini dari tutorial: test stabil (tidak flaky), data uji terisolasi, laporan mudah dibaca, bug report yang bisa direproduksi. Itulah yang akan kamu ceritakan saat wawancara.

PROYEK BESAR: Suite pengujian untuk aplikasi toko demo

Masalah
  Tim ingin rilis setiap minggu tanpa takut merusak fitur lama.

Fitur wajib
  1. Strategi test dan analisis risiko
  2. Test API (kontrak, negatif, auth)
  3. Test E2E alur utama dengan Page Object
  4. Laporan bug yang baik (langkah, harapan, bukti)
  5. Pipeline CI dengan laporan dan notifikasi

Stack yang disarankan
  Python/TypeScript, pytest, Playwright, Postman/Newman, k6, GitHub Actions, Allure

Rencana 4 minggu
  Minggu 1: strategi, risiko, kasus uji
  Minggu 2: test API
  Minggu 3: test E2E dan data uji
  Minggu 4: CI, laporan, presentasi temuan bug

Standar industri yang dinilai
  Test stabil (tidak flaky), data uji terisolasi, laporan mudah dibaca, bug report yang bisa direproduksi

Keluaran
  [ ] Repo dengan README lengkap, keputusan teknis, dan screenshot
  [ ] Demo online atau video 2 menit
  [ ] Test/bukti pengujian dan CI hijau (untuk proyek kode)
  [ ] Ringkasan 1 paragraf untuk CV dan LinkedIn

Poin penting

  • Masalah: Tim ingin rilis setiap minggu tanpa takut merusak fitur lama.
  • Stack: Python/TypeScript, pytest, Playwright, Postman/Newman, k6, GitHub Actions, Allure.
  • Rencana 4 minggu; dinilai dengan rubrik standar industri.
