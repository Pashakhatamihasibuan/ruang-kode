Auth JWT dan izin per peran

Buka versi interaktif

Pengguna login dengan username dan password ke /api/auth/token/ dan mendapat dua token: access (berumur pendek, misalnya 15 menit, dikirim di header Authorization: Bearer) dan refresh (lebih panjang, untuk meminta access baru).

Autentikasi menjawab "siapa kamu", otorisasi menjawab "boleh apa". Buat kelas permission sendiri: semua staf boleh membaca produk, hanya admin yang boleh mengubah. Peran bisa memakai is_staff atau grup Django.

Uji izin secara eksplisit: request tanpa token harus 401, kasir yang mengubah produk harus 403. Kesalahan izin adalah celah keamanan yang paling sering ditemukan di proyek pemula.

Status code keamanan
KondisiStatus
Tanpa token / token kedaluwarsa401 Unauthorized
Login, tetapi tidak berhak403 Forbidden
Data milik orang lain (sembunyikan keberadaannya)404 Not Found
Terlalu banyak percobaan login429 Too Many Requests
PYTHON
# toko/permissions.py
from rest_framework.permissions import BasePermission, SAFE_METHODS

class AdminAtauHanyaBaca(BasePermission):
    message = 'Hanya admin yang boleh mengubah produk.'

    def has_permission(self, request, view):
        if not request.user.is_authenticated:
            return False
        if request.method in SAFE_METHODS:      # GET, HEAD, OPTIONS
            return True
        return request.user.is_staff

# config/settings.py
from datetime import timedelta
SIMPLE_JWT = {
    'ACCESS_TOKEN_LIFETIME': timedelta(minutes=15),
    'REFRESH_TOKEN_LIFETIME': timedelta(days=1),
}

Poin penting

  • Access token pendek, refresh token untuk memperbarui.
  • Autentikasi vs otorisasi.
  • Uji 401 dan 403 secara eksplisit.
