Besar 3: Platform data dengan Infrastructure as Code dan CI/CD

Buka versi interaktif

Masalah. Startup fintech berkembang dari 3 menjadi 15 orang tim data. Infrastruktur dibuat manual lewat konsol cloud, tidak ada lingkungan staging, perubahan dbt langsung ke produksi, dan tagihan cloud naik 4x dalam 6 bulan.

Fitur wajib:
1. Seluruh infrastruktur (bucket, warehouse, IAM, Airflow di Kubernetes) ditulis dengan Terraform
2. Tiga lingkungan dev/staging/prod dari modul yang sama
3. CI untuk setiap PR: terraform plan, dbt slim CI, cek kontrak data, perkiraan biaya
4. Akses least privilege per peran dan enkripsi dengan kunci sendiri
5. Runbook insiden, on-call, dan dashboard biaya (FinOps)

Penyelesaian langkah demi langkah:
1. Impor sumber daya yang sudah ada ke Terraform (terraform import) sebelum mengubah apa pun.
2. Buat modul dan tiga lingkungan; pindahkan Airflow ke GKE dengan Helm.
3. Siapkan GitHub Actions: plan di PR, apply bertahap setelah review.
4. Terapkan dbt slim CI dan cek kontrak; larang perubahan langsung di prod.
5. Tulis runbook, aktifkan on-call, dan pantau biaya per tim selama sebulan.

Standar industri yang dinilai: tidak ada perubahan manual di konsol, setiap perubahan lewat PR dan review, lingkungan terpisah, akses minimum, biaya dipantau per tim, insiden punya runbook

Arsitektur dan stack (Terraform/OpenTofu, Google Cloud (GKE Autopilot, BigQuery, GCS, KMS) atau padanan AWS, Helm, Airflow, dbt, GitHub Actions, OpenLineage/Marquez, Grafana)
BagianIsi
Repositoriinfra/ (Terraform), dags/ (Airflow), dbt/ (model), contracts/ (YAML kontrak)
Lingkunganworkspace/variabel per env; data produksi tidak bisa diakses dari dev
CI/CDPR → plan + tes; merge ke main → apply ke staging; tag rilis → apply ke prod
KeamananIAM per grup, service account per workload, CMEK, audit log, secret di Secret Manager
KeandalanSLA per data product, alert freshness, runbook, on-call bergilir
Biayalabel biaya per tim, batas byte per query, reservasi slot, laporan biaya mingguan
KODE
# infra/terraform/main.tf  — semua lingkungan dibuat dari modul yang sama
module "lake" {
  source        = "./modules/lake"
  env           = var.env                        # dev | staging | prod
  region        = "asia-southeast2"              # Jakarta: data residency
  retensi_raw   = 90
  kms_key       = google_kms_crypto_key.data.id  # enkripsi dengan kunci sendiri (CMEK)
}

module "airflow" {
  source         = "./modules/airflow-gke"       # Helm chart resmi di GKE Autopilot
  env            = var.env
  git_sync_repo  = "git@github.com:org/data-dags.git"
  worker_min     = var.env == "prod" ? 2 : 0
  worker_max     = 12
}

resource "google_bigquery_dataset_iam_member" "analis_gold" {
  dataset_id = "gold"
  role       = "roles/bigquery.dataViewer"
  member     = "group:analis@toko-contoh.id"     # least privilege: analis hanya baca gold
}

# .github/workflows/data-ci.yml  — setiap pull request
jobs:
  terraform:
    steps:
      - run: terraform fmt -check && terraform validate
      - run: terraform plan -out=plan.tfplan        # plan ditempel ke komentar PR untuk direview
  dbt-slim-ci:
    steps:
      - run: dbt deps
      - run: dbt build --select state:modified+ --defer --state ./prod-manifest --target ci   # hanya model yang berubah + hilirnya
      - run: python scripts/cek_kontrak.py --berubah   # tolak PR yang menghapus kolom tanpa versi kontrak baru
  biaya:
    steps:
      - run: python scripts/perkiraan_biaya.py --maks-gb-per-query 200   # FinOps: dry-run BigQuery, gagal jika melampaui batas

# runbook/insiden.md (potongan)
# 1. Cek dashboard observabilitas (freshness, volume, lag Kafka)
