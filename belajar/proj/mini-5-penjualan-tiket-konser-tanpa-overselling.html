Mini 5: Penjualan tiket konser tanpa overselling

Buka versi interaktif

Masalah. Saat war tiket, 5.000 orang menekan tombol beli hampir bersamaan untuk 1.000 kursi. Sebagian menekan dua kali. Sistem tidak boleh menjual lebih dari kuota dan tidak boleh mencatat pesanan ganda.

Fitur wajib:
1. Simulasi 5.000 request bersamaan dengan virtual thread
2. Pengurangan stok atomik (compare-and-set)
3. Idempotency key: request yang dikirim ulang tidak diproses dua kali
4. Laporan: terjual, sisa, request ganda, dan bukti tidak ada overselling

Penyelesaian langkah demi langkah:
1. Executors.newVirtualThreadPerTaskExecutor() untuk ribuan tugas ringan.
2. Loop compareAndSet pada AtomicInteger: kurangi hanya jika nilai belum berubah.
3. ConcurrentHashMap.newKeySet(); add mengembalikan false untuk ID yang sudah ada.
4. Di database nyata, gunakan UPDATE ... WHERE sisa >= 1 atau SELECT ... FOR UPDATE.

Kembangkan sendiri: ganti stok di memori dengan PostgreSQL dan uji dengan 2 instance aplikasi; bandingkan penguncian optimistik dan pesimistik.
