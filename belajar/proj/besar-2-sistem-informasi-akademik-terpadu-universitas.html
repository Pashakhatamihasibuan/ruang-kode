Besar 2: Sistem informasi akademik terpadu universitas

Buka versi interaktif

Masalah. Universitas swasta dengan 14.000 mahasiswa memakai 5 aplikasi terpisah untuk PMB, KRS, keuangan, e-learning, dan pelaporan PDDikti. Server tumbang setiap masa KRS, data mahasiswa berbeda di tiap sistem, dan pelaporan ke PDDikti dikerjakan manual berminggu-minggu.

Fitur wajib:
1. Arsitektur terpadu dengan master data mahasiswa, dosen, dan kurikulum tunggal
2. KRS online yang tahan beban (kuota kelas aman saat ribuan akses bersamaan)
3. Integrasi keuangan (UKT/VA bank) dan e-learning (SSO, sinkron kelas)
4. Sinkronisasi otomatis ke PDDikti dengan antrean dan log
5. Dashboard akademik: early warning, kelulusan tepat waktu, beban dosen

Penyelesaian langkah demi langkah:
1. Petakan proses akademik dari PMB sampai wisuda dan sumber data masing-masing.
2. Rancang ERD terpadu dan rencana migrasi data dari 5 aplikasi lama.
3. Bangun modul KRS dengan aturan di database, lalu uji beban sebelum masa KRS.
4. Integrasikan keuangan, SSO, e-learning, dan sinkron PDDikti dengan pemantauan.
5. Luncurkan bertahap per fakultas, ukur waktu pelaporan, gangguan KRS, dan kepuasan.

Standar industri yang dinilai: satu sumber data akademik, KRS stabil saat puncak, aturan bisnis ditegakkan sistem, pelaporan PDDikti otomatis dan terpantau, data pribadi terlindungi

Arsitektur dan stack (PostgreSQL, backend Laravel/Django/Spring Boot, SSO (Keycloak), Moodle, API bank (virtual account), Neo Feeder PDDikti, Metabase/Power BI, uji beban k6)
BagianIsi
Datamaster mahasiswa/dosen/kurikulum di satu database; NIK disimpan sebagai hash + terenkripsi
KRSaturan kuota dan prasyarat di database; antrean akses; uji beban 5.000 pengguna serentak
IntegrasiVA bank untuk UKT (status bayar membuka KRS), SSO ke Moodle, sinkron PDDikti terjadwal
Keamananakses per peran (mahasiswa, dosen PA, prodi, BAA), audit perubahan nilai
Analitikearly warning IPS/IPK, kohort kelulusan, rasio dosen-mahasiswa untuk akreditasi
Tata kelolapemilik data per unit (BAA, keuangan, SDM), SOP perubahan nilai

Poin penting

  • Proyek besar: Sistem informasi akademik terpadu universitas.
  • Stack: PostgreSQL, backend Laravel/Django/Spring Boot, SSO (Keycloak), Moodle, API bank (virtual account), Neo Feeder PDDikti, Metabase/Power BI, uji beban k6.
  • Kerjakan dulu sendiri, lalu buka kode final untuk code review.

Cek pemahaman

Kenapa pemeriksaan kuota kelas diletakkan di database (dengan penguncian), bukan hanya di aplikasi?

Jawaban: Saat ribuan mahasiswa mendaftar bersamaan, pemeriksaan di aplikasi saja bisa lolos bersamaan (race condition) sehingga kelas melebihi kuota

Integritas di bawah konkurensi.
