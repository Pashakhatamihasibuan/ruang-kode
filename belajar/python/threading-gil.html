Threading & GIL

Buka versi interaktif

Thread memungkinkan beberapa pekerjaan berjalan bergantian dalam satu proses. Di CPython ada GIL (Global Interpreter Lock): hanya satu thread yang boleh menjalankan bytecode Python pada satu waktu. Akibatnya, thread tidak mempercepat pekerjaan berat di CPU.

Namun thread tetap sangat berguna untuk pekerjaan yang banyak menunggu (I/O): mengunduh file, memanggil API, membaca database. Saat satu thread menunggu jaringan, GIL dilepas dan thread lain bisa bekerja.

Meski ada GIL, race condition tetap bisa terjadi, karena n += 1 terdiri dari beberapa langkah bytecode dan thread bisa berganti di antaranya. Lindungi data bersama dengan threading.Lock. Catatan: Python 3.13 mulai menyediakan build eksperimental tanpa GIL (free-threaded).

PYTHON
import threading, time
from concurrent.futures import ThreadPoolExecutor

def unduh(nama):
    time.sleep(0.5)                  # pura-pura menunggu jaringan
    return f"{nama} selesai"

mulai = time.perf_counter()
with ThreadPoolExecutor(max_workers=5) as ex:
    hasil = list(ex.map(unduh, ["a.jpg", "b.jpg", "c.jpg", "d.jpg", "e.jpg"]))
print(hasil[0], "| 5 unduhan dalam", round(time.perf_counter() - mulai, 1), "detik")

saldo = 0
kunci = threading.Lock()
def setor():
    global saldo
    for _ in range(100_000):
        with kunci:                  # bagian kritis
            saldo += 1

ts = [threading.Thread(target=setor) for _ in range(4)]
for t in ts: t.start()
for t in ts: t.join()
print("saldo:", saldo)
KELUARAN
a.jpg selesai | 5 unduhan dalam 0.5 detik
saldo: 400000

Poin penting

  • GIL: satu thread menjalankan bytecode Python pada satu waktu.
  • Thread cocok untuk tugas I/O, bukan hitungan berat.
  • ThreadPoolExecutor untuk menjalankan banyak tugas.
  • Pakai Lock untuk data yang diubah bersama.
