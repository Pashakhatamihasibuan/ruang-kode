Middleware dan autentikasi

Buka versi interaktif

Middleware (middleware.ts di akar proyek) berjalan sebelum request mencapai halaman. Cocok untuk mengalihkan pengguna yang belum login, mengatur bahasa, atau A/B test. Batasi dengan matcher agar tidak berjalan di setiap file statis.

Untuk login, pustaka populer adalah Auth.js (NextAuth) dengan penyedia Google, GitHub, atau email, serta layanan seperti Clerk dan Supabase Auth. Sesi disimpan di cookie yang aman (httpOnly).

Middleware hanya lapisan pertama. Tetap periksa sesi di Server Component, Server Action, dan Route Handler yang mengakses data pribadi.

TYPESCRIPT
// middleware.ts
import { NextResponse, type NextRequest } from 'next/server';

export function middleware(req: NextRequest) {
  const sesi = req.cookies.get('sesi');
  if (!sesi) {
    const url = new URL('/masuk', req.url);
    url.searchParams.set('kembali', req.nextUrl.pathname);
    return NextResponse.redirect(url);
  }
  return NextResponse.next();
}

export const config = { matcher: ['/akun/:path*', '/pesanan/:path*'] };

// app/pesanan/page.tsx
import { auth } from '@/auth';
export default async function Pesanan() {
  const sesi = await auth();
  if (!sesi) redirect('/masuk');
  const daftar = await db.pesanan.findMany({ where: { userId: sesi.user.id } });
  // ...
}

Poin penting

  • Middleware berjalan sebelum halaman.
  • matcher membatasi rute.
  • Tetap cek sesi di server untuk data pribadi.
