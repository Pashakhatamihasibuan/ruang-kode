Deploy hasil slicing

Buka versi interaktif

Klien ingin melihat hasilnya di internet, bukan file zip. Tiga cara gratis yang paling umum: GitHub Pages (push ke repositori, aktifkan Pages di Settings), Netlify (seret folder ke app.netlify.com/drop), dan Vercel (hubungkan repositori GitHub, setiap push otomatis di-deploy dan setiap branch dapat URL pratinjau).

Sebelum deploy: pastikan file utama bernama index.html, semua path relatif (./css/style.css, bukan C:\Users\...), nama file huruf kecil tanpa spasi (server Linux membedakan Logo.png dan logo.png), dan gambar sudah dikompres.

Setelah deploy, kirim link ke klien dan uji sendiri di ponsel dengan data seluler (bukan Wi-Fi kantor) untuk merasakan kecepatan aslinya. Jalankan PageSpeed Insights (pagespeed.web.dev) dan catat skornya.

Soal latihan

  1. Hasil deploy GitHub Pages tampil tanpa CSS. Path di HTML: /css/style.css, situs di namakamu.github.io/kopinusa/. Apa penyebab dan perbaikannya?

    Petunjuk

    Garis miring di awal merujuk ke akar domain, bukan folder proyek.

    Lihat jawaban
    CONTOH
    Penyebab: /css/style.css dicari di namakamu.github.io/css/style.css (akar domain),
bukan di /kopinusa/css/style.css.
Perbaikan: pakai path relatif css/style.css atau ./css/style.css.

Poin penting

  • GitHub Pages, Netlify, Vercel.
  • index.html, path relatif, nama file huruf kecil.
  • Uji dengan data seluler dan PageSpeed Insights.

Cek pemahaman

Gambar tampil di laptop tapi rusak setelah deploy. Penyebab paling umum?

Jawaban: Beda huruf besar-kecil nama file atau path absolut

Server Linux peka huruf besar-kecil.
