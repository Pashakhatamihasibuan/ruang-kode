Flavor dan CI/CD

Buka versi interaktif

Flavor membuat beberapa varian dari satu kode: dev (server staging, nama aplikasi "Tokoku Dev") dan prod. Keduanya bisa terpasang berdampingan di satu ponsel karena application ID berbeda. Nilai konfigurasi bisa dikirim dengan --dart-define-from-file.

CI/CD menjalankan analisis, tes, dan build otomatis setiap push, lalu mengirim ke tester atau toko aplikasi. Pilihan populer: GitHub Actions, Codemagic (khusus Flutter, punya mesin macOS untuk iOS), dan fastlane untuk mengunggah ke Play Store dan App Store.

Simpan keystore dan kunci API sebagai secret CI, jangan di repositori.

TERMINAL
# .github/workflows/flutter.yml
name: flutter
on: [push, pull_request]
jobs:
  uji:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with: { channel: stable, cache: true }
      - run: flutter pub get
      - run: dart format --set-exit-if-changed .
      - run: flutter analyze
      - run: flutter test --coverage
      - run: flutter build appbundle --flavor prod --dart-define-from-file=env/prod.json
      - uses: actions/upload-artifact@v4
        with: { name: aab, path: build/app/outputs/bundle/prodRelease/app-prod-release.aab }

Poin penting

  • Flavor: dev dan prod dari satu kode.
  • CI: format, analyze, test, build setiap push.
  • Keystore dan kunci sebagai secret.
