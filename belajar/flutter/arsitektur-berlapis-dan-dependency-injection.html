Arsitektur berlapis dan dependency injection

Buka versi interaktif

Saat aplikasi membesar, pisahkan kode menjadi lapisan. Pola yang direkomendasikan tim Flutter: UI layer (widget + ViewModel/Notifier), data layer (repository + service/API), dan opsional domain layer (use case untuk logika bisnis yang rumit).

Widget tidak memanggil API langsung. Widget memanggil ViewModel, ViewModel memanggil repository, dan repository memutuskan mengambil dari API atau dari cache lokal. Hasilnya, setiap bagian bisa diuji dan diganti sendiri-sendiri.

Dependency injection memberi objek yang dibutuhkan sebuah class dari luar, bukan membuatnya di dalam. Riverpod sudah melakukannya lewat provider. Alternatif populer: get_it (service locator) dan injectable.

KODE
lib/
├── main.dart
├── data/
│   ├── services/produk_api.dart        // panggil HTTP
│   ├── local/produk_cache.dart         // database lokal
│   └── repositories/produk_repository.dart
├── domain/
│   └── models/produk.dart              // freezed
└── ui/
    ├── produk/
    │   ├── produk_page.dart            // widget
    │   └── produk_viewmodel.dart       // Notifier
    └── core/widgets/                    // tombol, kartu bersama

// repository memilih sumber data
class ProdukRepository {
  ProdukRepository(this._api, this._cache);
  final ProdukApi _api;
  final ProdukCache _cache;

  Future<List<Produk>> semua() async {
    try {
      final data = await _api.ambil();
      await _cache.simpan(data);
      return data;
    } catch (_) {
      return _cache.baca(); // offline: pakai data terakhir
    }
  }
}

// Riverpod sebagai dependency injection
final produkRepoProvider = Provider(
  (ref) => ProdukRepository(ProdukApi(ref.watch(dioProvider)), ProdukCache()),
);

Soal latihan

  1. Daftarkan ProdukRepository dengan get_it sebagai singleton, lalu ambil di ViewModel.

    Petunjuk

    GetIt.I.registerLazySingleton<T>(() => ...) lalu GetIt.I<T>().

    Lihat jawaban
    KODE
    final sl = GetIt.instance;

void siapkan() {
  sl.registerLazySingleton(() => Dio());
  sl.registerLazySingleton(() => ProdukApi(sl()));
  sl.registerLazySingleton(() => ProdukCache());
  sl.registerLazySingleton(() => ProdukRepository(sl(), sl()));
}

class ProdukViewModel extends ChangeNotifier {
  final _repo = sl<ProdukRepository>();
  List<Produk> data = [];
  Future<void> muat() async {
    data = await _repo.semua();
    notifyListeners();
  }
}

  2. Tulis unit test untuk ProdukRepository yang memastikan data cache dipakai saat API gagal, memakai mocktail.

    Petunjuk

    when(() => api.ambil()).thenThrow(...); when(() => cache.baca()).thenAnswer(...).

    Lihat jawaban
    KODE
    class MockApi extends Mock implements ProdukApi {}
class MockCache extends Mock implements ProdukCache {}

void main() {
  test('pakai cache saat API gagal', () async {
    final api = MockApi(), cache = MockCache();
    final simpanan = [const Produk(id: 1, nama: 'Kopi', harga: 18000)];
    when(() => api.ambil()).thenThrow(Exception('offline'));
    when(() => cache.baca()).thenAnswer((_) async => simpanan);

    final hasil = await ProdukRepository(api, cache).semua();
    expect(hasil, simpanan);
  });
}

Poin penting

  • UI → ViewModel → Repository → Service.
  • Repository menyembunyikan asal data.
  • Dependency injection: Riverpod, get_it.
