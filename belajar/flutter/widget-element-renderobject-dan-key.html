Widget, Element, RenderObject, dan Key

Buka versi interaktif

Flutter memakai tiga pohon. Widget adalah deskripsi ringan dan tidak bisa diubah (immutable); dibuat ulang setiap build. Element adalah wujud widget di layar yang bertahan lama dan menyimpan State. RenderObject mengurus ukuran, posisi, dan menggambar. Karena Element dan RenderObject dipakai ulang, membuat ulang widget itu murah.

BuildContext sebenarnya adalah Element milik widget itu, yaitu posisinya di pohon. Karena itu Theme.of(context) atau Navigator.of(context) mencari ke atas dari posisi tersebut. Kesalahan umum: memakai context dari atas Scaffold untuk mencari Scaffold.

Key membantu Flutter mencocokkan widget lama dan baru. Tanpa key, saat item daftar yang punya state diurutkan ulang atau dihapus, state bisa "pindah" ke item yang salah. Pakai ValueKey(id) untuk item daftar, GlobalKey hanya jika benar-benar perlu (misalnya FormState).

KODE
class DaftarTugas extends StatefulWidget {
  const DaftarTugas({super.key});
  @override
  State<DaftarTugas> createState() => _DaftarTugasState();
}

class _DaftarTugasState extends State<DaftarTugas> {
  final tugas = [(id: 1, judul: 'Belajar Dart'), (id: 2, judul: 'Slicing login')];

  @override
  Widget build(BuildContext context) {
    return ListView(
      children: [
        for (final t in tugas)
          // tanpa key, centang bisa berpindah ke item lain saat daftar berubah
          CheckboxTile(key: ValueKey(t.id), judul: t.judul),
      ],
    );
  }
}

Poin penting

  • Widget murah dibuat ulang; Element dan RenderObject dipakai ulang.
  • BuildContext = posisi widget di pohon.
  • ValueKey untuk item daftar yang punya state.
