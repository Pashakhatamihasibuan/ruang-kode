Dari transaksi ke laporan

Buka versi interaktif

Setiap laporan SIM berasal dari data transaksi yang dicatat TPS. Alurnya: transaksi dicatat → data disimpan di database → data diringkas (dijumlah, dirata-rata, dikelompokkan) → disajikan sebagai laporan atau dasbor. Kalau pencatatan di awal salah, laporan di akhir pasti salah ("garbage in, garbage out").

Peringkasan biasanya memakai SQL: GROUP BY untuk mengelompokkan per cabang atau per kelas, SUM/COUNT/AVG untuk menghitung, dan WHERE atau HAVING untuk laporan pengecualian. Kamu bisa mencoba query sungguhan di jalur SQL.

Untuk data besar atau dari banyak sistem, data dipindahkan dulu ke data warehouse lewat proses ETL agar laporan tidak memperlambat aplikasi kasir atau SIAKAD yang sedang dipakai.

CONTOH
-- Laporan terjadwal: penjualan per cabang minggu ini
SELECT cabang, SUM(total) AS omzet, COUNT(*) AS transaksi
FROM penjualan
WHERE tanggal >= '2026-10-26'
GROUP BY cabang
ORDER BY omzet DESC;

-- Laporan pengecualian: siswa alpa lebih dari 3 hari bulan ini
SELECT s.nama, s.kelas, COUNT(*) AS alpa
FROM presensi p JOIN siswa s ON s.nis = p.nis
WHERE p.status = 'A' AND p.tanggal >= '2026-10-01'
GROUP BY s.nis, s.nama, s.kelas
HAVING COUNT(*) > 3;

Poin penting

  • Laporan berasal dari data transaksi: salah catat = salah laporan.
  • SQL GROUP BY + SUM/COUNT untuk ringkasan, HAVING untuk pengecualian.
  • Data besar dipindah ke warehouse lewat ETL.
