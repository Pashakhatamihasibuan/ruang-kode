Primary key & foreign key

Buka versi interaktif

Primary key (PK) adalah kolom (atau gabungan kolom) yang nilainya unik dan tidak boleh NULL. Ia menjadi identitas setiap baris, seperti NIK untuk penduduk. Tabel detail_pesanan memakai PK gabungan (pesanan_id, produk_id), karena satu produk hanya muncul sekali dalam satu pesanan.

Foreign key (FK) adalah kolom yang menunjuk primary key tabel lain. pesanan.pelanggan_id menunjuk pelanggan.id. Database menjaga integritas referensial: kamu tidak bisa membuat pesanan untuk pelanggan yang tidak ada, dan tidak bisa menghapus pelanggan yang masih punya pesanan.

Perilaku saat induk dihapus bisa diatur: ON DELETE CASCADE ikut menghapus anak, ON DELETE SET NULL mengosongkan rujukannya. Diagram di bawah menunjukkan relasi di database Toko Nusantara.

Pesanan untuk pelanggan yang tidak ada
INSERT INTO pesanan (pelanggan_id, tanggal) VALUES (99, '2024-12-01');
Primary key kembar
INSERT INTO produk (id, nama, kategori, harga) VALUES (1, 'Kopi Lain', 'Minuman', 50000);
Foreign key dengan CASCADE
CREATE TABLE alamat (
  id INTEGER PRIMARY KEY,
  pelanggan_id INTEGER REFERENCES pelanggan(id) ON DELETE CASCADE,
  jalan TEXT
);
INSERT INTO pelanggan (id, nama) VALUES (50, 'Uji');
INSERT INTO alamat (pelanggan_id, jalan) VALUES (50, 'Jl. Merdeka 1');
DELETE FROM pelanggan WHERE id = 50;
SELECT COUNT(*) AS alamat_tersisa FROM alamat;

Tantangan

  1. Buat tabel favorit dengan kolom pelanggan_id yang merujuk pelanggan(id) dan produk_id yang merujuk produk(id), dengan primary key gabungan keduanya. Lalu catat bahwa pelanggan 2 menyukai produk 6.

Poin penting

  • PK: unik + tidak NULL, identitas baris.
  • FK: menunjuk PK tabel lain.
  • Integritas referensial dijaga database.
  • ON DELETE CASCADE / SET NULL mengatur efek penghapusan induk.
