Teknik optimasi query

Buka versi interaktif

Langkah pertama optimasi adalah mengukur, bukan menebak. Pakai EXPLAIN (atau EXPLAIN ANALYZE di PostgreSQL yang juga menjalankan query dan mencatat waktunya) untuk melihat bagian mana yang membaca banyak baris.

Teknik yang paling sering berdampak: index pada kolom di WHERE dan kondisi JOIN; selective projection, yaitu memilih kolom yang dibutuhkan saja, bukan SELECT *; menyaring sedini mungkin dengan WHERE; mengganti subquery berkorelasi yang berat dengan JOIN atau CTE; dan memakai LIMIT untuk tampilan berhalaman.

Hindari membungkus kolom berindeks dengan fungsi di WHERE, misalnya WHERE UPPER(kota) = 'JAKARTA', karena index pada kota tidak bisa dipakai. Hindari juga LIKE '%kata' (wildcard di depan) untuk pencarian di tabel besar.

Index pada kolom JOIN
CREATE INDEX idx_pesanan_pelanggan ON pesanan(pelanggan_id);
EXPLAIN QUERY PLAN
SELECT p.nama, s.id FROM pelanggan p JOIN pesanan s ON s.pelanggan_id = p.id WHERE s.pelanggan_id = 1;
Fungsi di kolom mematikan index
CREATE INDEX idx_kota ON pelanggan(kota);
EXPLAIN QUERY PLAN SELECT nama FROM pelanggan WHERE UPPER(kota) = 'JAKARTA';
Lebih baik: bandingkan kolom apa adanya
CREATE INDEX idx_kota ON pelanggan(kota);
EXPLAIN QUERY PLAN SELECT nama FROM pelanggan WHERE kota = 'Jakarta';
Subquery berkorelasi ditulis ulang dengan JOIN + GROUP BY
SELECT p.nama, COUNT(s.id) AS banyak_pesanan
FROM pelanggan p LEFT JOIN pesanan s ON s.pelanggan_id = p.id
GROUP BY p.id, p.nama
ORDER BY banyak_pesanan DESC;

Tantangan

  1. Tulis query efisien yang hanya mengambil kolom nama dan harga dari 3 produk termahal kategori Minuman.

Poin penting

  • Ukur dengan EXPLAIN sebelum mengoptimasi.
  • Index kolom WHERE dan JOIN.
  • Pilih kolom seperlunya; saring sedini mungkin.
  • Jangan bungkus kolom berindeks dengan fungsi.
