UNIQUE, NOT NULL & CHECK

Buka versi interaktif

Constraint adalah aturan yang dijaga oleh database itu sendiri, sehingga data salah ditolak dari mana pun asalnya: aplikasi web, aplikasi mobile, atau admin yang mengetik query.

NOT NULL mewajibkan kolom diisi. UNIQUE melarang nilai kembar, misalnya email. CHECK (kondisi) memastikan nilai memenuhi syarat, misalnya harga > 0 atau bintang BETWEEN 1 AND 5. DEFAULT memberi nilai bawaan.

Coba jalankan contoh di bawah dan baca pesan error-nya. Pesan seperti ini adalah teman: ia menghentikan data rusak sebelum masuk.

Harga negatif ditolak CHECK
INSERT INTO produk (nama, kategori, harga) VALUES ('Promo', 'Camilan', -1000);
Saldo tidak boleh minus
UPDATE rekening SET saldo = saldo - 1000000 WHERE id = 1;
UNIQUE menolak duplikat
CREATE TABLE akun (
  id INTEGER PRIMARY KEY,
  email TEXT NOT NULL UNIQUE,
  umur INTEGER CHECK (umur >= 13)
);
INSERT INTO akun (email, umur) VALUES ('rina@mail.com', 20);
INSERT INTO akun (email, umur) VALUES ('rina@mail.com', 25);
NOT NULL menolak kosong
INSERT INTO pesanan (pelanggan_id) VALUES (1);

Tantangan

  1. Buat tabel voucher dengan kolom kode (TEXT, NOT NULL, UNIQUE) dan potongan (INTEGER) yang harus antara 1 dan 100 (pakai CHECK). Tambahkan voucher HEMAT10 dengan potongan 10.

Poin penting

  • Constraint dijaga database, bukan hanya aplikasi.
  • NOT NULL, UNIQUE, CHECK, DEFAULT, PK, FK.
  • Pesan error constraint membantu menemukan data salah.
  • Tambahkan constraint sejak awal desain tabel.
