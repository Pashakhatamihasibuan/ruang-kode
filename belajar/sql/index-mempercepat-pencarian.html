Index: mempercepat pencarian

Buka versi interaktif

Tanpa index, mencari pelanggan dari kota tertentu berarti database membaca setiap baris (full table scan). Untuk 10 juta baris, itu lambat. Index adalah struktur tambahan yang menyimpan nilai kolom secara terurut beserta penunjuk ke barisnya, seperti indeks di belakang buku. Database bisa langsung melompat ke lokasi yang tepat dengan pencarian biner.

Index mempercepat WHERE, JOIN, dan ORDER BY pada kolom yang diindeks, tetapi ada harganya: memakan ruang dan memperlambat INSERT, UPDATE, DELETE karena index juga harus diperbarui. Jadi buat index untuk kolom yang sering dicari, bukan untuk semua kolom.

Gunakan EXPLAIN QUERY PLAN (SQLite) atau EXPLAIN (PostgreSQL/MySQL) untuk melihat apakah database melakukan SCAN (baca semua) atau SEARCH (memakai index).

Sebelum index: SCAN
EXPLAIN QUERY PLAN SELECT * FROM pelanggan WHERE kota = 'Jakarta';
Buat index lalu cek lagi
CREATE INDEX idx_pelanggan_kota ON pelanggan(kota);
EXPLAIN QUERY PLAN SELECT * FROM pelanggan WHERE kota = 'Jakarta';
Primary key sudah terindeks
EXPLAIN QUERY PLAN SELECT * FROM produk WHERE id = 3;
UNIQUE index menolak duplikat
CREATE UNIQUE INDEX idx_produk_nama ON produk(nama);
INSERT INTO produk (nama, kategori, harga) VALUES ('Kopi Gayo', 'Minuman', 1000);
Hapus index
CREATE INDEX idx_tmp ON pesanan(status);
DROP INDEX idx_tmp;

Tantangan

  1. Buat index bernama idx_pesanan_tanggal pada kolom tanggal di tabel pesanan.

Poin penting

  • Index = daftar terurut + penunjuk baris.
  • SCAN membaca semua; SEARCH memakai index.
  • Index mempercepat baca, memperlambat tulis.
  • Index kolom yang sering ada di WHERE dan JOIN.
