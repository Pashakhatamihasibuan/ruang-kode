Correlated subquery & EXISTS

Buka versi interaktif

Correlated subquery memakai kolom dari query luar, sehingga ia dihitung ulang untuk setiap baris luar. Contoh: "karyawan yang gajinya di atas rata-rata divisinya sendiri". Subquery butuh divisi dari baris karyawan yang sedang diperiksa.

EXISTS (subquery) bernilai benar jika subquery menghasilkan minimal satu baris. Ia biasanya ditulis sebagai correlated subquery: "pelanggan yang punya pesanan berstatus dikirim". NOT EXISTS untuk kebalikannya.

Correlated subquery mudah dibaca tetapi bisa lambat pada tabel besar karena dijalankan berulang. Sering kali query yang sama bisa ditulis ulang dengan JOIN atau window function. Database modern juga cukup pintar mengoptimalkannya.

Di atas rata-rata divisinya
SELECT k.nama, k.divisi, k.gaji
FROM karyawan k
WHERE k.gaji > (SELECT AVG(x.gaji) FROM karyawan x WHERE x.divisi = k.divisi);
EXISTS
SELECT nama FROM pelanggan p
WHERE EXISTS (SELECT 1 FROM pesanan s WHERE s.pelanggan_id = p.id AND s.status = 'dikirim');
NOT EXISTS: belum pernah memesan
SELECT nama FROM pelanggan p
WHERE NOT EXISTS (SELECT 1 FROM pesanan s WHERE s.pelanggan_id = p.id);
Subquery di SELECT
SELECT nama,
  (SELECT COUNT(*) FROM pesanan s WHERE s.pelanggan_id = p.id) AS banyak_pesanan
FROM pelanggan p ORDER BY banyak_pesanan DESC;

Tantangan

  1. Tampilkan nama produk yang pernah dipesan minimal sekali, memakai EXISTS.

Kode pemula vs kode rapi

Cek keberadaan dengan EXISTS

EXISTS berhenti begitu satu baris cocok ditemukan, sedangkan COUNT(*) > 0 menghitung semuanya dulu.

KODE PEMULA
SELECT nama FROM pelanggan c
WHERE (SELECT COUNT(*) FROM pesanan o WHERE o.pelanggan_id = c.id) > 0
ORDER BY nama
LIMIT 5;
KODE RAPI (BEST PRACTICE)
SELECT nama FROM pelanggan c
WHERE EXISTS (SELECT 1 FROM pesanan o WHERE o.pelanggan_id = c.id)
ORDER BY nama
LIMIT 5;

Poin penting

  • Correlated = memakai kolom query luar.
  • Dihitung ulang per baris luar.
  • EXISTS benar jika ada minimal satu baris.
  • Bisa ditulis ulang dengan JOIN untuk performa.
