Thread & race condition

Buka versi interaktif

Thread adalah jalur eksekusi. Program biasa punya satu thread (main), tetapi kamu bisa membuat thread lain agar beberapa pekerjaan berjalan bersamaan, misalnya mengunduh file sambil tetap merespons pengguna.

Masalah muncul ketika dua thread mengubah data yang sama. counter++ terlihat satu langkah, padahal sebenarnya tiga: baca, tambah, tulis. Jika dua thread membaca nilai yang sama sebelum salah satunya menulis, satu penambahan hilang. Ini disebut race condition, dan hasilnya berubah-ubah setiap dijalankan.

Solusinya adalah membuat bagian kritis hanya bisa dimasuki satu thread pada satu waktu, dengan synchronized, Lock, atau memakai kelas atomik seperti AtomicInteger.

JAVA
import java.util.concurrent.atomic.AtomicInteger;

public class Balapan {
    static int biasa = 0;
    static int aman = 0;
    static AtomicInteger atomik = new AtomicInteger();

    static synchronized void tambahAman() { aman++; }

    public static void main(String[] args) throws InterruptedException {
        Runnable kerja = () -> {
            for (int i = 0; i < 100_000; i++) {
                biasa++;              // tidak aman
                tambahAman();         // satu thread per waktu
                atomik.incrementAndGet();
            }
        };
        Thread t1 = new Thread(kerja);
        Thread t2 = new Thread(kerja);
        t1.start(); t2.start();
        t1.join();  t2.join();        // tunggu keduanya selesai
        System.out.println("biasa  = " + biasa + " (seharusnya 200000)");
        System.out.println("aman   = " + aman);
        System.out.println("atomik = " + atomik.get());
    }
}
KELUARAN
biasa  = 137482 (seharusnya 200000)
aman   = 200000
atomik = 200000

Poin penting

  • start() menjalankan thread baru; run() langsung hanya memanggil method biasa.
  • join() menunggu thread selesai.
  • Race condition: hasil bergantung pada urutan thread yang tidak bisa ditebak.
  • synchronized dan kelas atomik mencegah update yang hilang.
