Mocking & jenis tes lain

Buka versi interaktif

Kadang kelas yang diuji bergantung pada database atau API luar. Mockito membuat mock: objek tiruan yang perilakunya kamu atur (when(...).thenReturn(...)), lalu kamu periksa apakah ia dipanggil dengan benar (verify). Tes jadi cepat dan tidak bergantung pada sistem lain.

Cucumber JVM menulis skenario tes dalam bahasa mirip kalimat (Given, When, Then) sehingga bisa dibaca orang bisnis. REST Assured menguji REST API dengan gaya berantai: kirim request, periksa status dan isi JSON.

JMeter menguji beban: mensimulasikan ribuan pengguna sekaligus untuk melihat apakah aplikasi tetap cepat. Bersama unit test, ini membentuk piramida tes: banyak unit test, lebih sedikit tes integrasi, dan sedikit tes end-to-end.

JAVA
// Mockito: uji LayananPesanan tanpa database sungguhan
@Test
void totalDihitungDariRepo() {
    RepoProduk repo = mock(RepoProduk.class);
    when(repo.harga("KOPI")).thenReturn(85_000L);

    LayananPesanan layanan = new LayananPesanan(repo);
    assertEquals(170_000L, layanan.total("KOPI", 2));
    verify(repo).harga("KOPI");
}

// REST Assured: uji endpoint API
given().when().get("/api/produk/1")
       .then().statusCode(200)
       .body("nama", equalTo("Kopi Gayo"));

# Cucumber: skenario dalam bahasa manusia
Scenario: Diskon member
  Given pelanggan adalah member
  When ia membeli Kopi Gayo seharga 85000
  Then total yang dibayar adalah 76500

Soal latihan

  1. Uji LayananPesanan yang memanggil PengirimEmail tanpa benar-benar mengirim email, memakai Mockito.

    Petunjuk

    mock(), when(...).thenReturn(...), verify(...).

    Lihat jawaban
    JAVA
    import org.junit.jupiter.api.Test;
import static org.mockito.Mockito.*;

class LayananPesananTest {
    @Test
    void kirimEmailSetelahPesan() {
        PengirimEmail email = mock(PengirimEmail.class);
        LayananPesanan layanan = new LayananPesanan(email);

        layanan.pesan("rina@mail.id", "Kopi");

        verify(email).kirim("rina@mail.id", "Pesanan Kopi diterima");
    }
}

  2. Bedakan unit test, integration test, dan end-to-end test, beserta contohnya di aplikasi toko.

    Petunjuk

    Lihat cakupan: satu kelas, beberapa komponen nyata, atau seluruh sistem lewat UI/API.

    Lihat jawaban
    CONTOH
    Unit test        : satu kelas terisolasi, misal hitung total keranjang.
Integration test : beberapa bagian nyata, misal repository + database Testcontainers.
End-to-end test  : alur lengkap dari luar, misal pengguna checkout lewat browser.
Semakin ke atas semakin lambat dan mahal, jadi jumlahnya makin sedikit.

Poin penting

  • Mock menggantikan dependensi yang lambat atau tidak stabil.
  • when...thenReturn mengatur, verify memeriksa interaksi.
  • REST Assured untuk tes API, Cucumber untuk skenario bisnis, JMeter untuk tes beban.
  • Piramida tes: banyak unit, sedikit end-to-end.
