Checked, unchecked & exception buatan sendiri

Buka versi interaktif

Exception di Java terbagi dua. Checked exception (turunan Exception, misalnya IOException) wajib ditangani dengan try-catch atau dideklarasikan dengan throws; compiler memaksanya. Unchecked exception (turunan RuntimeException, misalnya NullPointerException) biasanya tanda bug dan tidak wajib ditangkap.

Saat exception dilempar, Java mencari catch yang cocok mulai dari method saat ini, lalu naik ke pemanggilnya, dan seterusnya. Proses naik tumpukan pemanggilan ini disebut stack unwinding. Kalau sampai main tidak ada yang menangkap, program berhenti dan mencetak stack trace.

Buat exception sendiri dengan menurunkan Exception atau RuntimeException agar pesan kesalahan bermakna bagi domainmu. Blok finally selalu dijalankan, dan try-with-resources menutup file atau koneksi secara otomatis.

JAVA
class SaldoKurangException extends Exception {
    SaldoKurangException(long kurang) {
        super("Saldo kurang Rp" + kurang);
    }
}

public class Atm {
    static long saldo = 50_000;

    static void tarik(long jumlah) throws SaldoKurangException {
        if (jumlah > saldo) throw new SaldoKurangException(jumlah - saldo);
        saldo -= jumlah;
    }
    static void layani(long jumlah) throws SaldoKurangException {
        System.out.println("Memproses " + jumlah);
        tarik(jumlah);                    // exception naik dari sini
        System.out.println("Berhasil");
    }

    public static void main(String[] args) {
        try {
            layani(20_000);
            layani(80_000);
        } catch (SaldoKurangException e) {
            System.out.println("Gagal: " + e.getMessage());
        } finally {
            System.out.println("Sisa saldo " + saldo);
        }
    }
}

Kode pemula vs kode rapi

Menutup sumber daya otomatis

Try-with-resources menutup reader, file, atau koneksi database secara otomatis, juga saat terjadi exception. Tidak perlu blok finally dan tidak ada risiko lupa memanggil close().

KODE PEMULA
BufferedReader r = new BufferedReader(new StringReader("baris pertama"));
try {
    System.out.println(r.readLine());
} finally {
    r.close();
}
KODE RAPI (BEST PRACTICE)
try (var r = new BufferedReader(new StringReader("baris pertama"))) {
    System.out.println(r.readLine());
}
KELUARAN KEDUANYA
baris pertama

Poin penting

  • Checked: wajib ditangani atau dideklarasikan dengan throws.
  • Unchecked (RuntimeException): biasanya bug, perbaiki kodenya.
  • Exception naik ke pemanggil sampai ada catch yang cocok.
  • finally selalu berjalan, cocok untuk membereskan sumber daya.
