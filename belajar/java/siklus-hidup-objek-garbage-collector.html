Siklus hidup objek & garbage collector

Buka versi interaktif

Setiap new membuat objek baru di area memori bernama heap. Variabel hanya menyimpan referensi (alamat) ke objek itu. Objek bisa punya banyak referensi sekaligus.

Ketika tidak ada lagi referensi yang menunjuk sebuah objek, objek itu tidak terjangkau. Di Java kamu tidak menghapus objek secara manual. Garbage collector (GC) milik JVM berkala mencari objek tak terjangkau lalu membebaskan memorinya.

Siklus hidupnya: dibuat (new + konstruktor), dipakai, tidak terjangkau, lalu dibersihkan GC. Kamu tidak bisa memastikan kapan GC berjalan, jadi jangan menaruh logika penting di sana. Untuk menutup file atau koneksi, pakai try-with-resources.

JAVA
class Kotak {
    String label;
    Kotak(String label) {
        this.label = label;
        System.out.println("Dibuat: " + label);
    }
}

public class Siklus {
    public static void main(String[] args) {
        Kotak a = new Kotak("A");
        Kotak b = new Kotak("B");
        Kotak c = a;          // dua referensi ke objek A
        a = null;             // A masih dijangkau lewat c
        b = null;             // B tidak terjangkau lagi -> calon GC
        System.out.println(c.label);
        c = new Kotak("C");   // A kini juga tidak terjangkau
        System.out.println(c.label);
    }
}
KELUARAN
Dibuat: A
Dibuat: B
A
Dibuat: C
C

Poin penting

  • Variabel menyimpan referensi, objeknya ada di heap.
  • Objek tanpa referensi menjadi calon garbage collection.
  • null berarti referensi tidak menunjuk objek apa pun.
  • GC berjalan otomatis; jangan bergantung pada waktunya.
