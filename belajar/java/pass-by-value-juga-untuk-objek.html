Pass by value (juga untuk objek)

Buka versi interaktif

Java selalu pass by value: saat memanggil method, nilai argumen disalin ke parameter. Untuk tipe primitif, yang disalin adalah angkanya. Mengubah parameter di dalam method tidak mengubah variabel pemanggil.

Untuk objek, yang disalin adalah referensinya. Parameter dan variabel pemanggil menunjuk objek yang sama di heap. Jadi jika method mengubah isi objek (misalnya daftar.add(...)), perubahan itu terlihat di luar.

Namun jika method mengganti parameter dengan objek baru (p = new ...), hanya salinan referensi yang berubah. Variabel pemanggil tetap menunjuk objek lama. Inilah bukti Java tidak pass by reference.

JAVA
import java.util.ArrayList;
import java.util.List;

public class Salin {
    static void ubahAngka(int x) { x = 99; }
    static void ubahIsi(List<String> d) { d.add("baru"); }
    static void gantiObjek(List<String> d) {
        d = new ArrayList<>();
        d.add("lain");
    }

    public static void main(String[] args) {
        int n = 5;
        ubahAngka(n);
        System.out.println(n);

        List<String> daftar = new ArrayList<>();
        daftar.add("awal");
        ubahIsi(daftar);
        System.out.println(daftar);
        gantiObjek(daftar);
        System.out.println(daftar);
    }
}
KELUARAN
5
[awal, baru]
[awal, baru]

Poin penting

  • Primitif: salinan nilai, aman dari perubahan.
  • Objek: salinan referensi, isi objek bisa diubah method.
  • Mengganti parameter dengan objek baru tidak berpengaruh ke pemanggil.
  • Untuk melindungi objek, kirim salinannya atau pakai koleksi immutable.

Cek pemahaman

Setelah <code>ubahAngka(n)</code> dengan n = 5, nilai n?

Jawaban: 5

Primitif disalin; parameter x bukan n.

Method memanggil <code>d.add("x")</code> pada list parameter. List pemanggil?

Jawaban: Ikut berubah

Keduanya menunjuk objek list yang sama.
