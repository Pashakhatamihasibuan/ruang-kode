volatile & Java Memory Model

Buka versi interaktif

Demi kecepatan, setiap inti CPU bisa menyimpan salinan variabel di cache-nya sendiri, dan compiler boleh mengubah urutan instruksi. Akibatnya, perubahan yang dibuat satu thread belum tentu langsung terlihat oleh thread lain.

Java Memory Model (JMM) adalah aturan resmi tentang kapan perubahan dijamin terlihat. Kuncinya adalah hubungan happens-before: misalnya, keluar dari blok synchronized "terjadi sebelum" thread lain masuk ke blok dengan kunci yang sama, sehingga perubahannya terlihat.

Kata kunci volatile menjamin setiap baca dan tulis variabel langsung ke memori utama, sehingga semua thread melihat nilai terbaru. Cocok untuk flag sederhana seperti berhenti = true. Namun volatile tidak membuat x++ menjadi atomik; untuk itu tetap pakai synchronized atau Atomic.

JAVA
public class Bendera {
    private static volatile boolean jalan = true;   // tanpa volatile, loop bisa tak berhenti

    public static void main(String[] args) throws InterruptedException {
        Thread pekerja = new Thread(() -> {
            long putaran = 0;
            while (jalan) putaran++;
            System.out.println("Pekerja berhenti");
        });
        pekerja.start();
        Thread.sleep(200);
        jalan = false;              // perubahan langsung terlihat oleh pekerja
        pekerja.join();
        System.out.println("Selesai");
    }
}
KELUARAN
Pekerja berhenti
Selesai

Poin penting

  • Tanpa sinkronisasi, thread bisa membaca nilai basi dari cache.
  • volatile = visibilitas terjamin, bukan atomisitas.
  • synchronized memberi visibilitas sekaligus eksklusivitas.
  • Happens-before adalah inti aturan JMM.
