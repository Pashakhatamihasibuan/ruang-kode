ExecutorService & virtual thread

Buka versi interaktif

Membuat new Thread untuk setiap tugas itu boros. ExecutorService mengelola kumpulan thread (thread pool): kamu cukup menyerahkan tugas, dan executor yang mengatur thread mana yang mengerjakannya. Hasil tugas bisa diambil lewat Future.

Java 21 memperkenalkan virtual thread: thread ringan yang dikelola JVM, bukan sistem operasi. Kamu bisa membuat ratusan ribu virtual thread sekaligus. Ini cocok untuk server yang banyak menunggu I/O, misalnya memanggil database atau API, karena saat menunggu, virtual thread tidak memakan thread sistem.

Cara memakainya hampir sama: Executors.newVirtualThreadPerTaskExecutor(). Kode tetap ditulis gaya biasa (blocking), tanpa callback yang rumit.

JAVA
import java.util.*;
import java.util.concurrent.*;

public class Pekerja {
    static int hitungHarga(int id) throws InterruptedException {
        Thread.sleep(100);                 // pura-pura memanggil database
        return id * 1000;
    }

    public static void main(String[] args) throws Exception {
        try (ExecutorService ex = Executors.newVirtualThreadPerTaskExecutor()) {
            List<Future<Integer>> hasil = new ArrayList<>();
            for (int i = 1; i <= 10_000; i++) {
                final int id = i;
                hasil.add(ex.submit(() -> hitungHarga(id)));
            }
            long total = 0;
            for (Future<Integer> f : hasil) total += f.get();
            System.out.println("Total: " + total);
        }
        // 10.000 tugas x 100 ms selesai sekitar sepersekian detik,
        // karena virtual thread yang menunggu tidak memblokir thread OS.
    }
}

Poin penting

  • Thread pool menghindari biaya membuat thread berulang.
  • submit mengembalikan Future; get() menunggu hasilnya.
  • Virtual thread (Java 21) cocok untuk tugas yang banyak menunggu I/O.
  • ExecutorService dalam try-with-resources ditutup otomatis setelah semua tugas selesai.
