Format kolom & partisi: Parquet

Buka versi interaktif

CSV mudah dibaca manusia, tetapi lambat dan boros untuk analitik: setiap kueri harus membaca seluruh baris, dan tipe datanya hilang. Parquet menyimpan data per kolom dengan kompresi dan skema, sehingga kueri yang hanya butuh dua kolom cukup membaca dua kolom itu.

Partisi membagi data ke folder berdasarkan kolom yang sering difilter, biasanya tanggal: tahun=2024/bulan=05/. Mesin kueri seperti Spark, DuckDB, atau BigQuery melewati folder yang tidak relevan (partition pruning).

Hati-hati dengan terlalu banyak partisi kecil: ribuan file berukuran beberapa kilobyte justru memperlambat. Targetkan file sekitar 128 MB sampai 1 GB, dan pilih kolom partisi dengan jumlah nilai yang wajar.

CONTOH
# menulis data penjualan sebagai Parquet berpartisi (pandas + pyarrow)
df.to_parquet("gudang/penjualan", partition_cols=["tahun", "bulan"], index=False)

# struktur yang dihasilkan
gudang/penjualan/
  tahun=2024/bulan=4/part-0.parquet
  tahun=2024/bulan=5/part-0.parquet
  tahun=2024/bulan=6/part-0.parquet

-- DuckDB hanya membaca folder bulan=5 dan dua kolom
SELECT kota, SUM(total) AS omzet
FROM read_parquet('gudang/penjualan/*/*/*.parquet', hive_partitioning = true)
WHERE tahun = 2024 AND bulan = 5
GROUP BY kota;

Poin penting

  • Parquet: per kolom, terkompresi, menyimpan skema.
  • Kueri hanya membaca kolom yang dibutuhkan.
  • Partisi per tanggal memungkinkan partition pruning.
  • Hindari terlalu banyak file kecil.
