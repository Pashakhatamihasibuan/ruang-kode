OLTP vs OLAP & penyimpanan kolom

Buka versi interaktif

OLTP (online transaction processing) melayani aplikasi: banyak transaksi kecil, baca-tulis satu baris (simpan pesanan #10293). Skema dinormalisasi agar tidak ada data ganda. Contoh: PostgreSQL, MySQL.

OLAP (online analytical processing) melayani analisis: sedikit query besar yang membaca jutaan baris tetapi hanya beberapa kolom (total omzet per bulan). Skema didenormalisasi (bintang). Contoh: BigQuery, Snowflake, Redshift, ClickHouse.

Gudang OLAP memakai penyimpanan kolom: nilai satu kolom disimpan berdampingan, sehingga query yang hanya butuh 2 dari 50 kolom membaca sebagian kecil data dan kompresinya sangat efisien.

SQL
-- OLTP: satu pesanan, beberapa milidetik
INSERT INTO pesanan (id, pelanggan_id, tanggal, status)
VALUES (10293, 41, CURRENT_DATE, 'baru');

-- OLAP: jutaan baris, hanya 2 kolom dibaca
SELECT DATE_TRUNC('month', tanggal) AS bulan, SUM(omzet)
FROM fakta_penjualan
WHERE tanggal >= '2024-01-01'
GROUP BY 1;

Poin penting

  • OLTP: transaksi kecil, dinormalisasi.
  • OLAP: query besar, didenormalisasi.
  • Penyimpanan kolom untuk analitik.

Cek pemahaman

Kenapa warehouse memakai penyimpanan kolom?

Jawaban: Query analitik hanya membaca sedikit kolom dari banyak baris

Kolom yang tidak dipakai tidak dibaca.
