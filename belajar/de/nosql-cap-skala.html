NoSQL, CAP & skala

Buka versi interaktif

Keluarga NoSQL: dokumen (MongoDB) untuk data berbentuk bebas, key-value (Redis, DynamoDB) untuk akses super cepat dengan kunci, kolom lebar (Cassandra, HBase) untuk tulis masif, graf (Neo4j) untuk relasi rumit, dan pencarian (Elasticsearch).

Teorema CAP: saat jaringan terputus (Partition), sistem terdistribusi harus memilih antara Consistency (semua node mengembalikan data terbaru, atau menolak) dan Availability (selalu menjawab, mungkin data lama).

Vertical scaling = mesin lebih besar (mudah, ada batasnya). Horizontal scaling = lebih banyak mesin (hampir tanpa batas, tetapi lebih rumit).

CONTOH
Kebutuhan                                  Pilihan
Sesi login & keranjang, akses < 1 md         Redis (key-value)
Katalog produk dengan atribut berbeda-beda  MongoDB (dokumen)
Log sensor 1 jt tulis/detik                 Cassandra (kolom lebar)
Rekomendasi "teman dari teman"              Neo4j (graf)
Pencarian teks ulasan                       Elasticsearch
Saldo rekening                              PostgreSQL (relasional, ACID)

Poin penting

  • Dokumen, key-value, kolom lebar, graf, pencarian.
  • CAP: saat partisi, pilih C atau A.
  • Vertical = mesin besar; horizontal = banyak mesin.
