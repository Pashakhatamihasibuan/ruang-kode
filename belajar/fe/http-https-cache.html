HTTP, HTTPS & cache

Buka versi interaktif

Setiap permintaan HTTP punya metode (GET untuk membaca, POST untuk mengirim, PUT/PATCH untuk mengubah, DELETE untuk menghapus), header (informasi tambahan), dan kadang body. Respons membawa kode status: 2xx berhasil, 3xx pengalihan, 4xx kesalahan dari sisi klien, 5xx kesalahan server.

HTTPS mengenkripsi lalu lintas dengan TLS, sehingga kata sandi dan data pembayaran tidak bisa dibaca di jaringan Wi-Fi publik. Browser modern menandai situs non-HTTPS sebagai tidak aman.

Header Cache-Control memberi tahu browser berapa lama file boleh disimpan. File dengan nama ber-hash (app.3f9a1c.js) aman di-cache setahun karena namanya berubah setiap isinya berubah; dokumen HTML biasanya no-cache agar selalu diperiksa ulang.

CONTOH
GET /assets/app.3f9a1c.js HTTP/2
Host: tokonusantara.id

HTTP/2 200
content-type: text/javascript
cache-control: public, max-age=31536000, immutable

GET / HTTP/2
HTTP/2 200
content-type: text/html
cache-control: no-cache

Poin penting

  • Metode: GET, POST, PUT/PATCH, DELETE.
  • Status: 2xx sukses, 3xx pengalihan, 4xx salah klien, 5xx salah server.
  • HTTPS = HTTP + enkripsi TLS.
  • Aset ber-hash di-cache lama; HTML diperiksa ulang.
