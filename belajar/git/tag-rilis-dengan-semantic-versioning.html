Tag & rilis dengan semantic versioning

Buka versi interaktif

Tag memberi nama tetap pada satu commit, biasanya untuk menandai rilis. Berbeda dengan cabang, tag tidak bergerak. Pakai annotated tag (-a) agar tercatat siapa dan kapan membuatnya.

Penomoran yang paling umum adalah Semantic Versioning: MAYOR.MINOR.PATCH. Naikkan PATCH untuk perbaikan bug, MINOR untuk fitur baru yang tetap kompatibel, dan MAYOR untuk perubahan yang merusak kompatibilitas. Versi 0.x berarti API belum stabil.

Tag harus di-push secara eksplisit. Di GitHub, tag bisa dijadikan Release dengan catatan perubahan; GitHub dapat membuat catatan rilis otomatis dari judul pull request.

TERMINAL
git log --oneline -3
git tag -a v1.4.0 -m "Fitur filter harga"
git push origin v1.4.0
git tag --list "v1.*"
git show v1.4.0 --stat

# contoh urutan versi
# 1.3.2 -> 1.3.3   perbaikan bug total keranjang      (PATCH)
# 1.3.3 -> 1.4.0   fitur filter harga                 (MINOR)
# 1.4.0 -> 2.0.0   format API /pesanan diubah         (MAYOR)

Poin penting

  • Tag menandai satu commit secara tetap.
  • Annotated tag (-a) mencatat pembuat dan pesan.
  • SemVer: MAYOR.MINOR.PATCH.
  • Tag perlu di-push: git push origin v1.4.0.

Cek pemahaman

Menambah fitur baru yang tetap kompatibel dari 2.3.1 menjadi?

Jawaban: 2.4.0

Fitur kompatibel menaikkan MINOR dan PATCH kembali ke 0.

Apakah git push biasa mengirim tag?

Jawaban: Tidak, tag di-push secara eksplisit

Gunakan git push origin nama-tag atau --tags.
