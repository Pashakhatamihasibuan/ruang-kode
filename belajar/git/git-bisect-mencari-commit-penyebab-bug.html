git bisect: mencari commit penyebab bug

Buka versi interaktif

Fitur kemarin masih jalan, hari ini rusak, dan di antaranya ada 60 commit. git bisect mencari commit penyebabnya dengan pencarian biner: Git memilih commit di tengah, kamu menandai baik atau buruk, lalu rentangnya dibelah dua lagi.

Untuk 60 commit hanya perlu sekitar 6 langkah, karena 26 = 64. Kalau ada tes atau skrip yang bisa memeriksa bug secara otomatis, git bisect run menjalankan semuanya tanpa campur tangan.

Setelah ketemu, jangan lupa git bisect reset untuk kembali ke cabang semula. Ini salah satu perintah Git yang jarang diketahui pemula, padahal bisa menghemat berjam-jam.

TERMINAL
git bisect start
git bisect bad                 # commit sekarang rusak
git bisect good v1.3.0         # versi ini masih benar
# Git berpindah ke commit di tengah; uji, lalu tandai:
git bisect good                # atau: git bisect bad
# ... ulangi sampai Git menulis:
# a1b2c3d is the first bad commit

# otomatis dengan tes:
git bisect run npm test -- keranjang.test.js
git bisect reset               # kembali ke cabang semula

Poin penting

  • bisect memakai pencarian biner pada riwayat.
  • n commit butuh sekitar log2(n) langkah.
  • git bisect run untuk pemeriksaan otomatis.
  • Akhiri dengan git bisect reset.
