Membatalkan perubahan

Buka versi interaktif

Ada tiga situasi umum. Membuang perubahan berkas yang belum di-stage: git restore berkas. Mengeluarkan berkas dari staging: git restore --staged berkas.

Membatalkan commit yang belum di-push: git reset --soft HEAD~1 menghapus commit terakhir tetapi menyimpan perubahannya di staging. --hard membuang perubahan sama sekali, jadi pakai dengan hati-hati.

Membatalkan commit yang sudah di-push: gunakan git revert hash. Revert membuat commit baru yang membalik perubahan, sehingga riwayat orang lain tidak rusak.

TERMINAL
$ git restore gaya.css            # buang editan yang belum di-stage
$ git restore --staged index.html  # keluarkan dari staging

$ git reset --soft HEAD~1          # batalkan commit terakhir (lokal)

$ git revert a71be04
[main 9d0e3f7] Revert "style: warna tombol beli"
 1 file changed, 1 insertion(+), 1 deletion(-)

Poin penting

  • restore: berkas di working directory atau staging.
  • reset: hapus commit lokal (--soft simpan, --hard buang).
  • revert: commit pembalik, aman untuk riwayat bersama.

Cek pemahaman

Commit salah sudah di-push ke main tim. Cara aman membatalkannya?

Jawaban: git revert

Revert tidak menulis ulang riwayat yang sudah dimiliki orang lain.

git reset --soft HEAD~1 melakukan apa?

Jawaban: Membatalkan commit terakhir, perubahan tetap di staging

--soft menjaga perubahanmu.
