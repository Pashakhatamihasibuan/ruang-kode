init, add, commit

Buka versi interaktif

git init mengubah folder biasa menjadi repositori dengan membuat folder tersembunyi .git. Lalu alurnya selalu sama: ubah berkas, git add untuk memasukkannya ke staging, git commit untuk menyimpan potret permanen.

Setiap commit punya hash unik (misalnya 3f9a1c2), penulis, waktu, pesan, dan penunjuk ke commit sebelumnya. Rangkaian penunjuk inilah yang membentuk riwayat.

Pesan commit yang baik menjelaskan apa dan kenapa dalam kalimat perintah singkat: Tambah validasi email di form daftar, bukan update atau fix. Banyak tim memakai Conventional Commits: feat:, fix:, docs:.

TERMINAL
$ mkdir toko-nusantara && cd toko-nusantara
$ git init
Initialized empty Git repository in /home/sari/toko-nusantara/.git/

$ echo "<h1>Toko Nusantara</h1>" > index.html
$ git add index.html
$ git commit -m "feat: halaman awal toko"
[main (root-commit) 3f9a1c2] feat: halaman awal toko
 1 file changed, 1 insertion(+)
 create mode 100644 index.html

Poin penting

  • git init sekali per proyek.
  • Ubah → git add → git commit.
  • Commit = potret + hash + pesan + induk.
  • Pesan commit menjelaskan apa dan kenapa.

Perintah apa yang memindahkan perubahan ke staging area?
