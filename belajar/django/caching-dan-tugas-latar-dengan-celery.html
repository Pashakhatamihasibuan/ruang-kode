Caching dan tugas latar dengan Celery

Buka versi interaktif

Cache menyimpan hasil yang mahal dihitung. Django mendukung cache per view (@cache_page(60 * 5)), per potongan template ({% cache %}), dan API tingkat rendah (cache.get, cache.set). Backend produksi biasanya Redis.

Pekerjaan lambat seperti mengirim email, membuat PDF invoice, atau memproses gambar jangan dikerjakan di dalam request. Kirim ke antrean dengan Celery (broker Redis atau RabbitMQ) agar respons tetap cepat. Celery Beat menjalankan tugas terjadwal, misalnya laporan harian.

Selalu pikirkan kapan cache dihapus (invalidation): setelah produk diubah, hapus cache daftar produk.

PYTHON
# settings.py
CACHES = {'default': {'BACKEND': 'django.core.cache.backends.redis.RedisCache',
                       'LOCATION': 'redis://127.0.0.1:6379/1'}}
CELERY_BROKER_URL = 'redis://127.0.0.1:6379/0'

# katalog/views.py
from django.views.decorators.cache import cache_page
@cache_page(60 * 5)
def beranda(request): ...

# pesanan/tasks.py
from celery import shared_task
@shared_task
def kirim_invoice(pesanan_id):
    pesanan = Pesanan.objects.get(pk=pesanan_id)
    pdf = buat_pdf(pesanan)
    kirim_email(pesanan.pembeli.email, 'Invoice', lampiran=pdf)

# di view checkout: tidak menunggu email terkirim
kirim_invoice.delay(pesanan.id)
KELUARAN

Poin penting

  • Cache per view, fragmen, atau API rendah dengan Redis.
  • Pekerjaan lambat ke Celery dengan .delay().
  • Rencanakan invalidation cache.
