Autentikasi dan izin akses

Buka versi interaktif

Django sudah punya sistem autentikasi: model User, hash kata sandi yang aman (PBKDF2 atau Argon2), sesi, serta view bawaan login, logout, dan reset kata sandi lewat django.contrib.auth.urls.

Lindungi view dengan dekorator @login_required (FBV) atau LoginRequiredMixin (CBV). Untuk otorisasi, pakai permission (@permission_required('katalog.change_produk')) dan grup, atau periksa kepemilikan data secara eksplisit.

Untuk proyek baru, buat custom user model sejak awal (AUTH_USER_MODEL), misalnya agar login memakai email. Mengganti model user setelah ada data jauh lebih sulit.

PYTHON
# akun/models.py
from django.contrib.auth.models import AbstractUser
class User(AbstractUser):
    no_hp = models.CharField(max_length=16, blank=True)

# settings.py
AUTH_USER_MODEL = 'akun.User'
LOGIN_REDIRECT_URL = 'katalog:daftar'

# tokoku/urls.py
path('akun/', include('django.contrib.auth.urls')),   # login/, logout/, password_reset/

# pesanan/views.py
from django.contrib.auth.decorators import login_required

@login_required
def pesanan_saya(request):
    daftar = Pesanan.objects.filter(pembeli=request.user)   # hanya milik sendiri
    return render(request, 'pesanan/saya.html', {'daftar': daftar})

Poin penting

  • Auth bawaan: User, hash, sesi, login, reset.
  • @login_required dan LoginRequiredMixin.
  • Custom user model sejak awal proyek.

Cek pemahaman

Kenapa memfilter pesanan dengan pembeli=request.user?

Jawaban: Agar pengguna hanya melihat pesanannya sendiri

Mencegah kebocoran data antar pengguna.

Sebelumnya: Form, ModelForm, dan validasi
