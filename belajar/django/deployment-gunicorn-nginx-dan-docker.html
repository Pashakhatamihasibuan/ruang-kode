Deployment: Gunicorn, Nginx, dan Docker

Buka versi interaktif

runserver tidak untuk produksi. Pola umum: Gunicorn (server WSGI, beberapa worker) menjalankan Django, Nginx di depannya menangani HTTPS, file statis, dan meneruskan request. Untuk fitur asinkron atau WebSocket, pakai server ASGI seperti Uvicorn.

File statis (CSS, JS) dikumpulkan dengan collectstatic lalu dilayani Nginx atau WhiteNoise. File unggahan pengguna (media) sebaiknya disimpan di object storage seperti S3 atau Cloudflare R2.

Dengan Docker, aplikasi, Python, dan dependensi dikemas menjadi satu image yang berjalan sama di laptop dan server. Platform seperti Railway, Render, Fly.io, atau VPS dengan Docker Compose bisa dipakai.

Checklist rilis Django

KeamananDEBUG=False, ALLOWED_HOSTS, check --deploy

Statiscollectstatic + WhiteNoise atau Nginx
MediaObject storage (S3, R2)
ServerGunicorn di belakang Nginx, HTTPS
LatarCelery worker + Redis
PantauSentry untuk error, log terpusat
TERMINAL
# Dockerfile
FROM python:3.12-slim
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
RUN python manage.py collectstatic --noinput
CMD ["gunicorn", "tokoku.wsgi:application", "--bind", "0.0.0.0:8000", "--workers", "3"]

# langkah rilis
docker build -t tokoku:1.4.0 .
docker run --env-file .env.prod tokoku:1.4.0 python manage.py migrate
docker run -d --env-file .env.prod -p 8000:8000 tokoku:1.4.0

Poin penting

  • Gunicorn + Nginx, bukan runserver.
  • collectstatic untuk file statis, object storage untuk media.
  • Docker agar lingkungan sama di mana pun.
